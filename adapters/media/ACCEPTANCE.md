# M4 图片与视频独立执行证据

2026-09-10，本机 Apple M5 Max、128 GiB 内存、macOS 26.6.2。图片生成与 LoRA、SVD 图生视频与独立重载的功能通过；图片质量部分失败，视频近乎静止，明显运动质量未通过。这里不是 `GATE-M4` 产品验收报告。

## 图片：实际生成、训练与重载

证据根目录：`.artifacts/m4-media/acceptance-v2`。固定 Tiny-SD revision、完整模型文件摘要、配方及环境见每个结果的 `generation.json`；冻结方案见 `frozen-plan.json`；汇总见 `acceptance.json`。运行前冻结了 4 张训练源图的种子、两组独立评测提示词/种子和重载误差阈值。

| 实际验证 | 结果 |
| --- | --- |
| 4 张训练源图 + 2 张基座图 + 2 张 LoRA 候选图 + 1 张第二进程重载图 | 9 张 512×512 PNG，均通过独立 PIL 解码 |
| 图片生成 | 20 步、CFG 7.5、MPS FP32；实际生成部分每张约 4.22—6.89 秒，另加约 0.49—0.64 秒模型加载 |
| 真实 LoRA 训练 | 4 张明确标记为合成的图片、12 步、rank/alpha 4、AdamW 1e-4；实际训练部分 5.98 秒 |
| 可训练范围 | 431,616 个参数、144 个张量，全部属于 UNet attention LoRA；冻结基座参数摘要前后完全一致 |

训练报告在 `lora/training.json`，产物为 `lora/pytorch_lora_weights.safetensors`。训练 loss 为随机 timestep 去噪 MSE，不能比较首尾 loss 推导质量提高；本试验也没有做训练恢复。

独立产物核验 `independent-artifact-audit.json` 使用标准库、PIL 和 NumPy，未载入模型或原验收脚本；核验了全部 9 张 PNG、对应浮点像素、文件摘要、同一基座身份、训练数据与 LoRA 摘要、执行器源码摘要，以及 10 个不同生成/训练进程身份。

本次执行器与依赖 lock 另存于 `executors`，入口源码 SHA 与全部生成/训练报告一致；后续产品集成修改源码时，仍可核对当次真实运行版本。

## 图片质量：有明确失败项

已直接查看两组 PNG，详细观察保存在 `visual-review.json`。蓝色陶瓷杯在基座与候选里都可辨，杯口和杯身形状发生变化。红壶提示实际生成白壶与红背景，候选还多出红杯，茶壶把手结构异常；红色属性、单物体和结构质量未通过。这里的 LoRA 有效指实际训练权重被重新加载并影响输出，不表示质量改善。

这不是盲评，也没有用户业务素材、品牌一致性、广泛种子、文字准确度或视频连续性评测。4 张训练图均由同一基座生成，只作为来源明确的技术试验数据。

另逐张查看了训练源图：101/103 为红白配色壶，102 的把手呈额外壶嘴状，104 有第二个白色小壶。它们与统一的红壶 caption 存在颜色、结构、数量偏差，不能通过业务训练数据质量准入；原冻结数据和实际训练证据保留，不事后改 caption 或筛选成功样例。

## 保留的失败与修复

首次 `acceptance-v1` 已生成真实 PNG，但上游 scheduler 的 `lambda_min_clipped=-inf` 不能写入严格 JSON，流程在报告写出失败。现将该无界默认值显式保存为对象并补充单测，重新建立 `acceptance-v2` 完整执行通过；没有覆盖旧输出或把无完整报告的 v1 当作成功证据。

## 视频：真实 SVD、独立重载与解码

固定源 4,509,208,405 字节已全部下载，三个 fp16 权重通过官方 LFS SHA256，元数据通过 Git blob 摘要。首个视频在 `.artifacts/m4-media/video-acceptance-v1`，另一个 Python 进程同配方重载在 `video-acceptance-repeat-v1`。输入为已检查的基座蓝杯 PNG，等比缩放补边到 1024×576；完整原图与条件图摘要均已冻结。

两次都完成原生 SVD 的 25 步时序生成，得到 14 帧、7 FPS、2 秒的 H.264 MP4；全部浮点帧有限，FFprobe 实际计帧及 FFmpeg 全帧独立解码通过。两个不同进程的冻结参数完全一致，浮点帧最大差 0.0，MP4 SHA256 同为 `53913f16d15d779939c4579479362bc884fe67b8449972d752e67d1294c51cad`。生成部分分别耗时 118.53 秒、132.58 秒；首次可能与暂停的文本训练有设备驻留重叠，这些不是独占性能基准。没有启用 MPS 算子回退。

直接查看条件图与第 0/6/13 帧：蓝杯主体和背景保留，仅有极轻微轮廓、纹理抖动，画面近乎静止。因此真实推理与媒体编码功能通过，但明显运动质量未通过，不能以帧 SHA 不同宣传镜头或商品动作。汇总见 `.artifacts/m4-media/video-repeat-and-visual-review.json`；各次的 `acceptance.json`、浮点帧 `pixels.npy`、14 张 PNG、解码清单与执行器源码快照均保留。

## 媒体产品执行桥验证

新增 `workers/media_worker.py` 与 `adapters/media/preflight.py`，没有修改已冻结的图片/视频 CLI。6 项桥 CPU 测试通过，覆盖精确参数、完整输入身份、额外隐藏文件/符号链接拒绝、输出保护、真实子进程进度与失败、取消后回收。4 种实际输入预检均通过：图片生成、LoRA 图片生成、图片训练和视频生成；预检只检查实际分词、文件、解码和 LoRA meta 形状，不加载基座权重。

真实桥验收在 `.artifacts/m4-media/bridge-acceptance-v2`：图片生成→12 步训练→本次新 LoRA 独立生成均成功，收到完整 12 个真实 step 事件，所有封存产物摘要由独立测试进程复核。新图片、LoRA 和候选图片与原先直接查看过的对应产物 SHA 完全一致。视频在 CLI 日志显示实际完成第 1/25 步后发送同组 SIGTERM，桥返回 130/CANCELLED，没有完成事件，整个进程组已消失；后续另核验了全部原桥与模型子进程 PID 均不存在。

汇总、事件和进程核验分别在 `acceptance.json`、各 case 的 `*.events.jsonl`、`independent-output-and-process-audit.json`。这是执行桥的实际生命周期证据，控制 API 与普通用户 UI 工作流由主产品报告另行验收；取消视频不算成功视频。
