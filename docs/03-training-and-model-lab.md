# 训练、微调与模型实验室规格

版本：1.1 · 日期：2026-09-09 · 状态：已按审计修订的待实现规范；具体适配组合与修复效果待验证。

相关文档：[数据规格](05-data-model-and-assets.md)、[运行与硬件](04-runtime-and-hardware.md)、[评测验收](11-testing-and-acceptance.md)。

## 1. 三个维度必须分开

训练类别说明处理什么模型，例如语言、图像或音频；训练类型说明优化目标，例如 SFT、DPO、语音识别微调；参数更新方式说明修改哪些权重，例如 LoRA、QLoRA、全参数或指定模块。

SFT 和 LoRA 可以组合，不能作为同一个下拉列表中的互斥选项。用户提及的 STF 按上下文归一为 SFT（监督微调）；界面和文档统一使用 SFT。

## 2. 方法与数据矩阵

下表保留最终 Demo 的方法范围，不代表每个模型和每个硬件都已经支持。

| 类别 | 训练类型 | 优化目标 | 数据结构 | 可能的更新方式 | 首选验收点 |
| --- | --- | --- | --- | --- | --- |
| 语言 | SFT | 学习指令和对话回答 | 多轮 messages | LoRA、QLoRA、全参数 | 正常任务和格式遵循 |
| 语言 | CPT 继续预训练 | 适配连续领域文本 | text、source_id | LoRA、全参数；量化路径单独验证 | 领域能力和通用能力回归 |
| 语言 | DPO | 偏好选择 | prompt、chosen、rejected | LoRA、QLoRA、全参数 | 固定偏好集胜率与质量 |
| 语言 | GRPO | 可验证奖励优化 | prompt、answer、奖励配置 | 适配器或全参数 | 奖励有效性和独立答案正确率 |
| 语言 | PPO | 奖励模型驱动优化 | prompt、奖励模型、参考策略 | 由训练适配器声明 | 奖励、KL 与独立能力检查 |
| 多模态 | SFT | 图文／音视频理解 | messages、media | LoRA、全参数、指定模块 | 真实媒体读取与语义回答 |
| 多模态 | DPO | 媒体相关偏好 | media、prompt、chosen、rejected | 由模型模块结构决定 | 媒体事实与偏好表现 |
| 图片 | 扩散模型微调 | 风格或领域适配 | image、caption | LoRA、全参数 | 主体、风格与内容一致性 |
| 图片 | DreamBooth | 主体适配 | image、caption、trigger | LoRA、全参数 | 主体保持及泛化 |
| 图片 | 配对图像训练 | 融合、修复或编辑映射 | source、reference、target | 全参数、指定模块 | 对齐、结构和细节回归 |
| 视频 | 视频微调 | 镜头、动作与风格 | video、caption、fps、frames | LoRA、全参数 | 时序一致性与运动质量 |
| 音频 | 语音合成微调 | 音色／发音／韵律 | audio、text、speaker | 全参数、指定模块 | 发音、可懂度和音质 |
| 音频 | ASR 微调 | 语音识别 | audio、text、language | LoRA、全参数 | CER／WER、分段和时间戳 |
| 音频 | 声音转换训练 | 音色转换 | audio、speaker、音高特征 | 模型适配器定义 | 内容保持与目标音色 |
| 音频 | 音乐生成微调 | 音乐风格与条件生成 | audio、description、duration | LoRA、全参数 | 时长、描述符合度和听感 |

训练库候选包括 [TRL](https://huggingface.co/docs/trl/index)、[PEFT](https://huggingface.co/docs/peft/index) 与 [MLX-LM](https://github.com/ml-explore/mlx-lm)。选用这些库不自动使矩阵全部成立；版本、模型结构、量化和设备仍需适配验证。PPO 等变化较快的训练接口必须单独锁定版本并保留兼容层。

## 3. 原型模型模板

Demo 包含 Qwen3-4B、Qwen2.5-VL-3B、Qwen Omni 多模态示例、SDXL、FLUX、图像融合自定义网络、Wan 视频示例、CosyVoice、Whisper、RVC、MusicGen。

这些名称是原型配置模板，不应直接成为正式产品中“已通过适配”的模型清单。正式条目必须记录仓库标识、固定 revision、权重校验值、tokenizer／处理器版本、许可证文件引用、支持的输入和训练模块。Qwen Omni 等描述性示例必须替换为一个具体可下载、可加载的版本才能进入实机验收。

## 4. 训练配置字段

| 参数 | 说明 | 默认与约束策略 | 记录位置 |
| --- | --- | --- | --- |
| 任务名称 | 用户目标和区分用途 | 必填；允许后改显示名，不能改任务编号 | Task |
| 模型版本 | 固定源权重和 tokenizer | 必填；不得使用浮动 latest 作为完成记录 | ModelVersion |
| 训练类型 | SFT、DPO 等 | 从能力声明生成 | TrainConfig |
| 更新方式 | LoRA、QLoRA、全参数、指定模块 | 与模型和训练引擎联合校验 | TrainConfig |
| 目标模块 | 适配层／视觉连接层／输出层 | 展示解析后的模块列表 | TrainConfig |
| 数据版本 | 输入样本及处理结果 | 提交时固定版本与划分 | DatasetVersion |
| 训练步数／轮数 | 停止条件 | 正式产品允许选一种主条件，展示换算逻辑 | TrainConfig |
| 学习率 | 更新幅度 | 必须是有限正数；范围由适配器限制 | TrainConfig |
| 每设备批量 | 单设备 micro batch | 正整数，与内存检查关联 | TrainConfig |
| 梯度累积 | 多个微批次累积后更新 | 正整数；展示有效批量 | TrainConfig |
| 最大序列长度 | 训练截断与打包长度 | 受模型和内存限制 | TrainConfig |
| 分词与监督配方 | 实际参与损失计算的 token 和边界 | 版本化模板，提交前检查实际 token 与 labels | TokenizationRecipe |
| 种子 | 划分／初始化等可复现输入 | 明确哪些随机过程使用该种子 | TrainConfig |
| LoRA rank／alpha／dropout | 适配器结构与缩放 | rank 在 Demo 已有，其他待真实实现补齐 | AdapterConfig |
| 优化器／调度器 | AdamW 等优化器和学习率策略 | 由后端能力列出，禁止任意字符串执行 | OptimizerConfig |
| Warmup／权重衰减／梯度裁剪 | 训练稳定性配置 | 默认来自版本化模板，可查看实际值 | OptimizerConfig |
| 训练精度 | FP32、FP16、BF16 等 | 根据硬件、算子和引擎验证 | EnvironmentConfig |
| 梯度检查点 | 用重算降低激活内存 | 显示速度与内存取舍 | TrainConfig |
| 保存／评测间隔 | 中间检查点和验证频率 | 正数；支持结束时额外保存 | CheckpointPolicy |
| 输出保留策略 | 检查点数量和空间预算 | 不自动删除被引用的产物 | ArtifactPolicy |

有效批量按“每设备批量 × 梯度累积 × 数据并行设备数”说明。张量并行设备数不能直接代入这条公式。分布式训练采用何种并行方式由执行器声明。

### 4.1 原型数值不是生产上限

Demo 使用训练步数 10—10,000、验证集比例 5%—40%、批量 1—64、序列长度 128—131,072 等演示校验。正式产品必须改为模型、方法和设备联合约束，并在能力记录中说明来源，不照搬这些常量作为产品能力承诺。

### 4.2 SFT 的分词与监督合同（AUD-10）

`messages` 通过结构检查后仍不能直接训练。训练模板必须引用不可变的 `TokenizationRecipe`，同时固定 tokenizer、处理器、聊天模板、监督范围、EOS／PAD、截断与样本拼接策略；配方摘要进入数据检查报告和执行快照。适配器不能用自身默认值替代其中任何一项。普通用户选择训练模板即可，高级详情允许查看解析后的策略。

首个多轮对话模板采用 `assistant_only`：只监督助手回答及模板规定的回答结束标记，系统／用户消息和媒体占位／特征位置不参与文本损失。支持其他监督目标时使用不同的配方版本并重新检查；不能把 `completion_only` 或 `all_tokens` 与其无条件互换。模板不能生成可靠角色掩码、模型有独立媒体目标但未声明处理方式时阻断该组合。

| 项目 | 必须固定的规则 | 检查与失败处理 |
| --- | --- | --- |
| 分词与角色掩码 | tokenizer／processor／模板版本、特殊 token、监督角色、结束标记位置及标签移位由模型还是数据整理器负责 | 保存代表样本的 token／labels 对照和摘要，防止重复移位；掩码不是按显示文本猜测 |
| EOS 与 PAD | 结束标记插入规则、是否监督、PAD 位置规则、忽略值 `-100` | 每个 padding 位置均不参与损失；EOS 与 PAD 编号相同时按位置区分，不误屏蔽真实结束标记 |
| 超长样本 | 首个模板默认排除超长样本并报告；可选模板仅移除最旧完整轮次，保留系统消息与完整的最后监督回答 | 单个回答仍超长则排除；不得截掉全部回答却保留问题继续训练，排除影响由用户查看 |
| 样本拼接 | 首个模板关闭 packing；开放时声明边界标记、位置编号、attention 隔离与 loss 掩码策略 | 用跨样本边界反例验证，无法保证所声明边界则不开放，不能将拼接后序列冒充单样本 |
| 多模态对齐 | 媒体顺序、处理器版本、展开后的 token／特征位置、文本监督与非文本目标 | token、labels、媒体位置一致，非文本损失只能由对应模型适配器显式声明 |

检查报告展示输入样本、可训练样本、被截断／排除样本、各原因数量、有效监督 token 总量及分布。零有效监督的样本必须排除并定位；整个训练集或必需验证集无有效监督时拒绝提交。策略、模板、媒体处理或序列长度变化后原检查失效。多轮、超长回答、空回答、仅系统消息、padding、拼接边界和媒体样本都进入 AC-04／AC-06 的实际 token 与 labels 验收，不能只验证 JSON 字段存在。

媒体样本不得截断媒体 token／特征范围后继续训练；没有验证过安全截断的组合保留完整序列并按资源预算排除超长样本。上述首个模板是本项目的明确选择，不能视为底层库默认；[TRL SFT 文档](https://huggingface.co/docs/trl/sft_trainer)分别定义助手监督、完成部分监督和 packing，并指出视觉样本截断可能移除图片 token。

## 5. 多媒体训练补充

### 5.1 图像

数据准备包含图片可解码检查、长宽、通道、颜色空间、方向信息、重复与近重复检查。裁剪、缩放和标注修改必须生成处理配方。配对任务需要明确 source、reference、target 是否像素对齐，不能只校验文件存在。

参数包括分辨率、裁剪策略、增强、主体触发词、文本编码器是否训练、先验保持等模型相关配置。损失函数、网络模块和优化器必须属于适配器白名单，不能通过任意脚本字段注入。

### 5.2 视频

记录容器、编码、帧率、帧数、时长、分辨率、抽帧策略和字幕／描述。变帧率素材必须定义统一时间基准。切片边界以时间和帧索引双重记录，处理后的数据产生新版本。

验收必须包含真实视频解码和短片训练；仅显示关键帧、移动一张图片或完成文件写入不算视频训练／生成通过。

### 5.3 音频

记录采样率、声道、时长、响度、切片、转写、说话人和语言。结束时间必须大于开始时间且不超过实际音频长度。重采样、降噪、静音切分等处理由用户选择并保留参数；不默认进行无法追溯的自动清洗。

语音合成、ASR、声音转换、音乐生成使用独立数据与评测适配器。音频可播放只证明文件可以解码，不能代替语音质量或训练效果验收。

## 6. 提交前检查

分为数据、模型、环境、配置和资源五类检查。检查结果可以是通过、阻断或提示；每条结果包含原因、字段位置、可执行的修复动作和检查版本。

必需阻断：模型或数据文件缺失／损坏、数据格式不符、必要组件未准备、设备不可达、参数无效、引擎不支持当前方法、用户选择的精度不被实际设备支持、输出目录不可写。

提示项：预计内存接近上限、样本量较少、验证集偏小、实验目标描述不足。用户未填写来源声明时保留“未填写”，不能由 AI 变成“已授权”，也不把来源声明缺失伪装成技术格式错误。

## 7. 模型实验室

| 专项 | 输入 | 必要设置 | 输出 | 独立验收 |
| --- | --- | --- | --- | --- |
| 行为调整／破甲对照 | 源权重、目标数据、回归集 | Heretic／Abliterix 版本、目标、候选预算、允许能力下降 | 每种方法的候选与变更记录 | 正常任务、目标行为、格式和通用能力 |
| 蒸馏 | 教师、学生、数据 | 教师采样、损失／目标、训练预算、教师输出版本 | 学生候选及教师来源 | 学生质量与体积／速度对照 |
| 合并 | 兼容基座与适配器／模型 | 方法、权重、结构校验 | 新权重或合并适配器 | 能否加载、能力回归、配置可重现 |
| 量化 | 源权重、可选校准集 | 格式、位宽、分组、校准策略 | 运行产物 | 正确性、体积、速度、质量变化 |
| 转换 | 原始模型、处理器与示例输入 | Core ML／ONNX／TorchScript 等目标、形状、精度 | 目标格式及元信息 | 数值一致性和目标设备执行 |

### 7.1 行为调整研究边界

保留用户确认的入口和双引擎独立候选设计；不把方法名称等同于产品已具备技术能力。自研研究路径在没有执行适配器时保持不可启动。第一步是核实具体上游来源、版本、输入条件和输出形式，再运行正常任务与目标行为对照。

### 7.2 蒸馏边界

区分教师生成数据后的离线蒸馏与训练过程中调用教师的在线蒸馏。教师调用的地址、输入发送范围、费用来源、输出缓存和失败重试需要明确记录。远程教师不可用时不能默默切换其他教师。

### 7.3 合并边界

先检查架构、层数、tokenizer、基座版本和适配器目标模块。维度相同不等于语义兼容。合并不覆盖任一输入；产生新版本并记录参与权重。

### 7.4 量化／转换边界

转换不承诺提升速度，量化不承诺保持全部能力。产物登记前至少完成独立加载、固定样例对照和目标运行环境检查。ANE 验收必须使用实际 Core ML 产物及设备执行记录。

转换后的 `ModelVersion.format` 和实际文件 manifest 参与默认引擎选择。候选可以继承来源关系，不能继承已不兼容的源模型运行设置；“产物格式能被引擎读取”与“引擎允许此模型操作”必须双向成立。需要桥接转换时生成独立准备计划和新版本，用户完成后再试用；不可在加载时静默把 Core ML 产物当作 PyTorch 权重。具体规则见 [04](04-runtime-and-hardware.md) 的格式能力合同。

## 8. 评测与候选登记

评测集在训练前冻结，避免根据本次输出反复改变准入条件。报告同时保存基线、候选、评测配置、样本版本、阈值、逐样本结果和汇总。

语言任务至少覆盖业务正确性、格式、正常任务回归和目标行为；图像关注主体与结构；视频增加时序；音频按任务选择 CER／WER、可懂度、音质或听评。无法自动量化的项目标为人工评审，不伪造一个综合分数。

登记候选的前提是产物存在、哈希一致、能独立加载、要求的评测已完成且符合预设规则。登记操作幂等；同一候选重复点击不产生多个模型版本。

## 9. 完成标准

每一个“支持的训练组合”都必须有一条从真实数据到独立加载候选的证据链：输入版本、处理配方、最终配置、设备环境、训练日志、检查点、评测报告、产物哈希、运行结果。训练损失下降、脚本成功退出或页面显示完成，均不能单独作为交付依据。

E-03 的回程验证前移到 M0 的 TV-03：锁定一个具体的 NVIDIA 训练组合，将同一份实际 LoRA 产物带到指定 Apple 试用引擎，记录基座 revision、目标模块、适配器摘要、模板、必要转换及固定样例结果。不能用另训的 Apple 适配器或只下载的演示文件代替。试验只判断该组合是否可行；M3 的 AC-26 再覆盖产品入口、传输、候选登记、配置差异和失败恢复，不提前宣称跨端训练产物普遍兼容。
