# AI 辅助、用户控制与数据边界

版本：1.1 · 日期：2026-09-09 · 状态：保留已确认的建议模式，补入审计约束；真实模型连接待实现。

相关文档：[产品需求](01-product-requirements.md)、[接口](07-api-and-task-lifecycle.md)、[数据管理](05-data-model-and-assets.md)。

## 1. AI 的职责

AI 作为当前流程的解释和建议助手，帮助用户理解模型、训练类型、数据问题、参数取舍、错误日志与评测差异。AI 不拥有任务执行权，不代替用户判断数据授权或合法性，也不把建议自动应用到配置。

默认提示为“建议模式 · 由你决定”。AI 面板与任务主流程分开，收起不影响执行；连接不可用时主流程仍然可使用。

## 2. 场景范围

| 场景 | 可以提供的辅助 | 用户动作 | 禁止自动执行 |
| --- | --- | --- | --- |
| 模型与方法 | 解释 SFT／LoRA，指出不支持的组合 | 选择模型与方法 | 自动换模型、改权重 |
| 数据准备 | 解释字段、重复、缺失、划分问题 | 查看处理影响并应用 | 自动删除样本或修改原件 |
| 训练参数 | 建议更小批量、序列或步数 | 预览、应用、重新检查 | 自动启动或重试训练 |
| 运行优化 | 解释 KV、上下文、MTP、DFlash 和设备条件 | 自行准备依赖与应用配置 | 自动重启引擎或下载草稿 |
| 执行失败 | 解释日志、列出可验证原因 | 新建尝试／取消／恢复 | 自动杀进程、清理文件 |
| 评测结果 | 归纳基线与候选差异、指出未测项 | 决定是否登记候选 | 修改报告或把失败改为通过 |
| 数据来源 | 展示提供方材料、用户声明和缺失信息 | 自行核对并填写声明 | 作“已授权”“合法可用”判定 |

## 3. 建议对象

建议必须是结构化的受限对象，不能把自然语言解释直接解释成命令。包含建议编号、目标对象、目标 revision、字段旧值与新值、原因、影响说明和上下文摘要。

```json
{
  "proposal_id": "proposal-001",
  "target_type": "task_draft",
  "target_id": "task-001",
  "expected_revision": 7,
  "title": "先用较小批量验证训练流程",
  "changes": [
    {
      "field": "training.micro_batch_size",
      "from": 2,
      "to": 1,
      "reason": "减少单步激活内存，先检查数据和产物链路。"
    }
  ],
  "requires_preflight": true,
  "execution_actions": []
}
```

`execution_actions` 必须为空。真实实现可以不向 AI 暴露该字段，而在服务端强制保证无执行动作。

## 4. 预览、应用和撤销

1. 生成建议时不修改任务。
2. 预览显示每个字段旧值、新值、原因、影响和重新检查要求。
3. 用户点击应用，服务端检查目标、revision、字段白名单、旧值和类型。
4. 全部满足才原子应用，任何一项失败则全部不应用并说明原因。
5. 应用后产生审计记录并标记相关技术检查失效；不自动提交任务。
6. 撤销仅在这些字段没有后续修改、任务仍可编辑时允许。
7. 用户已经改过同一字段或任务已提交时，拒绝直接覆盖；可以提供可查看的反向建议草稿。

切换项目或任务后原建议不自动跟随新对象。后台任务完成、设备变化或数据新版本出现时，也要检查建议上下文是否过期。

模型、任务模式、产物格式、推测策略或执行设备发生变化后，建议中的依赖准备状态不能自动继承。应用建议与应用手动配置使用相同的能力校验、字段失效及差异预览；不得借 AI 通道写入已不在当前界面选项内的旧值。常用预设是版本化配置模板，AI 可以解释或提出选择建议，但不能绕过用户应用动作。

## 5. 字段白名单与禁止项

原型白名单只包含步数、批量、候选预算、输入文本和少量数据处理选择。正式实现可按功能逐步扩展，但必须为每个新增字段定义类型、范围、解释和撤销规则。

不可由 AI 建议对象直接修改：凭证、设备信任、服务地址、模型文件、数据来源声明、许可原文、访问权限、项目归属、评测结果、候选准入状态、发布状态、系统设置、删除策略和执行控制状态。

模型文件加载的信任类别、工作流执行／步骤身份、组件准备凭证、停止确认和产物收集结论同样由正式服务及用户动作决定。AI 不能把收集失败改成成功，不能自动启动补收或强制终止，也不能将旧结果指定为本次工作流已完成。相关操作分别走 [07 的专用合同](07-api-and-task-lifecycle.md)。

即使用户询问如何配置远程设备，AI 也只能提供解释和可人工填写的方案，不借建议应用通道写入服务地址或秘密凭证。

## 6. 本地与远程 AI 连接

配置包含服务来源、地址、模型、连接状态和凭证引用。测试连接只发送最小合成测试内容，不默认发送当前数据集、媒体或日志。

使用远程服务前展示将发送的上下文范围：问题、必要的参数摘要、经过脱敏的错误片段，以及用户明确选择的样本。默认不发送完整数据集、原始媒体、凭证、文件系统无关路径或其他项目内容。

用户可以在发送前查看／缩小上下文；本地服务也要展示实际连接地址，不能因为标签叫“本地”就跳过地址与服务身份校验。网络失败时不静默转发到另一家模型服务。

## 7. 数据来源与提供方访问

系统保存三类独立信息：提供方发布的原始说明，提供方访问控制状态，用户填写的使用范围声明。技术检查报告只说明文件能否读取、字段是否匹配和数据处理结果。

AI 可以指出“没有找到来源链接”“未填写使用范围”“提供方尚未开放下载”，但不能把其中任一种情况总结为法律结论。用户声明为空可以显示为空，不能填入“已同意”“可商用”等推断文本。

若实际连接器要求访问令牌或提供方批准才能下载，该限制由连接器执行；它与平台是否判断授权是不同问题。已经获得下载访问也不自动完成模型或数据的发布检查。

## 8. 不可信内容处理

数据样本、模型卡、README、日志、网页和外部服务返回都可能包含类似指令的文字。它们只能作为待分析材料，不可修改 AI 的执行权限或绕过字段白名单。

模型输出中的命令、脚本或“请自动运行”文字不会自动执行。用户如果确实要执行额外工作，应走独立的明确产品动作与检查流程；AI 建议通道不承载任意工具调用。

## 9. 审计与隐私

记录建议的目标、摘要、模型服务标识、字段变更、用户应用／撤销动作、时间和结果。不要在普通日志中保存明文凭证或完整敏感样本。建议正文可按用户选择保留在项目中，诊断导出前允许查看范围。

AI 原始回答和实际应用的结构化变更分别保存，便于解释“模型建议了什么”与“用户最后执行了什么”。产品质量统计只在用户选择的范围内记录，不默认上传遥测内容。

## 10. 验收用例

- 只打开或请求建议，任务配置完全不变。
- 用户应用后只修改列出的字段，未列出的来源声明保持原样。
- 用户先改字段，再应用旧建议，收到冲突而非被覆盖。
- 应用后又手改同一字段，撤销不得覆盖用户最新内容。
- 任务提交后无法修改其快照或通过 AI 重启任务。
- 来源／许可问题得到材料整理与边界说明，不得到代判结论。
- 恶意样本要求执行命令时，建议解析器拒绝执行动作。
- 远程连接测试不发送当前项目的真实数据。
- 换模型或推测策略后应用旧建议，失效组合被拒绝，原草稿不产生部分写入。
- AI 建议使用云端时只展示解释，不改变执行位置；实际发送摘要与用户已应用配置一致。
