## 2. 建议技术决策记录

### ADR-001：采用模块化控制服务与独立执行器

状态：建议采用，M0 验证。

原因：现有产品需要可靠的任务、版本与结果关系，多种引擎依赖差异大。控制服务维护统一合同，独立执行器承担计算，可避免某个模型环境崩溃拖垮全应用。

替代方案：全部在前端执行不适合真实训练；一开始拆成大量微服务增加部署成本。先使用单体领域服务，后续有真实规模需求再拆分。

验证：最小任务从界面提交到产物落盘，终止执行器后控制服务仍可响应并恢复状态。

### ADR-002：建议 React／TypeScript + Tauri + Python

状态：候选技术栈，尚未锁定版本。

原因：复用 Web 界面能力，并接近 Python 模型生态。风险在多平台打包、侧进程与本地依赖体积，需要 M0 验证。若桌面壳成为阻碍，可先以本地 Web 宿主验证业务合同；这不改变正式产品的桌面目标。

### ADR-003：SQLite 元数据与文件资产分离

状态：建议采用。

原因：本地单用户任务索引适合事务元数据库，大模型和媒体适合文件存储。风险是事务和文件提交之间的一致性，应通过临时写入、摘要校验、原子登记和恢复扫描处理。

### ADR-004：能力声明驱动配置

状态：产品要求，技术结构建议。

原因：运行参数由模型、引擎、硬件和版本联合决定。前端控件和后端校验共享 schema，但后端必须重新校验。风险是能力表变成静态宣传表，需记录来源、探测结果和实机报告。

### ADR-005：先实现已配置远程资源

状态：建议采用。

原因：首期重点是运行与训练闭环，不同时建设云采购与费用结算。云实例创建、预算和销毁作为后续独立能力；当前仅接入用户已有服务器或实例。

### ADR-006：AI 无执行权限

状态：已固定的产品边界。

原因：用户要求实时建议但不能干预。建议应用是一种受限配置变更，不接收任意命令；执行和外部动作走独立用户入口。风险是自然语言工具调用绕过边界，须通过服务端白名单与合同测试阻止。

### ADR-007：实验产物采用不可变版本

状态：建议采用，与可追溯目标一致。

原因：失败重试、量化、转换和合并都会产生新的实验分支。覆盖同一路径会损坏证据链。风险是磁盘占用上升，通过内容去重、引用和明确清理处理，而不是覆盖旧产物。

### ADR-008：工作流执行身份与步骤推进原子化

状态：纳入规范，待实现；回应 AUD-01、AUD-02。

工作流定义可以复用，每次执行和步骤尝试必须独立编号并绑定输入版本。进入下一步前先检查目标是否可用，再原子保存状态。旧结果复用是显式操作。采用同一领域事务完成即可，首期不引入独立分布式工作流平台。

### ADR-009：不可变计算尝试与可补收产物分开

状态：纳入规范，待实现；回应 AUD-07、AUD-08。

暂停／取消等控制按执行器证据和状态版本裁决，停止未知不能冒充成功。原执行尝试终态不改写，产物补收使用独立记录，只传输、校验和登记已有文件，不触发训练重算。具体字段与例外以 05、07 为准。

### ADR-010：阶段验证和最终产品验收分开

状态：纳入计划；回应 AUD-12。

M0 用 TV-01—TV-03 完成组合、侧进程和最小 LoRA 回程试验；M1—M6 采用明确的阶段门槛。工作包的最终 AC 列表示追踪归属，只有阶段验收要求的子集才影响该阶段完成，禁止 M0 依赖 M6 安装包。M0 通过后仍需锁定模型、设备、人员与版本，不能直接宣布完整产品可交付。

### ADR-011：监督配方、加载信任和缓存身份显式化

状态：纳入规范，待适配验证；回应 AUD-09—AUD-11。

SFT 固定分词与损失计算策略；媒体参与缓存身份；模型导入计划记录具体格式、加载方式与信任类别。这些规则属于适配器合同，普通用户可以通过已说明的模板使用，不要求用户逐个填写底层字段。

### ADR-012：常用预设和首次路径采用小范围增强

状态：纳入计划；回应 E-01—E-05。

保留四类结构，补直接试用与最近运行；常用预设限模型默认、低内存、低延迟，效果需验证；M0 前移实际 LoRA 回程试验；结果修订与生成配方分开。原型和测试归入团队固定目录安排在 WP-04，迁移先核对清单和摘要并保留旧资产。本轮仅归档文档，不迁移或删除原型。

## 3. 风险登记

| 风险 | 影响 | 早期信号 | 缓解办法 | 责任／阶段 |
| --- | --- | --- | --- | --- |
| 组合数量过大 | 排期失控、界面假支持 | 新增开关多于真实报告 | 按模型×引擎×设备分项，限制每阶段目标 | 产品 + ML／全程 |
| 上游接口变化 | 训练／推理失效 | 同一配置升级后行为变化 | 锁版本、合同适配、保留旧环境 | ML／M0—M6 |
| 依赖冲突 | 安装和运行不稳定 | 一个环境升级破坏另一个 | 独立环境和摘要，不使用全局任意依赖 | 平台／M1—M2 |
| 多媒体流程只剩形式 | 用户无法得到真实产物 | 只有预置图／音频或文件元数据 | 真解码、真生成、独立播放与质量验收 | ML + 测试／M4 |
| 模拟状态进入生产 | 虚假完成、虚假测速 | 连接即成功、计时器即完成 | 演示隔离，生产路径禁止模拟成功函数 | 后端 + 测试／M1—M6 |
| 数据或版本覆盖 | 结果不可追溯 | 旧任务指向变化的文件 | 不可变版本、摘要、事务和引用 | 后端／M1 |
| 检查点不能真实恢复 | 长任务丢失 | 只保存权重却显示继续训练 | 声明恢复范围，保存优化器和随机状态 | ML／M3 |
| 优化有速度无质量保证 | 模型效果退化 | 只报告 tokens/s | 同时比较质量、内存、接受率与总延迟 | ML + 测试／M5 |
| ANE／NPU 使用被夸大 | 误导兼容声明 | 选择后端即显示硬件已使用 | 区分允许计算单元与真实执行证据 | 平台／M5 |
| 远程断连重复执行 | 资源重复消耗 | 超时即再次提交 | 幂等键、远端持久状态与先查后重试 | 后端／M2 |
| AI 覆盖用户设置 | 违背控制边界 | 未点击应用字段就变化 | 建议草稿、旧值校验、原子应用 | AI + 测试／M3 |
| 大文件与磁盘耗尽 | 应用不可用、产物损坏 | 缓存与作品共用无配额空间 | 空间预检、分区统计、可恢复清理 | 平台／M1—M6 |
| 研究方法来源不明 | 无法适配或发布 | 只有方法名、没有固定项目版本 | 分项核查源码、依赖、输入和许可材料 | ML／M5 |
| 旧选择影响新任务 | 可见控件与提交内容不同 | 换策略、模型或格式后旧值仍生效 | 下游失效、差异预览、服务端双向校验；工作流原子推进 | 前端 + 后端／M1—M5 |
| 监督目标不确定 | 数据相同却训练不同目标 | 仅检查 JSON，没有有效 labels 统计 | 版本化监督配方、超长与空监督负例 | ML／M3 |
| 补收演变成重算 | 重复花费算力 | 文件传输失败只能重新训练 | 独立 collection、同源 manifest、计算次数验收 | 后端 + 平台／M1—M3 |
| 检查器假一致 | 编号齐全但任务漏做 | 错配关系和周期仍通过 | 直接需求覆盖矩阵、实际数字与依赖检查、语义负例 | 测试 + 产品／本轮起 |

## 5. 不应继续沿用的原型简化

固定进度条、预置模型输出、单一图片素材、模拟访问批准、连接按钮直接置 ready、以人工选择生成评测通过、所有字段放进一个无类型对象、静态硬件厂商模板、任意模型使用相同采样器。

这些简化适合演示界面，不适合正式执行。具体差距和工作包见 [14](14-prototype-traceability.md)。发现差距时优先修正执行语义，不重新扩张信息架构。
