## 2. 工作台首页

### 2.1 页面内容

- 四个入口卡片包含类别、适用目标和常见方法，主要操作统一为“开始训练／微调”。
- 每类保留“直接运行／试用”次级入口；有运行草稿或历史时提供“继续上次运行”，不创建新的顶级导航。
- “继续最近任务”展示当前项目最近任务名称、编号、类别、状态和下一步操作。
- 状态操作采用用户语言：继续配置、查看运行、继续评测、查看失败原因。
- 次级入口链接到模型库、数据集市场和模型实验室，不再增加另一套“创作空间”导航。

### 2.2 继续任务规则

按用户进入的训练或运行类型，优先恢复本项目、本类别上次选择的草稿。最近任务同时包含训练和生成，显示类型与下一步。没有草稿时创建新任务；已有执行中任务时允许查看执行，但不能把它的参数当成可编辑草稿。用户主动“新建训练任务”始终生成新编号；运行页的新建操作表达为新建运行，不诱导用户误建训练。

切换项目时保留各项目的最近选择、草稿与历史。返回原项目恢复原上下文；后台任务完成时更新所属项目的任务，不将用户强制带离当前页面。

## 3. 路径 A：语言模型 SFT + LoRA

| 步骤 | 用户操作 | 页面反馈 | 校验／失败处理 |
| --- | --- | --- | --- |
| A1 | 工作台选择语言与多模态 | 打开当前训练草稿 | 没有草稿时新建 |
| A2 | 选择基座模型 | 展示输入类型、版本、训练能力 | 未准备模型指向准备入口 |
| A3 | 选择 SFT、LoRA | 显示所需数据和适配器产物 | 不支持组合给出原因 |
| A4 | 选择或导入数据 | 预览实际样本、字段、版本 | 不匹配数据不能带入 |
| A5 | 检查并决定清洗处理 | 展示缺失、重复、划分、媒体问题 | 用户应用清洗后生成数据版本并重新检查 |
| A6 | 设置步数、批量、学习率、环境 | 展示训练参数与依赖摘要 | OOM 仅预测风险，不伪造实际剩余显存 |
| A7 | 检查并启动 | 显示模型、数据、设备、费用来源、最终设置 | 不支持字段或未连接设备阻断 |
| A8 | 执行 | 实际日志、进度和可用检查点 | 失败保留现场，重试新建尝试 |
| A9 | 评测 | 基线与候选的固定样本对照 | 未通过者不得登记为可用候选 |
| A10 | 登记并试用 | 带入候选模型，保留来源实验入口 | 模型加载失败返回产物检查 |

“配置”分三步：模型与方法、准备数据、参数与环境。任务级页签为配置、运行、评测与产物。提交后配置转只读；修改通过“复制为新尝试”进行。

## 4. 路径 B：从模型库直接运行

1. 在模型库按类别和格式筛选，查看模型的来源、版本与运行条件。
2. 若组件缺失，启动下载／准备任务；下载期间可以离开页面，从队列查看进度。
3. 准备完成后点击运行，进入对应类别的运行／试用页，带入该模型。
4. 输入问题或提示词；需要媒体时选择素材并预览。
5. 打开“运行参数与优化”，按分组编辑草稿，点击“检查并应用”。
6. 回到主表单检查摘要，再点击发送、生成、开始转写等动作。
7. 结果出现在当前页并加入当前项目历史；用户可保存、比较、查看配方或载入继续修改。

模型已下载不等于引擎可以加载。真实应用在模型清单中区分“文件完整”“格式适配”“已加载”“运行通过”。点击运行时需要完成加载检查。

换模型时同步检查任务模式和素材类型，例如音频理解换成只有图像／视频能力的模型，应在草稿中清除不支持的模式并说明素材影响。不能让下拉框显示看图问答，提交值却仍是音频理解。转换候选的默认引擎按产物格式重新选择；没有可用路径时保留草稿并阻断运行。

## 5. 路径 C：运行参数与优化

### 5.1 入口和分组

主输入区常驻“运行参数与优化”摘要，显示引擎、硬件后端、上下文和输出限制等关键参数。提供“完整设置”“设备与引擎”“缓存与加速”快捷入口。

语言与多模态设置分五组：生成与上下文、KV Cache、Prefill／Decode、推测解码、设备与引擎。媒体模型设置为生成与加速、设备与引擎，不展示与该模型无关的语言参数。

### 5.2 编辑交互

- 打开时复制当前配置为独立编辑草稿；取消、关闭、Escape 都放弃未应用修改。
- 切换设备或引擎后重新计算适用项，保留仍有相同语义的生成参数，并展示优化项变化摘要。
- 切换推测策略或目标模型后，不匹配的草稿组件及准备状态失效。依赖检查覆盖目标、策略、草稿版本、思考模式和引擎，不能仅判断非空或 ready。
- 不能适用的选项展示原因与准备动作，不允许出现已勾选但实际被忽略的状态。
- “检查并应用”返回字段错误及可修复原因；成功后关闭弹窗并刷新摘要，不立即生成。
- 任务执行中，本次配置只读；用户可以另建运行草稿，但不能改写已提交快照。

### 5.3 常用预设与本次执行摘要

提供模型默认、低内存、低延迟三类预设模板；后两类仅在当前组合已定义且验证后显示可应用。模板带版本，列出相对当前配置的具体字段变化、失效的准备状态和模型重载要求。名称是目标偏好，不是性能承诺；没有实测时不显示节省量或加速倍数。预设与手动编辑使用同一份校验与取消流程，完整高级设置继续保留。

主表单常驻本次设备名称与本地／远端位置，必要时展开数据发送范围。摘要、发送按钮旁提示与提交快照均读取已应用配置，全局默认仅用于新建草稿。已有结果展示其提交时的环境，不能随当前默认设备变化。

### 5.4 关键异常

| 条件 | 提示与处理 |
| --- | --- |
| 输入加输出超过上下文 | 展示实际 token 预算；按用户选择拒绝或裁剪，并说明保留／删除内容 |
| 模型不支持关闭思考 | 禁用切换并说明模板／模型限制；不使用隐藏标签冒充关闭 |
| MTP 没有配套预测组件 | 说明缺少模型能力与可用引擎；不允许提交该优化 |
| DFlash 未准备草稿 | 指向匹配草稿准备流程，保留已有配置 |
| ANE 选择了原始权重 | 指向 Core ML 转换产物要求；不声称原始权重已由 ANE 加速 |
| 引擎变化后 KV 格式失效 | 展示变更前后，要求用户应用新草稿 |
| 远程服务断开 | 保留草稿和已收到结果，进入连接检查／任务重连 |

## 6. 路径 D：图像 → 视频 → 配音工作流

进入模型库的工作流页，选择“商品图 → 视频 → 配音”。详情显示三步、依赖模型和准备状态。依赖缺失时可以准备组件，但不能直接载入运行。

第一步生成商品图，结果保持为图像任务产物。用户点击带入下一步后，视频任务引用该图片的资产编号，而不是复制一个失去来源的临时文件。视频完成后生成配音；每步可以检查、重做或暂停继续。最终保存时保存工作流记录和全部选中产物引用。

第一版真实工作流采用逐步确认，不后台自动串行执行。任何一步失败，都保留前序成功结果；重做某一步后，后续旧结果显示“基于旧输入”，不得自动替换成新版本。音视频合成导出是额外能力，不能把存在独立视频和音频文件称为已经完成最终成片。

每次“载入工作流”创建独立执行编号，各步骤固定输入版本与尝试编号。重新开始时本次结果为空，历史缩略图仍可查看，但不能自动成为本次已完成结果。用户可以选择“复用历史结果”，查看原输入与当前输入的差异后明确关联，记录来源与选择动作。

“带入下一步”先检查本步骤产物完整、所属执行和输入版本、目标类别是否可进入，再一次性提交步骤与引用。目标运行中或暂停中时，保持原步骤、输出列表及两个草稿均不变，提供查看阻塞任务和返回入口。解除阻塞后再次操作只推进一次。修改上游步骤生成新输入版本，下游旧结果保留并标明基于旧输入，不显示为新版本完成。

## 7. 路径 E：数据市场与原任务返回

1. 从训练数据步骤打开市场，记录原项目、任务、类别和配置步骤。
2. 进入详情查看格式、样例、版本、提供方原文、访问条件和用户声明。
3. 开放数据可下载；受限数据先填写申请用途，由提供方处理访问。
4. 下载完成后选择“用于当前任务”；格式不匹配时禁用并解释需要的数据格式。
5. 返回原任务，保留名称、已设置参数和位置，新数据使旧技术检查失效。
6. 若另选新建训练，则明确创建新任务，不覆盖原任务。

提供方批准下载只改变访问状态，不生成“AI 已确认授权”的标签。导入 JSONL 后，列表切换到新数据所属类型，并高亮导入结果，避免数据已导入却看不见。

## 8. 路径 F：模型实验室与候选

专项入口先说明输入、方法和产物。行为调整可以选择 Heretic、Abliterix 或对照；蒸馏选择教师与学生；合并选择兼容输入与权重；量化选择格式与校准方案；转换选择目标格式与计算环境。

执行后统一进入评测与产物。每个候选独立展示状态和来源。原模型与候选采用同一套样本；候选未达标可以保存报告、调整后新建尝试，不能仅改显示状态获得登记资格。

转换／量化产物可用于运行；需要再训练时回到源权重。真实产品允许的后续转换链由适配器声明，不能把 Demo 的 `runtimeOnly` 简化限制扩展成所有运行产物永久禁止转换。

## 9. 全局交互规则

### 9.1 空态、加载和错误

空态说明缺少什么，并提供一个主要动作。下载、检查、预处理、加载和生成都使用不同状态文字。长操作显示可取消性和当前阶段；不能拿不断增长的伪进度替代未知进度。错误优先定位到可修复字段，同时保留技术详情展开入口。

### 9.2 表单与持久化

单位紧跟标签，例如 token、秒、Hz、GB；0、自动、不限制和未填写具有不同语义。选项变更不得让用户在输入过程中丢失焦点。草稿保存显示最近保存状态；离开页面时未持久化失败才提示用户处理。

### 9.3 弹窗与响应式

全局设置属于应用层，运行参数属于当前任务。弹窗有明确标题、关闭、取消和主要操作；真实客户端需要焦点约束与关闭后焦点归还。窄屏采用单列和换行页签，主要操作不被溢出隐藏；多列对照表可以局部横向滚动，但页面整体不得横向溢出。

### 9.4 结果比较

对照至少显示模型、版本、输入、种子、关键运行设置和结果。不同输入或不同量化方式需要醒目标记，不能显示为严格公平比较。图片比较保留尺寸和裁剪条件；音频比较可独立播放；视频比较保留帧率、时长和来源。

字幕、裁剪或其它人工修订保存为新的作品版本，并能查看原结果和差异。“本次提交时固定配置”只显示生成快照；编辑记录单列。载入生成配方不会把后续人工字幕当作原始模型输出。

## 10. 首次使用引导

首次打开给出三个可执行步骤：准备模型、检查设备、完成一个示例任务。用户可以跳过并浏览界面。示例任务必须标注示例数据和模拟／真实模式；真实模式缺少依赖时提示准备步骤。

正式首次使用验收从干净安装、没有模型或数据的状态开始，包含下载／准备失败后恢复、首次真实结果、保存和再次打开。操作全程提供界面入口；记录用户独立完成率、耗时与阻塞点，不以熟悉实现的开发人员能点通替代目标用户验收。

训练方法旁提供简短解释；上下文、KV、Prefill 等设置提供单位、影响和适用范围。详细技术资料放在帮助展开区，不能迫使用户阅读接口字段或环境命令才能完成基本操作。

## 11. 交互验收

交互验收不是“按钮能跳转”。必须从明确入口完成真实用户任务，验证最终结果、数据保存、来源链和再次打开。关键路径对应 [AC-01—AC-27](11-testing-and-acceptance.md)，原型与产品之间的差距见 [14](14-prototype-traceability.md)，本轮修改追踪见 [16](16-audit-remediation-plan.md)。
