# 开发路线、里程碑与资源计划

版本：1.1 · 日期：2026-09-09 · 状态：已按审计修订范围和阶段门槛；真实开发尚未开始，周期待技术试验后重估。

相关文档：[工作包](10-work-breakdown.md)、[测试门槛](11-testing-and-acceptance.md)、[风险与决策](13-decisions-risks-and-questions.md)、[审计整改计划](16-audit-remediation-plan.md)。

## 1. 实施顺序

先打通真实任务与数据保存，再扩展模型和硬件；先证明一个完整组合，再增加优化开关。四类工作台和现有辅助入口保持不变，后端按阶段接入。未接入功能显示实际状态，不把全部功能隐藏到一个无法评审的“未来版本”。

第一条真实路径选择语言模型推理及 SFT + LoRA 闭环。它覆盖项目、模型、数据、设备、执行、评测、产物、试用、配方、恢复，能够验证共用架构。同一份 LoRA 产物在目标试用设备加载的风险前移到 M0 技术试验，M3 再验证完整产品路径。随后扩展媒体、专项实验与多硬件，避免各模块各建一套任务系统。

本版纳入 AUD-01—AUD-14 的必要整改，并按最小范围采纳 E-01—E-05：首次用户路径、三类运行预设、跨端产物验证、结果修订版本、可复跑审计资产。当前修订只完成规范和计划，不代表原型问题已经修复或真实能力已经通过。

## 2. 资源假设

| 角色 | 建议投入 | 职责 |
| --- | --- | --- |
| 产品／交互 | 0.5 人 | 需求取舍、流程验收、文案与可用性 |
| 前端／桌面 | 1 人 | 页面、表单、桌面宿主、状态恢复 |
| 后端／平台 | 1 人 | 控制服务、元数据、文件、任务与远程执行 |
| ML 训练／推理 | 2 人 | 训练、推理、媒体、量化与适配验证 |
| 测试／质量 | 0.5—1 人 | 自动化、真实设备、回归、发布证据 |

估算基于约 5—5.5 人的持续投入，以及可用的 Apple Silicon、NVIDIA Linux 服务器和后续 AMD／Intel 测试设备。不是一个人执行的时间估算。没有设备、数据或适配器许可／版本验证时，相关阶段单独延期，不用模拟结果代替交付。

表内 19—28 周是 1.0 范围的顺序累计参考，保留用来识别范围变化，**不是 1.1 的交付承诺**。它原本假定每类只选最小组合、M5 明确裁剪、约 5—5.5 人持续投入，不含设备采购、上游阻塞、额外硬件／训练方法或本次补入工作的独立工时。新增的状态异常、只补收、导出器、负例、首次使用和跨端验证尚无实测人日，不把它们默认为零成本。

M0 退出时，按 30 个工作包的子项、设备可用性和验证成本重新估算阶段区间，给出新增范围差额、关键路径与可延后组合后再承诺日期。允许不相依模块有限交错，但必须保留退出条件。专项与硬件矩阵过大时，M5 拆为后续版本，已纳入的完整用户路径不能仅靠压缩测试来保持旧周期。

## 4. M0：形成可执行基线

### 先收敛文档合同

在技术试验前统一工作流身份、配置联动、任务控制异常、补收、监督配方、模型信任和导出归属；关系检查能发现错配与阶段倒挂。这里要求文档可据以实施，**不要求 M0 完成这些模块的产品后端**。原型 AUD-01—AUD-06 的实现修复归相应工作包，完成前保留已知问题标记。

### 交付物

- 首期模型：固定文本模型和 tokenizer revision；训练与推理使用可互相验证的源版本。
- 首期设备：具体 Apple 型号／内存、NVIDIA 型号／显存、系统和驱动。
- 桌面壳与 Python 侧进程启动、退出、崩溃、重启试验。
- TV-01：按精确模型、引擎和设备组合记录真实推理、最小训练与环境复现。
- TV-02：壳与侧进程在最小打包试验中的启停、崩溃、重启、路径和日志；不依赖项目数据库、正式签名或完整升级。
- TV-03：将 TV-01 产生的同一份实际 LoRA 产物，从 NVIDIA 训练环境带到指定 Apple 试用设备，固定基座 revision、模板、目标引擎并独立加载。若需格式转换，保存输入／输出摘要和转换步骤；命令行即可，尚不是产品闭环。
- 能力声明初版、提交快照 schema、任务状态机和存储布局。
- ADR 中需要拍板的选型结论与有证据的替代方案；1.1 范围重估表。

退出只要求 TV-01—TV-03 及上述文档记录。AC-01、AC-12、AC-22、AC-26 等是后续完整验收追踪，不能反过来阻塞 M0 试验工作包完成。跨端不可行时调整目标组合并重跑 TV-03；不能先标记支持再等待 M3 补证。

### 停止／调整条件

若目标模型无法加载、驱动不兼容或打包依赖无法稳定复现，先调整该组合，不继续在前端标记支持。若 Tauri 宿主延缓核心验证，可临时使用本地 Web 界面验证合同；桌面产品决策单独记录。

## 5. M1：应用和持久化基础

将最终 Demo 转为正式组件，保持四类入口、模型库、数据市场、实验室和 AI 面板。建立项目、任务、数据、模型和作品的数据库结构；支持安全的文件选择、导入、元信息和草稿保存。WP-04 在 M1 整理原型与测试的固定项目位置、清单、摘要和复跑命令，保留旧资产；M6 由 WP-30 验证新成员复跑。

实现任务状态、事件流、幂等提交和假执行器；覆盖暂停检查点失败、暂停时取消、取消／完成竞争、强制停止及停止状态未知。计算结果和收集记录分开，假执行器测试补收不触发 run／resume，原尝试终态不改。模型导入计划同时保存加载方式与信任类别，受限加载失败不得自动放宽执行能力。假执行器仅用于开发与测试，模式必须显式，不作为真实模型支持证据。

退出验收按 GATE-M1：杀掉控制服务后重启，草稿和索引仍在；开发用执行器状态可恢复，控制／补收合同负例通过；跨项目后台结果不串入当前项目；文件损坏与磁盘不足有可恢复处理。这里只验 M1 子集，不要求真实模型、训练候选、M4 媒体或 M6 安装升级已完成。

## 6. M2：真实推理与参数生效

先完成一个 Apple 本地文本推理适配器和一个 NVIDIA 服务推理适配器。实现模型准备、加载、卸载、输入处理、流式输出、取消、结果保存、实际参数记录和配方重载。

开放经过验证的思考开关、上下文、输出上限和采样参数；KV、前缀缓存和调度先选择少量可测组合。其余高级选项保留说明和未验证状态，不急于全部开放。模型／策略／引擎／产物格式改变时重新校验任务模式、素材和配套组件；提交端拒绝旧配置。参数摘要、按钮旁执行位置和发送范围统一来自本次已应用配置。

加入“模型默认、低内存、低延迟”三个可解释预设，绑定已经验证的组合；应用前展示实际字段差异，取消不改值，不宣称未经测量的收益。前缀缓存测试纳入媒体身份、顺序、处理器与预处理参数，未知组合保持关闭。首次使用引导在此形成可操作的语言试用路径。

退出验收按 GATE-M2：输入／输出 token 预算正确；界面、已应用配置、请求快照、后端实际参数和执行位置一致；配方／预设能说明失效项；断网本地推理、远端中断、取消后资源释放、只补收不重算通过。

## 7. M3：训练与评测闭环

实现 SFT + LoRA 的数据检查、版本化分词与监督配方、训练、检查点、恢复、独立评测、候选登记和直接试用。检查多轮、超长、空回答、EOS／PAD、packing 边界的最终 tokens／labels，统计有效监督 token 并拒绝零监督样本。增加 QLoRA 或全参数路径前，先锁定后端与硬件；不将“LoRA 能跑”视为其他更新方式已完成。

AI 辅助接入真实建议模型，但只开放已定义字段，完成预览、应用、撤销与冲突测试。首个内测版本在此阶段形成，范围限定于已经验收的语言任务和设备。

WP-29 的模型／适配器／文本作品／报告导出子项在 M3 交付，由后端与前端共同承担：选择对象、解析依赖、清单、完整性、落盘、取消／失败恢复和独立环境使用。这里不依赖 M6 安装更新工作。

退出验收按 GATE-M3：真实数据 → 权重更新 → 独立产物 → 评测 → 同份产物在目标设备试用及导出；失败重试保留原任务，收集失败只补收；检查点恢复有一致性记录；AI 无执行权。

## 8. M4：媒体和工作流

分别选一个图片生成／微调组合、一个短视频组合和一个能完成配音的 TTS 组合；ASR、变声和音乐按冻结矩阵追加。仅接入 ASR 不能满足三步工作流的配音出口。每类必须验证真实文件读取、真实产物和任务特有参数，不能用文本任务复制页面替代。

实现“商品图 → 视频 → 配音”的结果传递、旧结果失效标记、阶段重做和整体保存。每次执行、步骤尝试、输入版本独立编号；默认只能使用本轮当前步骤产物，显式复用旧产物必须记录来源。先校验目标占用，再原子提交推进；失败不改步骤、输出或源草稿，重复点击只推进一次。

WP-29 增加图片、视频、音频作品导出；人工字幕／转写修改写入 WorkRevision，保留原结果和生成配方，重新生成不隐含套用人工修订。数据市场至少接入一个可控来源，验证受限访问流程、版本、下载和原任务返回。

退出验收按 GATE-M4：两轮三步真实流程与目标忙碌反例通过；来源链、媒体导出和编辑差异完整；图像、视频、音频有对应报告；市场接口不可用时已下载数据仍可使用。

## 9. M5：专项和多硬件

按成熟度独立推进量化、转换、合并、蒸馏、行为调整。先选择较小模型和可重复评测集，明确每项的输入格式和产物，避免建立统一空壳后宣称全部完成。

AMD／ROCm、Intel／SYCL、OpenVINO／NPU、Core ML／ANE 逐条加入设备矩阵。MTP 与 DFlash 使用已配套的目标模型、组件和版本，完成优化开／关对照。Prefill／Decode 分离若不具备部署条件，作为独立延后工作包，不阻塞其他优化。

退出验收按 GATE-M5：每个开放组合都有支持范围、限制、测试样本和报告；Core ML 等转换候选从“候选 → 运行”入口选中可加载引擎，错误格式／引擎两个方向都拒绝；推测策略切换使不匹配准备状态失效；不能验证的组合保持未验证或不支持。

## 10. M6：稳定化与发布

冻结候选版本后执行干净机器安装、升级／回滚、数据库迁移、备份恢复、长任务、磁盘满和网络故障测试。真实模式中不存在预置成功报告、模拟连接捷径或伪造进度。

按实际支持矩阵编写用户手册和发行说明，附安装包身份、依赖版本、已知问题、恢复方法和兼容性清单。发布动作与准备发布包分别验收。GATE-M6 汇总冻结范围内 AC-01—AC-27；用同一候选包完成 5 名目标用户零资源到首次结果、升级后产物导出、跨端产物链和恢复回归。

审计资产按 E-05 纳入固定版本位置并提供清单、摘要和复跑命令，保留原资产；本次文档修订不能将仍可复现的 Demo 错误标记为产品修复完成。

## 11. 版本建议

| 版本 | 阶段门槛 | 范围 |
| --- | --- | --- |
| 技术预览 | M0—M2 的纵向验证完成 | 内部验证，不能称完整产品 |
| 私有 Alpha | M3 | 语言训练／试用闭环，限定硬件 |
| 功能 Beta | M4 + 选定 M5 工作包 | 媒体工作流、部分专项与扩展适配 |
| 首个正式版本 | M6，且目标矩阵全部有证据 | 按已验收范围发布，未完成项清楚列出 |

## 12. 依赖与关键路径

关键路径为：能力与快照合同 → 资产／数据库 → 任务执行与恢复 → 真实推理 → 训练与产物 → 独立评测 → 候选试用 → 发布验收。

可以交错推进的工作：数据导入器与前端表单、远程执行器与本地推理、媒体解码与专项模型来源核查。不能提前跳过的依赖：没有固定数据版本不能做公平评测；没有真实参数映射不能做优化测速；没有产物完整性不能登记候选；没有精确设备身份不能宣称 ANE／ROCm／oneAPI 通过。

## 13. 进度管理与变更控制

每周按工作包更新：已完成证据、进行中内容、阻塞、下周交付，不只报告百分比。每个阶段结束进行实际任务演示和测试报告评审。

新增模型或优化开关需要一张能力卡和相应测试成本。需求变更同时更新 PRD 编号、工作包、验收用例和支持矩阵；发现更简单且满足目标的实现可以调整方案，但不能删掉用户已经确定的完整流程。

## 14. 估算边界

本计划没有取得团队排班、设备预算或正式上线窗口。开始 M0 后用实际加载、训练、打包、跨端产物与测试结果重估，并对新增整改及增强逐项列出投入。未完成重估前，1.0 的 19—28 周只作历史比较。若由单人实施，不能直接沿用上面的日历周期；应缩减并行工作并以完整闭环为阶段单位逐次承诺。
