# 导出目录项完整性修复

按 AC-27 与运维规范检查导出恢复时，发现固定 Ver2.4（038）仍可能误接受含符号链接的包。本次已修复源码并完成相关回归；尚未编入新的签名候选，不能将源码通过计为包内或原生修复验收。038 的既有清单身份验收保留其原有范围，完整 M6、M0—M6 与发行仍未完成。

## 重现与原因

旧检查只枚举普通文件，因此忽略额外断链、目录符号链接和命名管道；读取清单时也没有拒绝清单文件本身的符号链接。真实文件与数据库停机重开测试中，这 4 种负例错误地恢复成功；合法完整包、普通空目录及已有的内容文件链接拒绝对照共 3 项通过。[修复前记录](../../.artifacts/export-tree-integrity-source-v1/red.log)

另在固定 038 的实际包内服务执行 HTTP 负例：只在新建测试库注入一次导出登记拒绝，正常停止后，将包内清单替换为指向测试目录中相同内容清单的链接，再重启核实。旧候选错误返回成功和可用路径，负例已保留。该故障是受控登记拒绝，不是操作系统进程崩溃；合成模型文件不可用于模型运行，也未操作原生界面。[包内负例](../../.artifacts/export-tree-integrity-source-v1/packaged038-negative-001/result.json)

## 最小修复与验证

核对过程改为先遍历全部目录项，不跟随符号链接，只允许普通文件与真实目录，再检查文件集合、清单身份和逐文件摘要。特殊目录项在读取清单前被拒绝；扫描错误仍保留为失败。合法目录继续允许，不修改原包、不重新复制或执行模型。该检查不宣称提供对同用户并发篡改的操作系统隔离。

7 项定向测试通过，覆盖清单链接、内容文件链接、断链、目录链接、命名管道、合法完整包及普通空目录。每项实际停机重开后核实，同幂等键返回原结果，文件与链接保持，任务及尝试数量不增。导出、备份恢复、作品修订与划分数据导出共 186 项回归通过，保留 2 项既有依赖警告。[定向结果](../../.artifacts/export-tree-integrity-source-v1/green.log) [整合回归](../../.artifacts/export-tree-integrity-source-v1/regression.log)

## 证据边界与后续

包内负例后，47 项原保护记录保持，所有本轮控制服务正常停止；没有模型执行，也未连接原用户库进行 SQL 查询。现有子代理因用量限制不可执行，主代理审查不计为独立审查。下一候选仍需公司签名构建、实际包内拒绝与合法恢复复验及对应原生验证；本记录不提高完整 AC27 或 M6 状态。
