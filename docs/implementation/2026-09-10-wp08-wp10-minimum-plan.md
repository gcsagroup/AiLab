## 3. 必须保留的协议语义

控制端分配稳定 `attempt_id` 与幂等键；远端用 `attempt_id + snapshot_sha256` 识别同一次计算，持久记录后才公开完整启动授权。回包丢失后先查询 attempt；同一编号不因为网络重试再次调用执行器。远端新进程启动、控制端连接和任务执行身份分开记录，PID 本身不能证明归属。

状态、事件和产物均通过登记目标访问。首期可选择 SSH 隧道承载回环 HTTP：宿主校验固定主机指纹，凭证由安全存储提供，命令以参数数组执行，禁止跳过主机身份检查。仅回环测试使用独立临时凭证和独立测试目录；这不替代正式 SSH／原生凭证路径。不得在错误、配方、日志、诊断或导出中写入密钥。

`connection_state` 与 `state` 分开；断连只表示最后状态待确认。取消请求没有停止证据时保留 `stop_status=unknown`，不能显示资源已释放或再次提交计算。远端事件序号单调递增，本地按远端实例、attempt 和序号去重，完成／取消竞争只裁决一次。

计算完成先封存只读 manifest，远端保留原文件，直到本地确认完整登记或用户按明确清单清理。收集只接受原 attempt、manifest 摘要和独立 collection 编号；不调用 run／resume、不改原摘要、不重写原终态。原文件缺失或损坏时返回缺失清单；不能改成重新生成来冒充补收成功。

输入准备和模型加载继续执行受限格式与信任检查。未知格式、自定义仓库代码或任意反序列化不进入首期默认路径；受限加载失败不能扩权重试。虚拟环境只固定依赖，不能作为文件、网络或凭证权限隔离的证明。

## 4. NVIDIA 的首个组合与完成边界

建议首个推理适配器采用固定 PyTorch／Transformers CUDA 组合，以一个明确的 safetensors 文本模型完成模型加载、流式生成、取消和卸载；选择理由是可以先复用受限权重及 tokenizer 校验，再将同一进程合同带到 CUDA。具体版本、模型 revision、GPU、系统与驱动必须在真实目标确定后共同锁定。此建议不表示已经选择 vLLM／SGLang，也不开放未经映射的 KV、并行或推测参数。

WP-10 首期完成条件是该固定 NVIDIA 组合的真实推理与服务生命周期通过 GATE-M2 子集。CPU 夹具成功、回环服务成功或 CUDA 探测成功，均不能单独完成 WP-10。TV-03 与 AC-26 还要求在 NVIDIA 上真实训练得到的一份 LoRA，经传输／必要转换后在指定 Apple 引擎独立加载；不得用已有 Apple 训练产物替代这条证据。

交付时至少保留两份报告：一份记录本机协议故障注入、原生目标选择及真实文件传输；另一份记录 NVIDIA 精确组合、固定输入、有效参数、产物 SHA、取消／重连／资源释放和必要的 LoRA 回程结果。任何缺失单列为待验，不以一个总体“远程通过”掩盖。
