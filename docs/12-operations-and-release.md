# 安装、运行维护与发布计划

版本：1.1 · 日期：2026-09-09 · 状态：已按审计修订的待实现运行规范；当前没有安装包、后台服务或生产部署。

相关文档：[开发路线](09-development-roadmap.md)、[任务合同](07-api-and-task-lifecycle.md)、[测试](11-testing-and-acceptance.md)。

## 1. 交付单元

区分桌面客户端、控制服务、执行器、环境包、模型文件、数据、作品和报告。应用升级不默认重下全部模型，也不自动升级正在使用的训练环境。

发布清单包含应用版本、提交哈希、构建平台、包摘要、签名身份、基础依赖、可选环境、数据库 schema、支持矩阵、已知问题和回滚说明。

## 2. 首次安装与环境准备

1. 安装应用，检查基本存储权限和可用空间。
2. 用户选择数据根目录与模型缓存位置。
3. 只读探测设备，显示真实型号、内存、驱动和可用后端。
4. 用户选择要准备的运行／训练环境，查看依赖来源、空间和操作范围。
5. 创建独立环境并执行最小自检；成功后登记环境摘要。
6. 准备模型，完成下载完整性和加载检查。
7. 执行一个真实示例任务，保存结果与配方。

首次使用验收 AC-25 从干净环境出发，允许在类别内直接试用，记录模型准备、设备检查、首次结果和退出后续做的完整路径。最近任务入口必须能找到生成与训练记录，不能只展示训练历史；五名目标用户的完成情况、耗时和阻塞作为可用性证据，不能用开发者熟练操作替代。（E-01）

没有驱动时说明需要的步骤；驱动安装、系统权限变更和远程服务部署不作为普通连接检查的一部分。用户取消准备后，现有环境和数据保持可用。

## 3. 运行模式

| 模式 | 网络与执行 | 展示规则 |
| --- | --- | --- |
| 演示模式 | 预置数据和模拟执行，无真实计算承诺 | 全局醒目标记，结果附演示来源 |
| 本地模式 | 本机已准备模型和执行环境 | 显示实际设备、参数和产物 |
| 远程模式 | 用户指定服务器或已配置云实例 | 提交前展示发送内容与目标 |

演示与真实数据目录分开，不能在同一任务中混用模拟指标和真实指标。生产发布包可以保留演示体验，但必须有清晰模式边界，模拟成功记录不得进入正式支持报告。

## 4. 日常运行与资源管理

模型实例按模型版本、适配器、引擎、精度和加载参数标识。复用条件一致才共享；否则新建实例或明确卸载重载。用户可以查看驻留模型、占用来源和正在使用的任务。

关窗、退出应用和停止执行器分别定义：关窗可以保留后台任务；退出前显示本地运行任务处理选项；远程任务即使控制端退出也应可在重开后重新连接。没有远端持久执行能力时必须提示其限制。

## 5. 日志与指标

日志分应用、控制服务、执行器、任务四层，统一 task_id／attempt_id／environment_id。用户界面显示阶段和中文摘要，可展开原始技术错误。

默认日志不保存完整数据集、明文凭证或无关文件内容。任务输入与输出作为项目资产保存，访问与清理遵循项目规则。诊断导出先生成可预览清单，用户选择范围后再导出。

指标需要声明来源与采集间隔。无法从系统或引擎读取的 GPU／ANE 使用率、缓存命中率或推理分段耗时显示未测，不从进度条反推指标。

## 6. 常见故障处理

| 故障 | 自动处理 | 用户可选操作 | 必须保留 |
| --- | --- | --- | --- |
| 模型下载中断 | 保存下载游标和已校验块 | 续传、重新下载、取消 | 来源 revision、临时文件状态 |
| 文件校验失败 | 隔离不完整文件，不登记成功 | 删除该临时下载并重试 | 校验摘要和错误 |
| 设备连接中断 | 限定频率重连和状态查询 | 修改连接、等待、取消本地等待 | 已知 attempt_id 和事件游标 |
| OOM | 记录错误并释放可释放资源 | 减小参数，新建尝试或恢复 | 原参数、日志、可用检查点 |
| 磁盘满／产物传输或登记失败 | 封存原 manifest，标记收集失败并保留计算结果 | 恢复空间／连接后只补收，或另建明确的计算重试草稿 | 原尝试终态、原产物摘要、收集记录和未完成标记 |
| 引擎进程崩溃 | 控制服务保持可用 | 查看日志、重试、新环境 | 退出信息和快照 |
| 暂停检查点失败 | 查询执行器是继续计算、异常退出还是未知，按状态合同反馈 | 查看失败原因、取消、已支持的强制停止；确认仍运行时可稍后再暂停 | 原控制命令、检查点完整性、执行证据 |
| 取消超时／停止结果未知 | 保留 cancelling，继续有限状态查询，不能显示已停止 | 等待、查看远端任务、已支持的强制停止 | 任务归属、进程树证据、最后确认状态 |
| 数据库迁移失败 | 停止新版本写入，保留备份 | 回滚应用／恢复数据库 | 旧库、迁移版本和日志 |
| 评测失败 | 保留候选研究记录，禁止准入 | 查看样例、调整后新建实验 | 固定评测规则和逐样本结果 |

不得通过自动反复重跑昂贵训练掩盖故障，也不得清理用户原始数据来“自动修复”磁盘问题。

### 6.1 计算结束后的补收（AUD-08）

计算完成与作品／模型可用是两个检查点。远端执行器封存完整 manifest 并保留文件后，传输、校验或本地登记失败可使用 [07 的 collections 接口](07-api-and-task-lifecycle.md) 补收；恢复操作只读取原文件，不再加载模型计算。清单缺失、源文件损坏或保留期已过时显示不可补收与缺失项，不能以重新训练代替这次操作。

收集记录单独保存失败、重试、取消和成功；原 failed／cancelled 尝试及原因不变。补收成功后显示“计算完成，产物已补收”，保留原失败／取消提示，逐文件摘要和登记结果可查。候选仍须独立加载和评测；已失败的旧评测不会自动变为通过。验收注入磁盘满、断传和登记事务失败，确认恢复前后计算启动次数不增加，资产只登记一次。

## 7. 备份与恢复

备份范围：元数据库一致快照、资产 manifest、需要保留的模型／数据／作品、任务快照、环境锁文件、检查点和报告。凭证只保留重新连接说明或安全存储引用，不导出明文。

推荐允许用户选择完整备份或元数据／配方备份。后者必须说明大文件缺失时需要重新获取，不能声称可离线恢复所有产物。

恢复先校验 schema 与文件摘要，创建新恢复目录，验证后再切换当前工作区。恢复失败不覆盖仍可使用的原工作区。每次正式发布前至少进行一次从实际备份恢复代表项目的演练。

## 8. 清理与空间治理

按类别展示空间：模型、数据原件、处理版本、检查点、作品、运行缓存、下载临时文件和日志。先列出路径、大小、引用与原因，再执行用户选择的清理。

优先可恢复方式。存在引用的文件不能因为“很久没打开”就删除；训练检查点若被恢复任务引用必须保留。清理完成后验证索引、引用和剩余空间，必要时允许撤销。

卸载客户端默认不删除用户数据根目录。删除模型、移除模型条目、清理引擎缓存是不同动作，文案要说明实际影响。

## 9. 更新与回滚

应用更新先检查是否存在本地任务和数据库迁移。需要中断时让用户选择合适时机，不能在训练过程中自动重启侧进程。下载的新包校验摘要与签名，再切换版本。

数据库迁移采用版本化脚本和备份；不可逆迁移需要保留旧应用能够读取的备份副本。环境升级以新环境并存方式进行，旧任务仍可找到原依赖。模型更新产生新 ModelVersion，不能更改已有版本的文件。

回滚后验证项目列表、任务快照、产物读取和新任务执行。应用回滚成功不等于所有训练环境都回滚成功，报告要分开。

## 10. 导出与对外发布

### 10.1 用户产物导出器的范围（AUD-13）

普通产物导出由 WP-29 明确负责：M3 交付模型／适配器／文本作品／报告的基础导出，M4 扩展图片／视频／音频及字幕修订版本，M6 汇总四类对象在安装包和独立环境中的 AC-27 验收。M5 新增转换格式由 WP-24 提供产物与兼容条件，交给已有导出器并扩展对应验收；WP-24 不代替通用导出器。诊断包属于日志排障，不能当作模型和作品导出交付。

| 导出对象 | 包含内容与依赖 | 独立使用验证 |
| --- | --- | --- |
| 完整模型／运行模型 | 固定权重或转换产物、配置、所需 tokenizer／processor／模板、来源和兼容组合 | 在声明的独立环境加载并跑固定样例，不能依赖原应用的未声明缓存 |
| 适配器 | 适配器文件、目标模块／参数、固定基座 revision 与摘要、模板及必要处理器 | 用声明基座加载该适配器；基座可选内含或外部依赖，但必须明确列出获取与校验方式 |
| 作品 | 用户选定的原版或 WorkRevision、媒体文件／文本、生成配方、来源与修订记录 | 文本可读，图片可解码，视频／音频可独立播放，字幕时间与媒体匹配 |
| 评测报告 | 基线与候选引用、固定数据／规则版本、汇总及已选择的逐样本结果、产物摘要 | 能从包内报告追踪结论来源；未包含的原始样本与模型标为外部依赖，不伪称完整重评测包 |

字幕修订与生成配方分别导出，清单固定作品版本；选择“原输出”不会带上后来的人工校正，选择“修订版”仍保留修订来源。已有报告不可因导出更改阈值或结论。（E-04）

### 10.2 计划、落盘与失败恢复

1. 用户选择对象、固定版本、目标格式与目录；格式转换需要先完成独立转换任务。解析内含文件和外部依赖，显示清单、预计空间、来源材料及兼容条件。
2. `/exports/prepare` 生成不可变 ExportPlan 和摘要；缺少应内含文件、未完成资产、不可读版本或未明确处理的依赖阻断计划。外部基座已明确列出时可以导出适配器，但界面必须说明需要基座才能使用。
3. 用户执行计划时复核源摘要、空间、目标目录与计划未变；创建 kind=export 的独立任务尝试，使用同一文件系统内的临时目录，不覆盖现有完整导出包。
4. 写入选定文件、`manifest.json`、配方、来源／修订记录、必要说明和逐文件校验值。manifest 包含 schema、对象版本、相对路径、大小、摘要、内含／外部依赖和兼容条件，禁止绝对私有路径、明文凭证及越界符号链接混入。
5. 完成文件摘要、清单引用和可读性检查后，才原子改名为正式导出目录并记录完成；独立加载／播放结果另记为使用验证，文件完整与使用验证分别展示。宣称“可独立使用”必须已有对应验证证据，尚未验证显示未验证。
6. 磁盘满、传输中断、源文件变化、用户取消或校验失败保留明确临时状态和错误，不产生可误认为完整的包。重试只重做导出打包或从已验证文件续写，不重训／重生成；源摘要变化必须重新准备计划。

相同幂等键返回同一导出任务，重复点击不多次打包。取消与完成沿用任务状态合同，已原子登记成功的包返回已完成；取消先提交则临时文件不发布为完整包。清理残留临时目录前展示其关联任务、大小和可恢复性。AC-27 包含四类代表对象、缺文件、外部基座、字幕版本、取消、磁盘满与独立环境使用，结果保留具体文件和摘要。

### 10.3 对外发布

对外上传、模型仓库发布、服务器部署和创建云资源均为独立动作，不由导出按钮自动触发。

发布前记录分发依赖与模型／数据材料范围；只列出实际可核查材料，不由 AI 生成授权结论。当前文档不包含特定法律结论，也不把来源说明替代用户的实际发布决定。

## 11. 发布验收清单

| 类别 | 必需证据 |
| --- | --- |
| 身份 | 安装包版本、摘要、签名、构建来源与提交一致 |
| 安装 | 干净机器安装、首次启动、基础环境检查 |
| 主流程 | 已声明范围的真实训练／推理／评测／保存闭环 |
| 数据 | 历史项目升级、备份恢复、引用完整 |
| 导出 | WP-29 普通产物导出四类对象及独立使用检查，完整性和外部依赖明确；诊断包单独验收 |
| 设备 | 发布矩阵内每个组合都有对应报告 |
| 参数 | 公开控件都有实际映射和必要测试 |
| 故障 | 暂停失败、取消竞争、停止未知、断连、OOM、磁盘满、进程崩溃与只补收可解释和恢复 |
| AI | 无自主执行、建议冲突处理、发送范围明确 |
| 外观 | 中文、键盘、深浅色和代表窗口宽度检查 |
| 文档 | 用户指南、支持范围、已知问题、回滚方法 |

任何数据丢失、错误项目归属、参数被静默忽略、虚假成功或凭证泄露问题都阻断发布。未验证硬件不应列为已支持。
