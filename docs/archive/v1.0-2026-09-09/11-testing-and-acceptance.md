# 测试策略与验收标准

版本：1.0 · 日期：2026-09-09 · 状态：原型测试已复跑；真实产品测试为待执行计划。

相关文档：[需求](01-product-requirements.md)、[工作包](10-work-breakdown.md)、[发布](12-operations-and-release.md)、[原型证据](14-prototype-traceability.md)。

## 1. 证据层级

| 层级 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 文档与静态检查 | 需求、链接、示例与字段一致 | 应用实际可运行 |
| 原型状态测试 | 模拟状态、部分校验和交互意图 | 真实执行、持久化与性能 |
| 单元／合同测试 | 规则、接口、状态、参数映射 | 实际驱动、模型加载或最终体验 |
| 集成测试 | 数据库、进程、文件、服务交互 | 所有硬件与模型通用支持 |
| 实机测试 | 指定组合的真实执行和指标 | 未测试版本和其他设备 |
| 用户端到端验收 | 真实入口到最终产物的完整任务 | 对外发布、升级等未执行流程 |
| 发布验收 | 具体安装包和支持矩阵可交付 | 未来版本自动继承通过 |

测试报告必须标明层级、输入、环境、版本、执行时间、结果与限制。原型测试和模拟执行不得进入真实性能统计。

## 3. 测试环境与数据

### 3.1 最小设备池

- 一台明确型号与统一内存大小的 Apple Silicon Mac。
- 一台明确 GPU、显存、系统和驱动版本的 NVIDIA Linux 机器。
- M5 扩展时提供明确型号的 AMD GPU 和 Intel GPU／NPU 设备。
- 一台干净安装／升级测试环境；可使用独立用户账户或虚拟机，但 GPU 功能验收必须有实际适用设备。

每次报告保存 CPU、GPU／NPU、内存、系统、驱动、引擎、模型、精度、存储、网络和电源状态。设备不可用时标记未测，不以其他厂商机器代替。

### 3.2 数据夹具

准备小型可公开文本、图像、短视频和音频样例，并附来源记录。正常数据与负例分别管理，负例包含缺字段、损坏文件、空内容、重复、过长输入、越界切片、错采样率、变帧率和模型不兼容。

功能性小样本用于检查链路，质量评测集用于检查效果，二者分开。不得把训练中使用的样本直接当独立测试集。近重复分组信息与划分种子固定保存。

## 4. 核心验收用例

### AC-01：项目与草稿持久化

前置：两个项目，各有语言和图片草稿。操作：编辑、切换项目、关闭应用、重启。预期：任务编号、字段、选中对象和历史按项目恢复；后台结果归属原项目。证据：数据库记录、应用操作录像或截图、相关事件。覆盖 PRD-001、PRD-018。

### AC-02：四类入口与继续任务

从首页逐类进入，恢复草稿、新建任务、查看运行和评测，再返回首页。预期：入口清楚、状态按钮指向下一步，无重复训练入口或错误类别。不能只检查路由存在。覆盖 PRD-002、PRD-020。

### AC-03：模型准备与独立加载

使用固定模型 revision，下载、暂停／恢复（支持时）、取消、重试，并加入一个损坏文件。预期：完整性失败不能显示准备成功；完成后独立进程可加载；适配器需要基座时能指出依赖。覆盖 PRD-003。

### AC-04：数据导入、检查与版本

导入正常 JSONL 与四类负例，检查行号、媒体、重复和划分。应用排除／重采样后验证原件哈希不变，新版本可追溯；数据改变使旧检查失效。覆盖 PRD-004。

### AC-05：市场访问与返回原任务

从已有训练草稿进入市场，分别完成开放下载、受限申请、拒绝、通过、下载和选择数据。预期：错误 schema 不能使用；返回后原名称、参数、项目和步骤保留；访问获准不出现授权代判标签。覆盖 PRD-005。

### AC-06：训练方法与更新方式

对每个开放组合运行最小真实训练，至少包含首期 SFT + LoRA。验证目标模块、数据 schema、优化步数与权重变化；不支持的 QLoRA／精度／设备组合由服务端拒绝。新增方法逐项增加用例。覆盖 PRD-006。

### AC-07：任务生命周期

覆盖排队、准备、运行、取消、失败、检查点、可用时暂停／恢复。预期：没有确认就不显示终态；失败重试产生新尝试；旧日志保留；恢复不是仅加载权重后伪称继续原轨迹。覆盖 PRD-007。

### AC-08：真实运行与结果

文字生成、图像生成、视频生成、TTS／ASR 等按已开放能力实际执行。预期：输入被使用，输出文件可独立读取，最终结果和历史一致；不能用预置图或音频作为真实产物。覆盖 PRD-008。

### AC-09：运行参数真正生效

测试关闭思考、上下文、输出限制、采样、停止词与流式。比较请求配置、后端实际参数和观察结果；超预算拒绝／裁剪符合用户选择。修改弹窗取消后原值不变；运行中不能修改快照。覆盖 PRD-009。

### AC-10：缓存、Prefill 与 Decode

固定模型和输入，验证缓存隔离、失效、KV dtype、分块、批处理、并发和 CUDA Graph。引擎不支持字段时拒绝，不能丢参。分离部署缺连接器时阻断；实现后注入传输和模型版本错配。覆盖 PRD-010。

### AC-11：推测解码配对

分别测试普通草稿、MTP、DFlash 的正常和不匹配输入。MTP 缺组件拒绝；DFlash 目标、草稿、模板或思考条件错配拒绝；配套准备后测正确性、接受率和延迟。覆盖 PRD-011。

### AC-12：设备与引擎适配

逐个登记真实设备，验证可达、探测、依赖、加载和运行状态分离。NVIDIA、Apple、AMD、Intel、CPU 分别保存报告；同品牌不同系统不自动继承支持。覆盖 PRD-012。

### AC-13：媒体参数与 Core ML／ANE

图片检查调度器、CFG、VAE 与卸载；视频检查帧率、帧数、时长与切片；音频检查采样率、切片、流式块和转写。Core ML 原始权重错配拒绝，转换产物独立执行；只有具备分配证据才声明 ANE 使用。覆盖 PRD-008、PRD-012、PRD-013。

### AC-14：评测与候选准入

基线和候选使用固定数据与规则，注入一个不达标候选和一个损坏产物。预期：不能登记为可用模型；通过候选可独立加载试用，来源实验可返回；重复登记幂等。覆盖 PRD-014。

### AC-15：AI 建议模式

检查建议生成不修改、应用只改白名单、过期 revision 拒绝、撤销不覆盖后改、提交后只读、恶意材料无执行权。核对远程请求范围与来源问题回答边界。覆盖 PRD-017。

### AC-16：作品、配方与来源

保存产物后关闭应用，重新打开并载入配方；切换模型版本／设备后检查差异提示。预期：输入、产物、基座／适配器、参数和来源都可找到；收藏与文件保存不混淆。覆盖 PRD-016。

### AC-17：完整媒体工作流

真实完成图片 → 视频 → 配音，并在中间注入失败。预期：前序结果保留，重做后旧下游有来源版本提示，最终全部产物可独立打开。若没有合成能力，不得称为最终成片。覆盖 PRD-015。

### AC-18：故障与恢复

在运行、写文件、提交事务、事件发送等阶段终止进程，模拟磁盘满和远端断开。重启后无重复执行、不丢已提交记录、不把部分文件标完整；任务状态未知时进行重连核对。覆盖 PRD-018。

### AC-19：模型实验室

对合并、蒸馏、量化、转换和行为对照逐项执行。检查输入兼容、候选独立、产物哈希、质量回归和来源链。自研未实现入口不可启动。覆盖 PRD-013。

### AC-20：幂等与竞争

双击提交、相同幂等键重发、不同内容复用幂等键、取消与完成竞争、AI 与手工编辑竞争、重复终态事件。预期：合法单次执行、明确冲突、数据库与界面一致。覆盖 PRD-007、PRD-018。

### AC-21：远程执行与输入边界

测试远端身份不符、凭证失效、上传中断、相同文件去重、运行断连、日志补拉。预期：不静默发送到其他地址，不在未知状态重复启动，诊断数据无明文密钥。覆盖 PRD-012、PRD-018。

### AC-22：安装、升级、备份与导出

在干净环境安装具体候选包，升级含历史任务的旧版本，回滚一次失败迁移，并恢复备份。导出后用独立进程加载文件。预期：身份和数据一致，不将卸载等同删除模型数据。覆盖 PRD-018、PRD-019。

### AC-23：界面、键盘与外观

检查 1024、736、360 px 深浅色、最小 320 px，表单标签、焦点、弹窗、错误关联、长名称、中文路径、空态和大列表。用键盘完成一条任务；不能以静态截图代替关键交互。覆盖 PRD-002、PRD-020。

### AC-24：性能与质量对照

对每个宣传的优化执行关闭／开启对照，固定负载、精度和环境，记录冷／热、并发、内存与质量。结果包含无收益或变慢情况，不筛选最好样本作为普遍结论。覆盖 PRD-010、PRD-011、PRD-012。

## 5. 性能测试方法

### 5.1 基准条件

每个配置至少包含短、中、长输入和单请求／多请求两组负载。正式输入长度由参考模型能力决定，并记录精确 token 数。冷加载与热运行分开；稳定性测试至少 30 个固定请求，必要时重复 3 轮；首轮编译和模型下载单独计时。

采样参数、输出长度限制、停止条件、种子、缓存命中条件和并发必须相同。比较不同量化或不同精度时明确它们改变了计算条件，并同时报告质量。

### 5.2 指标口径

| 指标 | 口径 |
| --- | --- |
| 端到端延迟 | 客户端提交到最终结果完成；包含传输和排队 |
| 首 token 延迟 | 提交到首个输出 token；单独注明是否包含模型加载 |
| Prefill 速度 | 输入 token 数／实际 Prefill 时长；仅引擎能明确归因时报告 |
| Decode 速度 | 首 token 之后的生成 token 数／对应生成时长；1 token 输出不计算 |
| 总吞吐 | 测试窗口实际完成 token 或请求数／窗口时长 |
| 峰值内存 | 测量工具记录的峰值；显存／统一内存／进程内存分别列出 |
| 缓存命中 | 引擎实际命中统计；没有观测接口则标未知 |
| 草稿接受率 | 被接受的草稿 token／提出的草稿 token，口径与引擎报告对应 |
| 质量变化 | 固定样本与规则下的候选和基线差异 |

不以字符数直接冒充 token 数，不以第一段响应提前返回证明完整推理更快，不以单次最好结果替代中位数和 p95。

## 6. 训练质量验收

功能验收与模型质量验收分别报告。功能验收要求参数更新、检查点完整、可恢复、产物可加载；质量验收要求固定业务／回归样本、合理阈值、样本量与人工评审。

阈值在测试前确定，按任务分别制定。无法统一自动评分时保留逐样本结果和评审说明，不用一个无来源分数掩盖差异。损失下降、奖励升高不单独构成通过。

## 7. 自动化分层

- 单元层：参数 schema、版本、数据划分、状态转移、建议应用和缓存键。
- 合同层：请求／响应、错误代码、幂等、事件顺序、执行器能力。
- 集成层：真实 SQLite、临时目录、进程、文件校验和受控远程服务。
- 模型层：小模型／小样本真实运行，检查权重和输出，不使用大模型占满常规 CI。
- 设备层：带标签的专用机器执行已安排矩阵，产物与报告关联提交版本。
- 端到端层：浏览器／桌面真实操作完成用户路径。

## 8. 缺陷等级与放行

| 等级 | 示例 | 放行原则 |
| --- | --- | --- |
| 阻断 | 数据丢失、重复昂贵执行、错误项目归属、虚假成功、凭证泄露 | 本版本不得发布 |
| 高 | 主流程无法完成、参数被忽略、候选准入绕过、取消不生效却显示成功 | 必须修复并复测 |
| 中 | 明确的非主路径错误、可绕过但影响使用的交互问题 | 评估范围与公开限制，通常修复 |
| 低 | 非关键文案、局部间距、辅助信息不清楚 | 记录并纳入后续修正 |

不支持某硬件不是缺陷，错误宣称支持或允许不可执行组合才是缺陷。未测能力在发布矩阵中保持未测，不能通过关闭测试消除失败记录。

## 9. 阶段门槛

M1 通过持久化与任务合同；M2 通过真实推理和参数；M3 通过训练到候选闭环；M4 通过媒体和市场；M5 对每个新增组合独立验收；M6 通过安装、升级、恢复和完整回归。每阶段保留已失败案例作为后续回归输入。

## 10. 报告模板

每份报告必须包含：报告编号、对应需求／工作包、代码提交、应用包身份、模型和数据版本、环境摘要、操作步骤、预期结果、实际结果、日志／产物引用、通过／失败／未测、限制和复测结果。

发布验收必须使用将要交付的同一个安装包与运行依赖。重新打包、更改签名、驱动或模型版本后，相关验收失效并按影响范围复测。
