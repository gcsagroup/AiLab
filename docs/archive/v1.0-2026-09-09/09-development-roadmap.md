# 开发路线、里程碑与资源计划

版本：1.0 · 日期：2026-09-09 · 状态：基于最终 Demo 的建议排期；尚未开工、没有实际交付日期。

相关文档：[工作包](10-work-breakdown.md)、[测试门槛](11-testing-and-acceptance.md)、[风险与决策](13-decisions-risks-and-questions.md)。

## 1. 实施顺序

先打通真实任务与数据保存，再扩展模型和硬件；先证明一个完整组合，再增加优化开关。四类工作台和现有辅助入口保持不变，后端按阶段接入。未接入功能显示实际状态，不把全部功能隐藏到一个无法评审的“未来版本”。

第一条真实路径选择语言模型推理及 SFT + LoRA 闭环。它覆盖项目、模型、数据、设备、执行、评测、产物、试用、配方、恢复，能够验证共用架构。随后扩展媒体、专项实验与多硬件，避免各模块各建一套任务系统。

## 2. 资源假设

| 角色 | 建议投入 | 职责 |
| --- | --- | --- |
| 产品／交互 | 0.5 人 | 需求取舍、流程验收、文案与可用性 |
| 前端／桌面 | 1 人 | 页面、表单、桌面宿主、状态恢复 |
| 后端／平台 | 1 人 | 控制服务、元数据、文件、任务与远程执行 |
| ML 训练／推理 | 2 人 | 训练、推理、媒体、量化与适配验证 |
| 测试／质量 | 0.5—1 人 | 自动化、真实设备、回归、发布证据 |

估算基于约 5—5.5 人的持续投入，以及可用的 Apple Silicon、NVIDIA Linux 服务器和后续 AMD／Intel 测试设备。不是一个人执行的时间估算。没有设备、数据或适配器许可／版本验证时，相关阶段单独延期，不用模拟结果代替交付。

## 3. 阶段总览

| 阶段 | 建议周期 | 主要目标 | 进入条件 | 退出条件 |
| --- | --- | --- | --- | --- |
| M0 范围与技术验证 | 1—2 周 | 冻结首期组合、打包与执行器最小验证 | 本套文档可评审 | 选型记录、模型与设备清单、最小实机报告 |
| M1 应用与数据基础 | 2—3 周 | 原型产品化、项目／资产／任务持久化 | M0 合同与存储方向确定 | 草稿恢复、导入、队列与事件合同通过 |
| M2 真实推理与运行配置 | 3—4 周 | Apple 本地与 NVIDIA 服务推理、真实参数 | M1 基础可用 | 真实输出、参数回读、配方重载和取消通过 |
| M3 训练与评测闭环 | 3—4 周 | SFT + LoRA、检查点、评测、候选试用 | M1 数据和任务；M2 试用 | 数据到候选完整实机链路 |
| M4 媒体与数据市场 | 4—6 周 | 图像／视频／音频最小组合与工作流 | 共用任务、产物、评测稳定 | 四类至少一个真实组合，市场返回路径通过 |
| M5 专项实验与高级适配 | 4—6 周 | 蒸馏等专项、多硬件、缓存调度／推测优化 | 有基线模型、评测集与设备 | 每项独立报告，未达标组合关闭 |
| M6 发布与稳定化 | 2—3 周 | 安装、升级、恢复、性能、文档和发布包 | 目标功能矩阵明确 | 发布验收清单完整，演示路径与生产隔离 |

顺序累计约 19—28 周，不含设备采购、较大上游阻塞或需求变更。允许不相依的模块有限交错，但必须保留退出条件，不通过重叠排期把真实工作量压缩成不可信日期。专项与硬件矩阵很大时，M5 可拆成多个后续版本，不强行塞入同一发布窗口。

## 4. M0：形成可执行基线

### 交付物

- 首期模型：固定文本模型和 tokenizer revision；训练与推理使用可互相验证的源版本。
- 首期设备：具体 Apple 型号／内存、NVIDIA 型号／显存、系统和驱动。
- 桌面壳与 Python 侧进程启动、退出、崩溃、重启试验。
- 一条真实推理和一条最小训练命令的运行记录；这里只用于验证选型，尚不是产品闭环。
- 能力声明初版、提交快照 schema、任务状态机和存储布局。
- ADR 中需要拍板的选型结论与有证据的替代方案。

### 停止／调整条件

若目标模型无法加载、驱动不兼容或打包依赖无法稳定复现，先调整该组合，不继续在前端标记支持。若 Tauri 宿主延缓核心验证，可临时使用本地 Web 界面验证合同；桌面产品决策单独记录。

## 5. M1：应用和持久化基础

将最终 Demo 转为正式组件，保持四类入口、模型库、数据市场、实验室和 AI 面板。建立项目、任务、数据、模型和作品的数据库结构；支持安全的文件选择、导入、元信息和草稿保存。

实现任务状态、事件流、幂等提交和假执行器。假执行器仅用于开发与测试，模式必须显式，不作为真实模型支持证据。

退出验收：杀掉控制服务后重启，草稿和索引仍在；长任务状态可恢复；错误能定位；跨项目后台结果不串入当前项目；文件损坏与磁盘不足有可恢复处理。

## 6. M2：真实推理与参数生效

先完成一个 Apple 本地文本推理适配器和一个 NVIDIA 服务推理适配器。实现模型准备、加载、卸载、输入处理、流式输出、取消、结果保存、实际参数记录和配方重载。

开放经过验证的思考开关、上下文、输出上限和采样参数；KV、前缀缓存和调度先选择少量可测组合。其余高级选项保留说明和未验证状态，不急于全部开放。

退出验收：输入／输出 token 预算正确；后端确实采用配置；配方重载能说明环境差异；断网本地推理、远端中断、取消后资源释放通过。

## 7. M3：训练与评测闭环

实现 SFT + LoRA 的数据检查、训练、检查点、恢复、独立评测、候选登记和直接试用。增加 QLoRA 或全参数路径前，先锁定后端与硬件；不将“LoRA 能跑”视为其他更新方式已完成。

AI 辅助接入真实建议模型，但只开放已定义字段，完成预览、应用、撤销与冲突测试。首个内测版本在此阶段形成，范围限定于已经验收的语言任务和设备。

退出验收：真实数据 → 权重更新 → 独立产物 → 评测 → 候选试用；失败重试保留原任务；从检查点恢复有一致性记录；AI 无执行权。

## 8. M4：媒体和工作流

分别选一个图片生成／微调组合、一个短视频组合、一个语音或 ASR 组合，再逐步加入其他音频任务。每类必须验证真实文件读取、真实产物和任务特有参数，不能用文本任务复制页面替代。

实现“商品图 → 视频 → 配音”的结果传递、旧结果失效标记、阶段重做和整体保存。数据市场至少接入一个可控来源，验证受限访问流程、版本、下载和原任务返回。

退出验收：三步真实产物来源完整；图像、视频、音频指标与人工检查有对应报告；市场接口不可用时已下载数据仍可使用。

## 9. M5：专项和多硬件

按成熟度独立推进量化、转换、合并、蒸馏、行为调整。先选择较小模型和可重复评测集，明确每项的输入格式和产物，避免建立统一空壳后宣称全部完成。

AMD／ROCm、Intel／SYCL、OpenVINO／NPU、Core ML／ANE 逐条加入设备矩阵。MTP 与 DFlash 使用已配套的目标模型、组件和版本，完成优化开／关对照。Prefill／Decode 分离若不具备部署条件，作为独立延后工作包，不阻塞其他优化。

退出验收：每个对外开放组合都有支持范围、限制、测试样本和报告；不能验证的组合保持未验证或不支持。

## 10. M6：稳定化与发布

冻结候选版本后执行干净机器安装、升级／回滚、数据库迁移、备份恢复、长任务、磁盘满和网络故障测试。真实模式中不存在预置成功报告、模拟连接捷径或伪造进度。

按实际支持矩阵编写用户手册和发行说明，附安装包身份、依赖版本、已知问题、恢复方法和兼容性清单。发布动作与准备发布包分别验收。

## 11. 版本建议

| 版本 | 阶段门槛 | 范围 |
| --- | --- | --- |
| 技术预览 | M0—M2 的纵向验证完成 | 内部验证，不能称完整产品 |
| 私有 Alpha | M3 | 语言训练／试用闭环，限定硬件 |
| 功能 Beta | M4 + 选定 M5 工作包 | 媒体工作流、部分专项与扩展适配 |
| 首个正式版本 | M6，且目标矩阵全部有证据 | 按已验收范围发布，未完成项清楚列出 |

## 12. 依赖与关键路径

关键路径为：能力与快照合同 → 资产／数据库 → 任务执行与恢复 → 真实推理 → 训练与产物 → 独立评测 → 候选试用 → 发布验收。

可以交错推进的工作：数据导入器与前端表单、远程执行器与本地推理、媒体解码与专项模型来源核查。不能提前跳过的依赖：没有固定数据版本不能做公平评测；没有真实参数映射不能做优化测速；没有产物完整性不能登记候选；没有精确设备身份不能宣称 ANE／ROCm／oneAPI 通过。

## 13. 进度管理与变更控制

每周按工作包更新：已完成证据、进行中内容、阻塞、下周交付，不只报告百分比。每个阶段结束进行实际任务演示和测试报告评审。

新增模型或优化开关需要一张能力卡和相应测试成本。需求变更同时更新 PRD 编号、工作包、验收用例和支持矩阵；发现更简单且满足目标的实现可以调整方案，但不能删掉用户已经确定的完整流程。

## 14. 估算边界

本计划没有取得团队排班、设备预算或正式上线窗口。开始 M0 后用实际加载、训练、打包和测试结果重估。若由单人实施，不能直接沿用上面的日历周期；应缩减并行工作并以完整闭环为阶段单位逐次承诺。
