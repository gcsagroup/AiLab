## 3. 文档工具的代表性测试

**21 项测试全部通过。** 正常基线和新加一份合法文档应通过；其余反例应被拒绝并给出对应错误。所有变更只发生在临时副本，测试前后核对原始文档摘要不变。

- 保留编号但把 WP-14 改成错误需求／验收关系，必须报错。
- 修改 M1 周期却保留旧累计数字，必须报错；M0 误用最终 AC 也必须报错。
- 缺失整改映射、普通导出被诊断包替代、缺少直接需求覆盖、虚构产品已修状态，必须报错。
- 依赖成环、引用不存在子项、早期任务依赖后期任务、复合依赖未指明子交付，必须报错。
- 断链、越界行号、坏 JSON、表格列数、未闭合代码块和归档被修改，必须报错。

这补上原 AUD-14 中“编号齐全但关系错误”“周期改变但检查仍通过”的盲区。工具报告规则一致性；正式变更仍需人工复核语义，不能用多张表同步写错来替代产品判断。

## 4. 合同与计划交叉复核

本轮复核了以下跨文档关系，修订目标均有工作包与验收承接：

- 工作流执行、步骤与输入版本绑定；目标占用与推进原子处理；旧结果只经明确操作复用。
- 模型、任务模式、输入媒体、产物格式、引擎和推测组件联动失效；显示位置与实际提交配置同源。
- 暂停失败、暂停中取消、取消中崩溃和收集阶段取消有明确处理；状态未知不得伪报已停止。
- 计算结果、尝试终态和独立补收记录分开；补收不得重算，原失败／取消事实与旧评测保留。
- SFT 的分词／模板／监督范围、EOS／PAD、截断与拼接版本固定；有效 labels 是训练前检查对象。
- 模型导入识别实际加载方式与信任类别，不因受限加载失败自动降级为执行未知代码。
- 作品人工修订保留独立版本；普通产物导出与诊断包分别实施和验收。
- M0 技术试验不依赖 M3 训练产品或 M6 发布；同份 LoRA 跨端试验、首次用户流程和正式导出有独立验收。
