# 测试策略与验收标准

版本：1.1 · 日期：2026-09-09 · 状态：已按审计补充反例、技术试验和分阶段验收；真实产品测试仍为待执行计划。

相关文档：[需求](01-product-requirements.md)、[工作包](10-work-breakdown.md)、[发布](12-operations-and-release.md)、[原型证据](14-prototype-traceability.md)、[整改追踪](16-audit-remediation-plan.md)。

## 1. 证据层级

| 层级 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 文档与静态检查 | 链接、示例和编号结构；可解析关系、阶段依赖及指定负例 | 应用实际可运行、全部自然语言语义正确 |
| 原型状态测试 | 模拟状态、部分校验和交互意图 | 真实执行、持久化与性能 |
| 单元／合同测试 | 规则、接口、状态、参数映射 | 实际驱动、模型加载或最终体验 |
| 集成测试 | 数据库、进程、文件、服务交互 | 所有硬件与模型通用支持 |
| 实机测试 | 指定组合的真实执行和指标 | 未测试版本和其他设备 |
| 用户端到端验收 | 真实入口到最终产物的完整任务 | 对外发布、升级等未执行流程 |
| 发布验收 | 具体安装包和支持矩阵可交付 | 未来版本自动继承通过 |

测试报告必须标明层级、输入、环境、版本、执行时间、结果与限制。原型测试和模拟执行不得进入真实性能统计。

## 2. 已有基线

1.0 文档验证曾运行原型 `test-ailab-unified.cjs`，输出 42 组代表性验证通过；运行 `test-ailab-runtime.cjs`，输出 17 组运行优化专项验证通过。原型脚本语法、HTML 片段结构与小于 1 MB 的检查通过。

上述 59 组是原型脚本报告的测试分组，并非 59 个真实模型／硬件组合。随后审计在原测试通过时仍复现 AUD-01—AUD-06 的行为错误，另发现 E-04 的结果配方语义问题。审计脚本断言通过代表成功复现问题，不代表产品已修复。

1.1 文档修订的实际执行结果见 [验证报告](validation-report.md)；本文新增 TV、GATE 和 AC 是待执行验收合同，不能因文档检查通过而标记产品验收通过。

## 3. 测试环境与数据

### 3.1 最小设备池

- 一台明确型号与统一内存大小的 Apple Silicon Mac。
- 一台明确 GPU、显存、系统和驱动版本的 NVIDIA Linux 机器。
- M5 扩展时提供明确型号的 AMD GPU 和 Intel GPU／NPU 设备。
- 一台干净安装／升级测试环境；可使用独立用户账户或虚拟机，但 GPU 功能验收必须有实际适用设备。

每次报告保存 CPU、GPU／NPU、内存、系统、驱动、引擎、模型、精度、存储、网络和电源状态。设备不可用时标记未测，不以其他厂商机器代替。

### 3.2 数据夹具

准备小型可公开文本、图像、短视频和音频样例，并附来源记录。正常数据与负例分别管理，负例包含缺字段、损坏文件、空内容、重复、过长输入、越界切片、错采样率、变帧率和模型不兼容。

功能性小样本用于检查链路，质量评测集用于检查效果，二者分开。不得把训练中使用的样本直接当独立测试集。近重复分组信息与划分种子固定保存。

## 4. 核心验收用例

### AC-01：项目与草稿持久化

前置：两个项目，各有语言和图片草稿。操作：编辑、切换项目、关闭应用、重启。预期：任务编号、字段、选中对象和历史按项目恢复；后台结果归属原项目。证据：数据库记录、应用操作录像或截图、相关事件。覆盖 PRD-001、PRD-018。

### AC-02：四类入口与继续任务

从首页逐类进入，恢复草稿、新建任务、查看运行和评测，再返回首页。预期：入口清楚、状态按钮指向下一步，无重复训练入口或错误类别。不能只检查路由存在。覆盖 PRD-002、PRD-020。

### AC-03：模型准备、信任与独立加载

使用固定模型 revision，下载、暂停／恢复（支持时）、取消、重试，并加入损坏文件、格式伪装、受限加载失败、不受信任 pickle／检查点、TorchScript 和需要自定义代码的模型。核对 ModelImportPlan 中声明的格式、加载方式、信任类别、依赖及隔离边界。预期：完整性通过不能替代信任判断；受限加载失败不得自动降级为任意反序列化；需要执行能力时按明确决定限制文件、网络、凭证，隔离效果有记录。完成后在独立进程按声明加载方式加载，适配器缺基座时指出具体依赖。使用无害受控夹具测试，不执行来源未知的恶意模型。覆盖 PRD-003。对应 AUD-11。

### AC-04：数据导入、检查与监督配方

导入正常 JSONL 与四类负例，检查行号、媒体、重复和划分；应用排除／重采样后原件摘要不变，新版本可追溯。对多轮、超长回答、空回答、仅系统消息、padding、packing 边界和多模态样本输出最终 tokens／labels，核对 tokenizer／processor／模板、assistant-only 或 completion-only、EOS／PAD、截断和边界策略。预期：有效监督 token、截断和丢弃样本统计可解释；零监督样本必须排除，训练集或必需验证集过滤后无有效监督则阻断任务；数据或监督配方版本改变使旧检查失效。覆盖 PRD-004。对应 AUD-10。

### AC-05：市场访问与返回原任务

从已有训练草稿进入市场，分别完成开放下载、受限申请、拒绝、通过、下载和选择数据。预期：错误 schema 不能使用；返回后原名称、参数、项目和步骤保留；访问获准不出现授权代判标签。覆盖 PRD-005。

### AC-06：训练方法、更新方式与监督目标

对每个开放组合运行最小真实训练，至少包含首期 SFT + LoRA。验证目标模块、数据 schema、监督配方、最终 tokens／labels、优化步数和权重变化；对支持同一配方的适配器核对监督范围等价，不依赖各库默认值。模型／任务模式变化使不兼容训练输入或旧检查失效；服务端拒绝伪造模式、不支持的 QLoRA／精度／设备与零有效监督数据。新增训练方法逐项增加用例。覆盖 PRD-006。对应 AUD-04、AUD-10。

### AC-07：任务生命周期与异常出口

逐行执行 [07 状态表](07-api-and-task-lifecycle.md)，覆盖排队、准备、运行、收集、取消、失败、检查点及可用时暂停／恢复。注入暂停检查点失败、pausing 时取消、cancelling 时执行器崩溃、finalizing 时取消收集、控制超时和强制停止失败；核对状态、允许动作、错误、恢复入口与事件。停止证据缺失时 `stop_status=unknown`，界面不能宣称已停止或可安全重开。失败重试建立新计算尝试，旧记录保留；恢复包含已约定的训练状态，不能仅加载权重后伪称原轨迹继续。覆盖 PRD-007。对应 AUD-07、AUD-08。

### AC-08：真实运行、模型模式与结果

文字生成、图像生成、视频生成、TTS／ASR 按已开放能力实际执行。测试音频能力模型切到纯视觉模型及反向切换，带图片／视频／录音时分别换模型；界面选择值、已应用模式、媒体输入与提交快照一致，不兼容项明确重置并说明，伪造旧模式请求由服务端拒绝。真实输入必须被使用，输出文件能独立读取，最终结果与历史一致，不能以预置媒体替代真实产物。覆盖 PRD-008。对应 AUD-04。

### AC-09：运行参数、执行位置与预设

测试关闭思考、上下文、输出限制、采样、停止词和流式，比较界面、已应用配置、请求快照、后端实际参数及观察结果；超预算拒绝／裁剪符合用户选择。覆盖默认本机／本次云端、默认云端／本次本机与配方重载，按钮旁位置、参数摘要和发送范围都来自本次已应用配置。逐一使用“模型默认、低内存、低延迟”预设，应用前可看实际字段差异，取消不变；换模型／设备后失效值与需重载项有说明，未经测量不宣称加速。运行中不能修改快照。覆盖 PRD-009。对应 AUD-06、E-02。

### AC-10：缓存、Prefill 与 Decode

固定模型与输入，验证缓存隔离、失效、KV dtype、分块、批处理、并发和 CUDA Graph。相同文字换图片／视频／音频，或相同媒体改变顺序、裁剪、抽帧、采样、processor 版本时不得错误命中；保存媒体内容或编码摘要、处理器与预处理参数的身份条件。委托底层缓存时验证适配器实际保证这些条件，不增加弱化的应用层缓存；未知组合关闭。引擎不支持字段时拒绝，不能丢参。分离部署缺连接器时阻断；实现后注入传输和模型版本错配。覆盖 PRD-010。对应 AUD-09。

### AC-11：推测解码配对

分别测试普通草稿、MTP、DFlash 正常和不匹配输入，覆盖普通草稿与 DFlash 双向切换、准备前后换模型／引擎／模板／思考条件、直接提交旧配置。准备状态属于目标模型、策略、组件和引擎的确定组合，失配后清除并阻断准备／应用／提交；不能继承一个独立 `draftReady` 布尔值。MTP 缺组件、DFlash 配套错配均拒绝；正确组合测正确性、接受率和延迟。覆盖 PRD-011。对应 AUD-03。

### AC-12：设备与引擎适配

逐个登记真实设备，验证可达、探测、依赖、加载和运行状态分离。NVIDIA、Apple、AMD、Intel、CPU 分别保存报告；同品牌不同系统不自动继承支持。覆盖 PRD-012。

### AC-13：媒体参数与 Core ML／ANE

图片检查调度器、CFG、VAE 和卸载；视频检查帧率、帧数、时长与切片；音频检查采样率、切片、流式块和转写。从转换候选的“运行”入口走完默认配置与加载链，格式参与引擎选择，来源配置失效时不能继承；原始权重→不支持的 Core ML 引擎、Core ML 产物→不支持该格式的 PyTorch 路径两个方向都拒绝。桥接转换须作为显式准备步骤并留摘要链。只有具备实际分配证据才声明 ANE 使用。覆盖 PRD-008、PRD-012、PRD-013。对应 AUD-05。

### AC-14：评测与候选准入

基线和候选使用固定数据与规则，注入一个不达标候选和一个损坏产物。预期：不能登记为可用模型；通过候选可独立加载试用，来源实验可返回；重复登记幂等。覆盖 PRD-014。

### AC-15：AI 建议模式

检查建议生成不修改、应用只改白名单、过期 revision 拒绝、撤销不覆盖后改、提交后只读、恶意材料无执行权。核对远程请求范围与来源问题回答边界。覆盖 PRD-017。

### AC-16：作品、生成配方与结果修订

保存产物后关闭应用，重新打开并载入配方，换模型版本／设备后检查差异提示。输入、产物、基座／适配器、参数和来源均可找到；收藏与文件保存不混淆。编辑转写／字幕产生 WorkRevision，可查看原文、修订、父版本与差异；job.snapshot、原生成配方和原输出保持不变。重新生成只复用生成参数，不隐含带入人工修订；导出能明确选择原版或修订版。覆盖 PRD-016。对应 E-04。

### AC-17：完整媒体工作流与原子推进

真实执行两轮图片 → 视频 → 配音，保存 WorkflowRun id／revision、step attempt 和 input revision。第二轮修改输入后零次生成，默认不得用上一轮结果推进；显式复用须由用户选择并记录源执行／产物，修改上游使旧下游标记失效。

分别在目标类别运行中、暂停中、恰好完成、恰好取消时推进。目标占用检查失败，步骤、输出集合与源草稿均不变；查看阻塞任务、等待或退出可用，解除阻塞后一次点击只推进一次。注入中途失败并重做，前序产物保留、输入与来源版本完整，最终媒体独立可打开。没有合成能力不得称最终成片。覆盖 PRD-015。对应 AUD-01、AUD-02。

### AC-18：故障恢复与只补收

在运行、写文件、提交事务和事件发送时终止进程，模拟磁盘满与远端断开。重启后无重复计算、不丢已提交记录、不把部分文件标完整；任务状态未知时重连核对。另在计算完成、远端产物完整后注入本地磁盘满、传输中断、资产登记事务失败，通过 `POST /attempts/{id}/collections` 只补收：复用原 manifest，`run`／`resume` 调用次数不增加，文件摘要相同，资产只登记一次。原 RunAttempt 的失败终态和计算结果保留，新 collection 记录恢复经过与状态，不能伪装为重新计算成功。覆盖 PRD-018。对应 AUD-07、AUD-08。

### AC-19：模型实验室与转换候选试用

对已开放合并、蒸馏、量化、转换和行为对照逐项执行，检查输入兼容、候选独立、产物摘要、质量回归和来源链。转换候选从实际入口选择与格式匹配的引擎再独立运行；原引擎不兼容时必须失效，正反两类格式错配与缺桥接步骤均阻断。导出转换产物由 WP-29 的通用导出器承接，转换测试不替代导出验收。自研未实现入口不可启动。覆盖 PRD-013。对应 AUD-05。

### AC-20：幂等与竞争

覆盖双击提交、同幂等键重发、不同内容复用键、过期状态版本、暂停／取消／恢复／force-stop 重发、取消与完成竞争、AI 与手工编辑竞争、重复终态和断连事件补拉。工作流推进与目标占用变化、重复 advance、旧输入 revision 也必须原子裁决。预期：合法单次执行，旧请求明确冲突，失败事务不留下半推进，数据库与界面一致；停止确认未知不能裁决为已停止。补收重复请求只产生约定收集记录及一次资产登记。覆盖 PRD-007、PRD-015、PRD-018。对应 AUD-02、AUD-07、AUD-08。

### AC-21：远程执行、目的地与输入边界

测试远端身份不符、凭证失效、上传中断、相同文件去重、运行断连和日志补拉。默认本机／单次云端、默认云端／单次本机、配方重载时，摘要、按钮旁位置、发送范围和实际目的地一致，不静默改地址。上传和模型加载遵守已决定信任范围；受限加载失败不扩大执行权限。取消后失联保留停止结果未知，不重复启动；计算已完成而收集失败时只补传校验登记，不重新计算。诊断数据无明文密钥。覆盖 PRD-012、PRD-018。对应 AUD-06、AUD-08、AUD-11。

### AC-22：安装、升级、备份与导出回归

在干净环境安装具体候选包，升级含历史任务的旧版本，回滚一次失败迁移并恢复备份；核对安装身份、依赖版本、旧任务与原产物。升级／恢复后按 AC-27 重新导出并独立验证文件，诊断包另行验证脱敏；卸载不等同删除模型数据。此前 M3／M4 的导出子项通过不代表候选包升级验收已通过；本用例不作为 M0 壳侧进程试验前置。覆盖 PRD-018、PRD-019。对应 AUD-12、AUD-13。

### AC-23：界面、键盘与外观

检查 1024、736、360 px 深浅色、最小 320 px，表单标签、焦点、弹窗、错误关联、长名称、中文路径、空态和大列表。用键盘完成一条任务；不能以静态截图代替关键交互。另从固定项目位置按清单核验确认版本的 Demo、测试和检查器摘要，新成员按复跑说明可打开相同界面、运行指定检查并理解已知问题；M1 整理资产，M6 使用新成员视角验证，历史文件保留。覆盖 PRD-002、PRD-020。对应 E-05。

### AC-24：性能与质量对照

对每个宣传的优化执行关闭／开启对照，固定负载、精度和环境，记录冷／热、并发、内存与质量。结果包含无收益或变慢情况，不筛选最好样本作为普遍结论。覆盖 PRD-010、PRD-011、PRD-012。

### AC-25：首次用户零资源到首次结果

由 5 名目标用户分别使用干净安装、没有预置模型／项目／数据／历史的环境，从首页选择类别内“直接试用”，完成创建项目、选择首期支持模型、准备依赖、检查设备、输入样例、生成首次真实结果、保存并在重启后继续。允许产品内帮助，不依赖开发文档或开发者代填步骤。记录每人的成功／失败、阻塞、人工帮助、耗时与产物；5 人均能完成且无阻断问题才通过，小样本结果不外推为全部用户可用性结论。断网或资源不足应有可理解的恢复入口，不能用预置资源伪称零资源路径。完整验收使用 M6 候选包，M2 只做首条已接入语言路径的阶段预演。覆盖 PRD-002、PRD-020。对应 E-01。

### AC-26：同一 LoRA 产物跨端试用

在指定 NVIDIA 训练组合完成真实 SFT + LoRA，经评测登记后，将同一份适配器送至指定 Apple 目标引擎试用；记录基座 revision、目标模块、适配器摘要、tokenizer／模板、精度、引擎和硬件。无转换时摘要保持相同；必须转换时保留输入／输出摘要及可复跑转换链，不能另训一个相似模型代替。通过产品候选入口和独立加载分别验证指定样例，对照无适配器／有适配器结果及预先确定的兼容、质量标准；从导出包恢复链路也可复现。错误基座、缺依赖、错格式和不匹配模块必须阻断。M0 的 TV-03 只证明所选技术路径，本用例在 M3 完整产品链路首次执行，M6 对冻结发布组合回归。覆盖 PRD-006、PRD-008、PRD-012、PRD-014、PRD-019。对应 E-03。

### AC-27：模型、适配器、作品与报告导出

每类各选真实对象：模型、LoRA 适配器、图片／视频／音频作品、评测报告，从普通用户入口选择范围／版本与目标路径，检查依赖解析、manifest、摘要、完整落盘和独立使用。适配器包记录精确基座依赖与缺失提示，不默认包含无权分发的基座；媒体独立打开，修订版与原生成配方可区分；报告能追踪模型、数据、评测规则和结果。

注入缺文件、磁盘满、取消、摘要不符与中断恢复：临时／部分包不显示成功，完整性通过后才发布最终包；恢复不触发训练或推理重算，源资产不变。M3 验模型／适配器／文本作品／报告，M4 增加媒体，M5 增加本版转换格式，M6 在升级／恢复后的同一候选包回归全部适用对象。诊断包不能替代本用例。覆盖 PRD-019。对应 AUD-13、E-04。

## 5. 性能测试方法

### 5.1 基准条件

每个配置至少包含短、中、长输入和单请求／多请求两组负载。正式输入长度由参考模型能力决定，并记录精确 token 数。冷加载与热运行分开；稳定性测试至少 30 个固定请求，必要时重复 3 轮；首轮编译和模型下载单独计时。

采样参数、输出长度限制、停止条件、种子、缓存命中条件和并发必须相同。比较不同量化或不同精度时明确它们改变了计算条件，并同时报告质量。

### 5.2 指标口径

| 指标 | 口径 |
| --- | --- |
| 端到端延迟 | 客户端提交到最终结果完成；包含传输和排队 |
| 首 token 延迟 | 提交到首个输出 token；单独注明是否包含模型加载 |
| Prefill 速度 | 输入 token 数／实际 Prefill 时长；仅引擎能明确归因时报告 |
| Decode 速度 | 首 token 之后的生成 token 数／对应生成时长；1 token 输出不计算 |
| 总吞吐 | 测试窗口实际完成 token 或请求数／窗口时长 |
| 峰值内存 | 测量工具记录的峰值；显存／统一内存／进程内存分别列出 |
| 缓存命中 | 引擎实际命中统计；没有观测接口则标未知 |
| 草稿接受率 | 被接受的草稿 token／提出的草稿 token，口径与引擎报告对应 |
| 质量变化 | 固定样本与规则下的候选和基线差异 |

不以字符数直接冒充 token 数，不以第一段响应提前返回证明完整推理更快，不以单次最好结果替代中位数和 p95。

## 6. 训练质量验收

功能验收与模型质量验收分别报告。功能验收要求参数更新、检查点完整、可恢复、产物可加载；质量验收要求固定业务／回归样本、合理阈值、样本量与人工评审。

阈值在测试前确定，按任务分别制定。无法统一自动评分时保留逐样本结果和评审说明，不用一个无来源分数掩盖差异。损失下降、奖励升高不单独构成通过。

## 7. 自动化分层

- 文档层：解析实际 PRD → 工作包 → AC 关系、交付对象、阶段与子项依赖、参考周期和审计映射；结构检查与自然语言内容审查分别报告。
- 单元层：参数 schema、版本、数据划分、监督 tokens／labels、状态转移、WorkflowRun 身份与输入版本、建议应用和含媒体身份的缓存键。
- 合同层：请求／响应、错误代码、幂等、事件顺序、执行器能力。
- 集成层：真实 SQLite、临时目录、进程、文件校验和受控远程服务。
- 模型层：小模型／小样本真实运行，检查权重和输出，不使用大模型占满常规 CI。
- 设备层：带标签的专用机器执行已安排矩阵，产物与报告关联提交版本。
- 端到端层：浏览器／桌面真实操作完成用户路径。

## 8. 缺陷等级与放行

| 等级 | 示例 | 放行原则 |
| --- | --- | --- |
| 阻断 | 数据丢失、重复昂贵执行、错误项目归属、虚假成功、凭证泄露 | 本版本不得发布 |
| 高 | 主流程无法完成、参数被忽略、候选准入绕过、取消不生效却显示成功 | 必须修复并复测 |
| 中 | 明确的非主路径错误、可绕过但影响使用的交互问题 | 评估范围与公开限制，通常修复 |
| 低 | 非关键文案、局部间距、辅助信息不清楚 | 记录并纳入后续修正 |

不支持某硬件不是缺陷，错误宣称支持或允许不可执行组合才是缺陷。未测能力在发布矩阵中保持未测，不能通过关闭测试消除失败记录。
