## Root Cause and Next-step Boundaries

Read-only source inspection shows that the locked rfd uses NSOpenPanel without disabling default alias resolution. This is a mechanism consistent with the observed path mismatch, not a direct observation of panel internals. The observed fact is that confirmation displays the base Python path before host business-layer saving. Existing helper tests inject a symbolic-link PathBuf directly, proving only that the business layer preserves the supplied path; they do not pass through the real native panel. The minimal change to disable panel resolution has not been implemented. Even if subsequent code or property checks pass, the next candidate must verify the POSIX symbolic-link path through actual selection, without reconstructing the expected path to manufacture a result. [Root cause and evidence](../../../../.artifacts/native-picker-scope-ver2-4-next-v1/python-picker-alias-root-cause.md)

This run cannot close acceptance for saving/reopening/restoring all three environments, diagnostic-directory export, native cross-library races, or full AC. The specified NVIDIA device and same-LoRA return path, existing quality failures, human media review, clean installation, five first-time users, notarization, and release gates remain open.
