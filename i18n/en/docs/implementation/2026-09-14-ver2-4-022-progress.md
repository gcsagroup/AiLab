## E117: Focus Fix and Signed Candidate

Before the fix, focus fell to the page body after starting editing by keyboard, continuing review, or cancelling. Pressing Escape while editing long subtitles displayed a confirmation outside the viewport, with focus still in the original input. The fix is limited to the manual-revision component: starting editing focuses the first control; confirmation scrolls into view and focuses “Continue Reviewing”; continuing returns to the original input if still usable; cancelling returns to the Edit button. After saving or refreshing, focus waits until busy state ends before moving to a usable control. Request, idempotency, and parent-version rules remain unchanged. A separate loopback service, PID 30114, has been running since September 10 using an independent directory. At inventory time, all 3 execution records had completed successfully, with no nonterminal run or direct child process, but the service itself had not been terminated. It is valid only to say that this round’s fixed App and bundled control process stopped, not all product-related processes.
