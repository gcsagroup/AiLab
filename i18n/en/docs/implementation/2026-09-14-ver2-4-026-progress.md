# Ver2.4（026）Execution Progress

When manual revision is first opened, the close button is disabled during reading. The Safari comparison confirmed that focus can consequently fall to the page background and fail to return when reading finishes. This round remedies that local behavior while preserving focus on an already usable control. The company-signed 026 candidate at the fixed path has been accepted. The limited subset covering focus after initial content readiness, closing and reopening, reading saved subtitles, and exit protection in the same package has also been accepted.

## Startup Metrics and Remaining Scope

Startup measurement definition: the 3-second target in 1.1 means the main window’s “first visibility” in an installed environment with a normal data volume, verified through 20 independent cold starts, excluding the initial model download. Full readiness is a separate observation. A single 024/025 full-readiness run exceeding 3 seconds cannot directly be judged an initial-display failure. The 011 initial-display result of 20/20 and the old full-readiness variability records are retained separately. This round has no new 20-run initial-display acceptance. [Original requirements, line 118](../01-product-requirements.md)

The full-readiness phase measurements for 023/024/025 remain useful for diagnosing waits. A single run for each version cannot prove a stable benefit or explain the old 011 long tail of 45 seconds. This round fixes initial-read focus only and does not change startup-readiness conditions or performance code.

E125’s source failure, E126’s valid restoration, and E127’s limited focus return remain in [025 historical progress](2026-09-14-ver2-4-025-progress.md). The old 020 blank-window issue, complete keyboard coverage, designated NVIDIA environment, cross-host operation, five first-time users, clean installation, quality and existing model budgets, notarization, and full AC/M0—M6 status remain unchanged.
