## Manual Collection Recovery

When the original attempt was already failed/cancelled with successful computation, manual collection committed collecting before copying or registration. A real SIGKILL then left the terminal attempt skipped by old startup recovery, still collecting and unable to retry after reopening. The 4 original failures across copy/registration and both terminal states, plus 2 already-committed passes, remain preserved. The first fixed run, including the existing 6 local and 3 remote cases, passed 15 tests. [Original failures](../../../../.artifacts/m1-exit-audit-ver2-4-033-v1/recollection-red.log), [initial regression](../../../../.artifacts/m1-exit-audit-ver2-4-033-v1/recollection-green.log)

After startup acquires the exclusive library lock, recovery handles only the unique active collection matching attempt/project/manifest. It records `COLLECTION_INTERRUPTED`, increments collection version and event state, and preserves the original terminal state/version/reason/time, computation manifest, and registered results. It does not automatically run/resume/collect. Remote tasks already in local registration are included without remote access or changes to remote computation. Mismatched ownership/manifests and ambiguous active records are not guessed.

The expanded recovery set passed 11 tests, including restart after both registration and compensation writes failed and storage became writable again, local registration with remote identity, and ownership safeguards. Two wrong_project setup errors first violated a foreign key and then used an invalid project resource. The final fixture uses the production project-creation interface; both failures are retained as test setup errors rather than product defects. Recovery transactions still require writable storage and do not promise recovery from permanent storage damage. ## Lifecycle Boundaries

When computation finishes first, unconfirmed pause/resume commands resolve to `not_applicable`/`COMPUTE_COMPLETED`. Failure finalization persists the actual `process.poll` exit code and time. If sending a stop signal raises `OSError`, cancelling and unknown remain, the command fails, the device stays busy, and a new idempotency key may retry. Signal failure is not reported as successful cancellation or process exit.

The original lifecycle set had 8 tests: 5 passed and 3 failed. The fixed lifecycle cases together with 11 recovery and 14 checkpoint tests passed 33 tests in 6.47 seconds. These use deterministic state contracts, temporary libraries/files, and explicit fixture processes, not native App or real-model acceptance.
