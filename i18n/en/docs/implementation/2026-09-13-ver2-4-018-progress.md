## E110: Fix and Verification

Real React components with a fixed transport fixture reproduced this behavior: when a control POST arrived late, the original implementation could continue GET requests against the new library after library identity changed and invoke the old callback. Three save-operation types also lacked completion-time protection. This round changes only RunResult to check library identity and component lifecycle, preserving polling, request contents, and idempotency keys. The first version incorrectly dropped success notifications after same-library unmount, leaving the Works list stale when navigating there during a save. After a real App-component negative case failed, the second version restored same-library success refresh while still rejecting subsequent GET requests, old state, and parent callbacks across libraries. [Source acceptance](../../../../.artifacts/library-stale-response-ver2-4-017-v1/root-source-acceptance.json), [Original failure](../../../../.artifacts/library-stale-response-ver2-4-017-v1/red-001/execution.json), [Same-library navigation negative case](../../../../.artifacts/library-stale-response-ver2-4-017-v1/red-002/execution.json)

All 48 tests in two core files, 35 directly related regressions in five files, and TypeScript checking passed. Four original expectations of “never notify the parent after unmount” were corrected based on the business negative case, and a cross-library zero-callback comparison was added. The first version’s seven passes and all failure originals are retained. These 83 tests are not described as a whole-project regression suite. [Regression result](../../../../.artifacts/library-stale-response-ver2-4-017-v1/green-002/result.json), [First-version result](../../../../.artifacts/library-stale-response-ver2-4-017-v1/green-001/targeted-execution.json)

The normal same-library case added A GET and one call to each of the two parent callbacks. 12 AX records and 3 viewport screenshots are retained; request counts rely on the complete AX. The development fixture uses fixed transport data and does not connect to a real library. [Browser originals](../../../../.artifacts/library-stale-response-ver2-4-017-v1/browser-001/root-browser-001/ui-records.json), [Independent review](../../../../.artifacts/library-stale-response-ver2-4-017-v1/browser-independent-review-001/REVIEW.md)
