# M4 local media executor experiments

This is the entry point for real-model evidence from the independent CLIs and media execution bridge. Images use Tiny-SD + UNet LoRA; video uses SVD image-to-video; TTS is recorded by independent `tts_*` executors. The bridge provides fixed-parameter checking, provenance binding, real events, cancellation, and artifact sealing. Control-service and UI media paths are recorded through separate product acceptance. CLI or bridge success is not `GATE-M4` acceptance.

<a id="冻结组合与证据"></a>

## Frozen combinations and evidence

| Item | Fixed selection | Current boundary |
| --- | --- | --- |
| Image base | `segmind/tiny-sd`, revision `cad0bd7495fa6c4bcca01b19a723dc91627fe84f` | Approximately 1.062 GB from the official source; validate restricted reading before safetensors conversion; load only standard Diffusers classes |
| Image inference | PyTorch 2.14.0 / Diffusers 0.35.2 / Python 3.13 / MPS FP32 | 512×512, 20 sampling steps, CFG 7.5, fixed CPU random generator; no MPS operator fallback |
| Image training | PEFT 0.18.1, UNet attention LoRA | rank/alpha 4, 12 steps, batch size 1, AdamW 1e-4; VAE/CLIP/base frozen; epsilon denoising supervision |
| Image data | 4 product-teapot images generated by this base | Explicitly marked synthetic, not external corpus data; does not establish business-data rights or improved style quality |
| Short-video base | `stabilityai/stable-video-diffusion-img2vid`, revision `9cf024d5bfa8f56622af86c884f26a52f6676f2e` | 3 fp16 safetensors weights totaling 4,509,185,018 bytes; public download without login |
| Short-video experiment | Same Diffusers/PyTorch environment, MPS FP16 | 1024×576, 14 frames, 7 FPS, 25 steps; real image conditioning; independent FFmpeg decoding; video training is unimplemented |

Every execution creates an independent output directory. Generation saves PNGs and floating-point pixels, actual parameters, loading/generation timings, process identity, dependency versions, and file digests. Image training records per-step loss/gradients, actual trainable tensors, weight changes, frozen-parameter digests before/after, and an independent safetensors LoRA. Memory records process peak RSS separately from MPS driver allocation at exit. The current MPS interface has no independent peak reading; the exit value must not be presented as peak device memory.

## Rerunning

Run from the project root. All weights and dependencies are under `.artifacts/m4-media`; `~/Models` is not read and existing text-executor environments are not modified.

```sh
/opt/homebrew/bin/python3.13 -m venv .artifacts/m4-media/venv
.artifacts/m4-media/venv/bin/python -m pip install \
  --no-index --find-links .artifacts/m4-media/wheels/pytorch-official \
  --find-links .artifacts/m4-media/wheels/resolved \
  --require-hashes -r adapters/media/requirements.lock.txt

# 来源 API 必须对应冻结 revision；若 main 已改变，取固定版本 API，不篡改 SHA。
.artifacts/m4-media/venv/bin/python adapters/media/prepare_tiny_sd.py \
  --root .artifacts/m4-media/model --api .artifacts/m4-media/sources/tiny-sd-api.json
.artifacts/m4-media/venv/bin/python adapters/media/run_image_acceptance.py \
  --root .artifacts/m4-media --run-name acceptance-next

.artifacts/m4-media/venv/bin/python adapters/media/prepare_svd.py \
  --root .artifacts/m4-media/svd-model --api .artifacts/m4-media/sources/svd-api.json
.artifacts/m4-media/venv/bin/python adapters/media/video_cli.py \
  --model-root .artifacts/m4-media/svd-model \
  --input .artifacts/m4-media/acceptance-v2/base-blue_cup/image.png \
  --output .artifacts/m4-media/video-acceptance-next

/opt/homebrew/bin/python3.13 -m unittest discover -s tests/media -v
```

Scripts refuse to overwrite an existing acceptance directory. Choose a new evidence root when rerunning, or invoke `image_cli.py generate/train` individually with new output directories. Do not delete old evidence and then claim a first-time pass. `run_image_acceptance.py` freezes training seeds and two independent evaluation examples before generation. The candidate is reloaded in another process, with a maximum same-seed floating-point pixel error of `1e-5`. Pixel changes establish that the adapter takes effect, not a quality-improvement score.

The installation command above uses the local wheel archive actually verified in this run. The lock is specific to macOS arm64 / Python 3.13. Torch came from the official PyTorch index; same-version PyPI files have different digests and cannot be mixed. Original index/download-source snapshots are under `sources`; the actual installation log is `logs/install-local-verified.log`. Complete image acceptance is currently `acceptance-v2`; `acceptance-v1` preserves the first JSON-writing failure and is not counted as successful.

See [ACCEPTANCE.md](ACCEPTANCE.md) for verified results. Both image groups and LoRA passed functionality checks, but the red-teapot prompt produced a white teapot, while the candidate added an extra cup and an abnormal handle. These results cannot be described as product-image quality acceptance or training improvement.

Large files are downloaded within bounds through official HTTP Range endpoints. Each response range is checked, and a completed file is published only after matching the official LFS SHA256. Partial files survive interruption; restricted-loading or digest failure never falls back to arbitrary pickle reading. Real local HTTP tests for the chunk downloader cover resuming a downloaded prefix and rejecting a corrupted prefix.

## Licenses and source references

- The [official Tiny-SD model card and pinned source](https://huggingface.co/segmind/tiny-sd/tree/cad0bd7495fa6c4bcca01b19a723dc91627fe84f) specify CreativeML OpenRAIL-M and distillation from Realistic Vision V4.0. Model-card statements do not establish all upstream training-data or output rights; this experiment offers no conclusion on permission to redistribute the base model.
- The [official Diffusers 0.35.2 LoRA training source](https://github.com/huggingface/diffusers/blob/v0.35.2/examples/text_to_image/train_text_to_image_lora.py) provides the basis for freezing VAE/CLIP/UNet, adding attention LoRA, random-timestep denoising MSE, and adapter saving. This implementation uses a fixed minimal single-device loop with real update/reload checks rather than directly executing arbitrary repository scripts. The library code is Apache-2.0.
- [Official PyTorch restricted weight loading](https://docs.pytorch.org/docs/2.14/notes/serialization.html#torch-load-with-weights-only-true) and the [MPS interface](https://docs.pytorch.org/docs/2.14/mps.html) define loading/device boundaries. Failure with `weights_only=True` does not expand execution permissions. The actual Torch wheel came from the official PyTorch index, with SHA256 `caf6359d64c0074bcb9f8641a169239118c8165a0a0fef79110c72bfd6474bec`.
- The [pinned SVD source license](https://huggingface.co/stabilityai/stable-video-diffusion-img2vid/blob/9cf024d5bfa8f56622af86c884f26a52f6676f2e/LICENSE.md) includes commercial-registration and annual-revenue conditions. Current work is local evaluation only; the model is not described as unconditionally commercial-use licensed, and its weights are not included in the application package.
- The [official SVD model card](https://huggingface.co/stabilityai/stable-video-diffusion-img2vid) states that it is image-conditioned, natively produces 14 frames, and cannot be text-controlled. It may produce static or slow motion; the interface does not fabricate `prompt` control.

Corresponding official API, license, and inspected upstream-source snapshots are retained under `.artifacts/m4-media/sources`. The official Wan 1.3B Diffusers version was not selected: its actual source files total approximately 29 GB, and its first combination is text-to-video, exceeding this run's total download budget and unable to directly serve the product-image input. Kokoro package versions, Chinese frontend, device, and voice-output evidence are in the separate TTS documentation.

## Media execution bridge

The control side uses the same isolated image/video Python environment to call `adapters/media/preflight.py` and `workers/media_worker.py`, both accepting `--snapshot` and `--output-dir`. Preflight writes no output directory and loads no base weights. It uses fixed official file cards, full directory manifests, actual CLIP tokenization, and input-image decoding. Existing LoRA shapes are checked against a standard UNet created on the meta device without GPU allocation. `media_recipe_digest` binds actual configuration, input manifests, executor source, and dependencies, independently of text tokenization-recipe fields.

| Operation | Available parameters | Input |
| --- | --- | --- |
| Image generation | `engine=diffusers`, `device_id=apple-gpu`, 512×512, 20 steps, CFG 7.5, explicit nonnegative 32-bit seed | `input.prompt` and optional `negative_prompt`; optionally an image LoRA bound to a complete manifest |
| Image LoRA training | Same device, 512×512, 12 steps, rank/alpha 4, learning rate 1e-4 | Complete manifest for `dataset_root_path`; `dataset_path` must point to its `dataset.json`; 1—8 original RGB images with captions/provenance/SHA |
| Image-to-short-video | Same device, 1024×576, 25 steps, 14 frames, 7 FPS | `input.material_id` and top-level `input_image_path`, full PNG manifest and digest; current SVD accepts no text control |

All models, input images, training directories, and optional adapters must be bound to full manifests. Extra directory files, symlinks, unknown parameters, unverified combinations, overlapping input/output, and overwriting old output are rejected. Images can use the clean imported directory `.artifacts/m4-media/image-model-runtime`, whose full manifest is in adjacent `image-model-runtime-import.json`. The sample dataset is `.artifacts/m4-media/image-dataset-runtime` and retains the previously stated synthetic-data quality limitations.

The real-model CLI and bridge remain in one execution process group. The bridge converts only training steps already written by the CLI into progress events; it does not fabricate generation percentages. After completion, it rechecks inputs and the execution recipe, writes `effective-config.json`, `output-manifest.json`, and an actual-source snapshot, and sends a SHA256-bearing completion manifest to the control service. Main outputs are `result/image.png`, `result/video.mp4`, or `result/pytorch_lora_weights.safetensors`. The current media bridge does not support training pause or checkpoint recovery.

Representative execution of `tests/media/run_real_bridge.py` is recorded in `.artifacts/m4-media/bridge-acceptance-v2/acceptance.json`: real image generation, 12-step training, and independent new-LoRA generation passed. Video was cancelled after actual step 1/25, returning 130 without a completion event; the process group exited. This cancellation case establishes the stop boundary only, not successful video generation or a successful UI workflow.
