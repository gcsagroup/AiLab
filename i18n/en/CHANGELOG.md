## Ver3.2 (075) · 2026-10-21

The model lab now includes the official English GSM8K test set: all 1,319 questions and a separate fixed 12-question trial. The frozen protocol uses 8-shot CoT examples, raw-text prompts, greedy generation, at most 1,024 output tokens per question and an 8,192-token context limit. Strict and flexible extraction are scored separately. Missing extractions and truncated answers remain in the denominator; flexible scores do not replace strict scores. Reports preserve source provenance, model manifests, runtime identity and raw answers.

Workflow: create a capability comparison, choose the ordinary eight questions, GSM8K trial or full set, and select both models. Freeze the set, check configuration and explicitly start. Models load separately and show saved-answer counts. After stopping and confirming process exit, continue saved evaluation to create a linked task, check again and start; only confirmed answers are reused, preserving the original task. Filter errors, differing verdicts, missing strict answers or truncations, page through outputs and export complete records. The ordinary eight questions retain manual review; GSM8K does not use that review or candidate admission.

Both sides support unquantized Qwen2.5-0.5B, existing 0.5B MLX 4-bit/64/affine weights and unquantized Qwen2.5-7B. Cross-size comparison freezes each tokenizer separately. Preflight checks models, prompt length, storage and runtime; continuation also checks the original recipe and answer chain. Other architectures, quantized 7B, broader benchmark suites and FP8-to-BF16 remain deferred without placeholder entries. Ordinary tasks retain strict rules; explanatory text does not automatically pass an integer-only rule.

The fixed company-signed app completed a real full comparison in an isolated library, with 1,319 questions per model, stopping during execution, quitting and reopening before continuation, filtering, pagination and complete export verification. The packaged runtime also ran an existing real 0.5B 4-bit model on the trial, and continuation after backup restoration was verified. Confirmed answers were neither regenerated nor changed; the daily library was preserved and restored. Scores describe this fixed protocol only, not general ability, candidate admission or public release qualification.

## Ver3.1 (072) · 2026-10-20

The model lab adds source and environment verification and ordinary capability comparison. Verification reads Heretic reproduce v4 or Abliterix schema 2 JSON, checks tool versions, reported provenance, actual file hashes, the imported manifest and current MLX dependency versions, and preserves the original report bytes for reopening and export. It does not execute report code, configuration or reproduction recipes. Matching checksums do not authenticate the publisher or prove reproduction.

Workflow: open the model lab, create a source check, select an imported model and external JSON, then verify and save. Inspect file and environment differences or export the original report and findings. For capability comparison, select baseline and candidate, freeze the fixed questions, inspect the configuration and explicitly start. Review real outputs per question; choose the question, model and verdict and enter a reason in manual review. Reviews are appended with history and never overwrite outputs or automatic scores. Report export includes questions, rules and manual reviews.

Comparison currently supports Qwen2.5-0.5B with matching tokenizers and templates: an unquantized baseline and an unquantized fused/distilled or MLX 4-bit/64/affine candidate. The eight fixed questions cover three arithmetic, two format, one sorting and two everyday tasks. Arithmetic strictly compares the requested integer-only output; explanatory text fails that rule even if its number is correct. Normal assistance does not establish correctness; false refusals require manual review. Results do not qualify candidates for admission. Full GSM8K/general benchmarks, additional architectures and different tokenizers remain unsupported. FP8-to-BF16 is deferred with no new entry.

Real local models completed separate-process loading, saved results, cancellation, cold reopening and physical export verification. The same company-signed app was operated in an isolated library for source checks, comparison and manual review. Both models had identical strict automatic scores on this fixed set; no capability gain was established. Parser acceptance used representative protocol test reports with real model hashes, not evidence of upstream model publication. The daily library was preserved and restored.

## Ver3.0 (070) · 2026-10-20

The model lab now runs weighted LoRA fusion, local offline response distillation, and Core ML, ONNX and TorchScript conversion. Fusion bases and students are limited to unquantized Qwen2.5-0.5B; local teachers can be 0.5B or 7B. Each path has real computation, independent loading and generation, saved models and physically verified exports. Inputs remain unchanged. Outputs are experimental models; fixed examples do not establish overall quality improvement.

The same company-signed 070 App completed native fusion, four-step distillation, Core ML conversion and independent generation (output 9). Distillation was cancelled at step 41/200; a cold restart retained the models and cancellation record. Final bundled runtimes completed all three format paths and export checks. A separate 7B-teacher/0.5B-student run scored 3/3 for the teacher and 2/3 for the student both before and after training on three fixed questions: no quality improvement was established. The daily library was preserved and restored. Tests passed: 1175 control, 720 frontend, 88 Rust, plus an 87-test targeted rerun. Rust had 3 ignored tests; packaging had 43 passed and 1 skipped.

Workflow: choose fusion, distillation or format conversion in the model lab, create the task, inspect it, then explicitly start. Fusion uses the original base and matching LoRA with weight 0.01–1. For distillation, first split data by source group, then choose a single-turn training subset of 1–64 rows. The local teacher generates answers and the student trains for 1–200 steps. Save the experimental model, try it from the model library or export it. Execution reports include provenance, settings, teacher answers and comparison results.

Limits: all three new formats use CPU, FP32, a fixed 128-token context and no KV cache. Core ML does not establish GPU or ANE acceptance; TorchScript uses an upstream deprecated export interface. Input plus reserved output exceeding the context is rejected without truncation. Multi-model fusion, online or KL distillation, distillation checkpoint resumption, additional architectures, dynamic shapes and cross-platform target-device acceptance remain incomplete. Heretic/Abliterix have no entry or executor. Other training methods, speculative decoding, hardware extensions, independent domain quality, five real users, clean installation and release remain incomplete; M5/M6 remain open.
