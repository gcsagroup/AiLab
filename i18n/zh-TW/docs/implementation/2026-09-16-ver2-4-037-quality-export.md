# 037 失敗品質准入、報告匯出與重開

固定公司簽名候選 Ver2.4（037）完成既有失敗評測的有限驗收：實際 HTTP 拒絕候選登記，原生查看逐題結果、匯出報告及同庫重開均通過。原權重 11/16、量化候選 10/16 的品質失敗保持，沒有新增模型計算或評測；完整 M5、M0—M6 與發行仍未通過。

<a id="候选来源与恢复"></a>

## 候選、來源與恢復

沿用 Global Cybersecurity Alliance Limited 簽名的固定 App，沒有重新構建。實際二進位摘要為 `59ce9d899488da868af0935f6dcb7f09749623deab250d55eeda7def4f0b2ce0`，本輪再次通過深層嚴格簽名檢查。[整包回執](../../../../.artifacts/integration-ver2-4-037-v1/root-frozen-check.json)

原 E22 工作庫停機後，只複製已凍結檔案，不連接原庫 SQL。離線恢復輸入共 91 個檔案、1868874298 位元組，明確標記為驗收檔案副本，不是產品備份介面生成的備份。隨後用 037 包內控制服務透過實際 HTTP 正式檢查並恢復為獨立庫，路徑引用由產品恢復邏輯重寫；原 11 份封存評測產物摘要保持。[恢復回執](../../../../.artifacts/native-m5-quality-ver2-4-037-v1/restore-001/result.json)

<a id="实际准入与原生操作"></a>

## 實際准入與原生操作

包內服務讀取原失敗評測，再以該評測請求登記原量化候選，返回 `409 / EVALUATION_FAILED`；候選登記數仍為 0，實驗模型身分保持。請求前後資源、命令、事件與專案未變，服務正常退出；沒有提交新的模型任務。[實際准入回執](../../../../.artifacts/native-m5-quality-ver2-4-037-v1/admission-001/result.json)

原生開啟既有評測任務，查看 16 題的基線與候選輸出、判定和失敗原因。業務任務及輸出格式均為 2/4，低於 75%；能力回歸均為 3/4，行為對照由 4/4 降為 3/4。介面區分執行完成和品質未通過，候選登記按鈕停用。[品質畫面](../../../../.artifacts/native-m5-quality-ver2-4-037-v1/native-001/01-quality-failed.png) [逐題記錄](../../../../.artifacts/native-m5-quality-ver2-4-037-v1/native-001/02-item-results.ax.txt)

透過原生選擇器選擇中文及空格目錄，檢查範圍後僅執行一次報告匯出。計畫和實際內容均為 11 個檔案、60884 位元組，另有完整性清單；其中 7 個 JSON 報告來自原封存產物，其餘為配方、固定題集、規則和物件說明。全部內容檔案逐項大小與摘要一致，原品質報告位元組不變。匯出記錄為 `export-38e8198354cb4b1a82a6299f7108eed0`。[完成畫面](../../../../.artifacts/native-m5-quality-ver2-4-037-v1/native-001/04-export-result.png)

正常退出後重開同一候選與獨立庫，品質失敗、停用登記以及同一匯出完成記錄保持；隨後再次正常退出。匯出目錄全部檔案及清單位元組不變；不將報告匯出等同模型獨立執行或品質通過。[重開畫面](../../../../.artifacts/native-m5-quality-ver2-4-037-v1/native-001/06-reopen-export.png)

原選擇檔案物件及內容恢復，47 項保護中 44 項嚴格不變，其餘為選擇檔案 ctime 與兩份啟動診斷。原 E22 庫、先前 4 個驗收庫全樹、12 個模型來源檔案及本輪離線恢復輸入均不變，主機來源設定未新增，守衛已恢復並釋放鎖。
