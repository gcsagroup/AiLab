# 匯出目錄項完整性修復

按 AC-27 與維運規範檢查匯出恢復時，發現固定 Ver2.4（038）仍可能誤接受含符號連結的包。本次已修復原始碼並完成相關回歸；尚未編入新的簽名候選，不能將原始碼通過計為包內或原生修復驗收。038 的既有清單身分驗收保留其原有範圍，完整 M6、M0—M6 與發行仍未完成。

<a id="重现与原因"></a>

## 重現與原因

舊檢查只列舉一般檔案，因此忽略額外斷鏈、目錄符號連結和命名管道；讀取清單時也沒有拒絕清單檔案本身的符號連結。真實檔案與資料庫停機重開測試中，這 4 種負例錯誤地恢復成功；合法完整包、普通空目錄及既有的內容檔案連結拒絕對照共 3 項通過。[修復前記錄](../../../../.artifacts/export-tree-integrity-source-v1/red.log)

另在固定 038 的實際包內服務執行 HTTP 負例：只在新建測試庫注入一次匯出登記拒絕，正常停止後，將包內清單替換為指向測試目錄中相同內容清單的連結，再重啟核實。舊候選錯誤返回成功和可用路徑，負例已保留。該故障是受控登記拒絕，不是作業系統程序崩潰；合成模型檔案不可用於模型執行，也未操作原生介面。[包內負例](../../../../.artifacts/export-tree-integrity-source-v1/packaged038-negative-001/result.json)

<a id="最小修复与验证"></a>

## 最小修復與驗證

核對過程改為先遍歷全部目錄項，不跟隨符號連結，只允許一般檔案與真實目錄，再檢查檔案集合、清單身分和逐檔摘要。特殊目錄項在讀取清單前被拒絕；掃描錯誤仍保留為失敗。合法目錄繼續允許，不修改原包、不重新複製或執行模型。該檢查不宣稱提供對同使用者並行篡改的作業系統隔離。

7 項定向測試通過，涵蓋清單連結、內容檔案連結、斷鏈、目錄連結、命名管道、合法完整包及普通空目錄。每項實際停機重開後核實，同冪等鍵返回原結果，檔案與連結保持，任務及嘗試數量不增。匯出、備份恢復、作品修訂與劃分資料匯出共 186 項回歸通過，保留 2 項既有依賴警告。[定向結果](../../../../.artifacts/export-tree-integrity-source-v1/green.log) [整合回歸](../../../../.artifacts/export-tree-integrity-source-v1/regression.log)

<a id="证据边界与后续"></a>

## 證據邊界與後續

包內負例後，47 項原保護記錄保持，所有本輪控制服務正常停止；沒有模型執行，也未連接原使用者庫進行 SQL 查詢。現有子代理因用量限制不可執行，主代理審查不計為獨立審查。下一候選仍需公司簽名構建、實際包內拒絕與合法恢復複驗及對應原生驗證；本記錄不提高完整 AC27 或 M6 狀態。
