# 039 原生遷移失敗回復與健康備份還原

同一固定公司簽名 **Ver2.4（039）** 完成受控空庫的原生遷移失敗、自動回到健康工作庫、健康舊版備份還原及同庫重開。真實失敗回執、資料庫位元組、原生畫面和停機讀回相互一致。此結果是 AC-22 的有限子集，完整 AC-22、M6、M0—M6 與正式發行仍未通過。

<a id="原生失败回滚及恢复"></a>

## 原生失敗、回復及還原

透過原生選擇器選定故障備份與本輪獨立目的地，完成還原後明確切換。實際包內遷移因索引衝突失敗；介面顯示遷移失敗並已恢復連接原工作庫。故障庫保留結構版本 1，資料庫位元組、業務列及索引保持切換前狀態；回執為 `failed_rolled_back`、`committed=false`，遷移備份摘要與原有內容核對通過。沒有偽造成功、替換包內遷移程式碼或啟動模型。[故障停機核對](../../../../.artifacts/m6-migration-ver2-4-039-v1/native-001/fault-readback.json)

隨後從同一原生還原入口選擇健康舊版備份。失敗重連使舊目的地授權失效，介面要求重新選擇；重新選擇同一目錄後，還原檢查、複製與切換成功。健康庫實際完成 1→2、2→3、3→4 三次遷移，各回執均成功並已提交，三份遷移前備份摘要均通過核對。原健康 A 的 8 項資源和原專案、命令、事件保持。

在修復庫中透過介面建立單一測試專案，專案名為「039 遷移回復驗收」。未建立模型、資源或執行記錄；專案建立直接寫專案表，不登記命令表。正常退出後再次用同一 App 重開，專案仍可見，資料庫位元組、全部資料表及遷移備份／回執整棵目錄完全不變。[首次審計](../../../../.artifacts/m6-migration-ver2-4-039-v1/audit-final.json) [重開核對](../../../../.artifacts/m6-migration-ver2-4-039-v1/native-reopen-002/readback.json)
