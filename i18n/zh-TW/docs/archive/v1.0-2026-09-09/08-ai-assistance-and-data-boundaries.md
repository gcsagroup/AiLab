# AI 輔助、用戶控制與數據邊界

版本：1.0 · 日期：2026-09-09 · 狀態：保留已確認的建議模式，真實模型連接待實現。

相關文檔：[產品需求](01-product-requirements.md)、[接口](07-api-and-task-lifecycle.md)、[數據管理](05-data-model-and-assets.md)。

<a id="1-ai-的职责"></a>

## 1. AI 的職責

AI 作為當前流程的解釋和建議助手，幫助用戶理解模型、訓練類型、數據問題、參數取捨、錯誤日誌與評測差異。AI 不擁有任務執行權，不代替用戶判斷數據授權或合法性，也不把建議自動應用到配置。

默認提示為“建議模式 · 由你決定”。AI 面板與任務主流程分開，收起不影響執行；連接不可用時主流程仍然可使用。

<a id="2-场景范围"></a>

## 2. 場景範圍

| 場景 | 可以提供的輔助 | 用戶動作 | 禁止自動執行 |
| --- | --- | --- | --- |
| 模型與方法 | 解釋 SFT／LoRA，指出不支持的組合 | 選擇模型與方法 | 自動換模型、改權重 |
| 數據準備 | 解釋字段、重復、缺失、劃分問題 | 查看處理影響並應用 | 自動刪除樣本或修改原件 |
| 訓練參數 | 建議更小批量、序列或步數 | 預覽、應用、重新檢查 | 自動啓動或重試訓練 |
| 運行優化 | 解釋 KV、上下文、MTP、DFlash 和設備條件 | 自行準備依賴與應用配置 | 自動重啓引擎或下載草稿 |
| 執行失敗 | 解釋日誌、列出可驗證原因 | 新建嘗試／取消／恢復 | 自動殺進程、清理文件 |
| 評測結果 | 歸納基線與候選差異、指出未測項 | 決定是否登記候選 | 修改報告或把失敗改為通過 |
| 數據來源 | 展示提供方材料、用戶聲明和缺失信息 | 自行核對並填寫聲明 | 作“已授權”“合法可用”判定 |

<a id="3-建议对象"></a>

## 3. 建議對象

建議必須是結構化的受限對象，不能把自然語言解釋直接解釋成命令。包含建議編號、目標對象、目標 revision、字段舊值與新值、原因、影響說明和上下文摘要。

```json
{
  "proposal_id": "proposal-001",
  "target_type": "task_draft",
  "target_id": "task-001",
  "expected_revision": 7,
  "title": "先用较小批量验证训练流程",
  "changes": [
    {
      "field": "training.micro_batch_size",
      "from": 2,
      "to": 1,
      "reason": "减少单步激活内存，先检查数据和产物链路。"
    }
  ],
  "requires_preflight": true,
  "execution_actions": []
}
```

`execution_actions` 必須為空。真實實現可以不向 AI 暴露該字段，而在服務端強制保證無執行動作。

<a id="4-预览应用和撤销"></a>

## 4. 預覽、應用和撤銷

1. 生成建議時不修改任務。
2. 預覽顯示每個字段舊值、新值、原因、影響和重新檢查要求。
3. 用戶點擊應用，服務端檢查目標、revision、字段白名單、舊值和類型。
4. 全部滿足才原子應用，任何一項失敗則全部不應用並說明原因。
5. 應用後產生審計記錄並標記相關技術檢查失效；不自動提交任務。
6. 撤銷僅在這些字段沒有後續修改、任務仍可編輯時允許。
7. 用戶已經改過同一字段或任務已提交時，拒絕直接覆蓋；可以提供可查看的反向建議草稿。

切換項目或任務後原建議不自動跟隨新對象。後台任務完成、設備變化或數據新版本出現時，也要檢查建議上下文是否過期。

<a id="5-字段白名单与禁止项"></a>

## 5. 字段白名單與禁止項

原型白名單只包含步數、批量、候選預算、輸入文本和少量數據處理選擇。正式實現可按功能逐步擴展，但必須為每個新增字段定義類型、範圍、解釋和撤銷規則。

不可由 AI 建議對象直接修改：憑證、設備信任、服務地址、模型文件、數據來源聲明、許可原文、訪問權限、項目歸屬、評測結果、候選准入狀態、發佈狀態、系統設置、刪除策略和執行控制狀態。

即使用戶詢問如何配置遠程設備，AI 也只能提供解釋和可人工填寫的方案，不借建議應用通道寫入服務地址或秘密憑證。

<a id="6-本地与远程-ai-连接"></a>

## 6. 本地與遠程 AI 連接

配置包含服務來源、地址、模型、連接狀態和憑證引用。測試連接只發送最小合成測試內容，不默認發送當前數據集、媒體或日誌。

使用遠程服務前展示將發送的上下文範圍：問題、必要的參數摘要、經過脫敏的錯誤片段，以及用戶明確選擇的樣本。默認不發送完整數據集、原始媒體、憑證、文件系統無關路徑或其他項目內容。

用戶可以在發送前查看／縮小上下文；本地服務也要展示實際連接地址，不能因為標籤叫“本地”就跳過地址與服務身份校驗。網絡失敗時不靜默轉發到另一家模型服務。

<a id="7-数据来源与提供方访问"></a>

## 7. 數據來源與提供方訪問

系統保存三類獨立信息：提供方發佈的原始說明，提供方訪問控制狀態，用戶填寫的使用範圍聲明。技術檢查報告只說明文件能否讀取、字段是否匹配和數據處理結果。

AI 可以指出“沒有找到來源鏈接”“未填寫使用範圍”“提供方尚未開放下載”，但不能把其中任一種情況總結為法律結論。用戶聲明為空可以顯示為空，不能填入“已同意”“可商用”等推斷文本。

若實際連接器要求訪問令牌或提供方批准才能下載，該限制由連接器執行；它與平台是否判斷授權是不同問題。已經獲得下載訪問也不自動完成模型或數據的發佈檢查。

<a id="8-不可信内容处理"></a>

## 8. 不可信內容處理

數據樣本、模型卡、README、日誌、網頁和外部服務返回都可能包含類似指令的文字。它們只能作為待分析材料，不可修改 AI 的執行權限或繞過字段白名單。

模型輸出中的命令、腳本或“請自動運行”文字不會自動執行。用戶如果確實要執行額外工作，應走獨立的明確產品動作與檢查流程；AI 建議通道不承載任意工具調用。

<a id="9-审计与隐私"></a>

## 9. 審計與隱私

記錄建議的目標、摘要、模型服務標識、字段變更、用戶應用／撤銷動作、時間和結果。不要在普通日誌中保存明文憑證或完整敏感樣本。建議正文可按用戶選擇保留在項目中，診斷導出前允許查看範圍。

AI 原始回答和實際應用的結構化變更分別保存，便於解釋“模型建議了什麼”與“用戶最後執行了什麼”。產品質量統計只在用戶選擇的範圍內記錄，不默認上傳遙測內容。

<a id="10-验收用例"></a>

## 10. 驗收用例

- 只打開或請求建議，任務配置完全不變。
- 用戶應用後只修改列出的字段，未列出的來源聲明保持原樣。
- 用戶先改字段，再應用舊建議，收到衝突而非被覆蓋。
- 應用後又手改同一字段，撤銷不得覆蓋用戶最新內容。
- 任務提交後無法修改其快照或通過 AI 重啓任務。
- 來源／許可問題得到材料整理與邊界說明，不得到代判結論。
- 惡意樣本要求執行命令時，建議解析器拒絕執行動作。
- 遠程連接測試不發送當前項目的真實數據。
