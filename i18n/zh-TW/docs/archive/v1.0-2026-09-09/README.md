# GCSA-AiLab 文檔中心

版本：1.0 · 編寫日期：2026-09-09 · 需求基線：最後一版整合 Demo，包含運行優化與多硬件配置。

<a id="1-文档用途与当前结论"></a>

## 1. 文檔用途與當前結論

這套文檔用於把已經確定的產品原型轉成可實施、可分工、可驗收的開發基線。覆蓋產品範圍、交互流程、訓練與推理、硬件適配、數據與資產、技術架構、接口、AI 輔助、開發排期、測試和發佈。

**當前交付是完整的設計與計劃文檔，不是已經實現的客戶端或模型服務。** 編寫時項目目錄沒有應用代碼；最後一版 Demo 存放在獨立原型目錄。原型的 42 組主流程測試與 17 組運行優化測試在本次編寫時重新執行通過。它們證明演示狀態與部分輸入校驗可以工作，不證明真實訓練、推理、下載、硬件檢測或加速效果已經完成。

本套文檔使用以下狀態，後續評審和開發不得混用：

| 狀態 | 含義 | 能否對外稱為支持 |
| --- | --- | --- |
| 原型已表現 | Demo 存在對應頁面、配置或模擬流程 | 只能稱為原型功能 |
| 規範待實現 | 本文明確要求、真實應用尚未實現 | 不能 |
| 技術方案建議 | 為開發提出的選型或結構，可由技術驗證調整 | 不能 |
| 待驗證組合 | 上游存在相關能力，但本項目未驗證完整組合 | 不能 |
| 實機驗收通過 | 精確設備、模型、版本、參數與報告均有證據 | 僅能聲明報告覆蓋的範圍 |

<a id="3-产品不变的骨架"></a>

## 3. 產品不變的骨架

1. 工作台按語言與多模態、圖片、視頻、音頻四類模型組織任務。
2. 每類提供訓練／微調、運行／試用、任務與結果，保留在同一類別內繼續工作的路徑。
3. 模型庫、工作流、數據集市場、模型實驗室、作品與素材、設備環境繼續保留。
4. 訓練類型與參數更新方式分開表達，例如 SFT + LoRA。
5. 運行配置必須體現模型、引擎、設備和版本的組合能力。
6. AI 只提出建議，修改、執行、登記和對外操作由用戶決定。
7. 來源記錄、提供方訪問控制和用戶聲明分別保存，AI 不代判數據授權或合法性。

<a id="4-文档之间如何保持一致"></a>

## 4. 文檔之間如何保持一致

- 功能需求編號統一使用 `PRD-xxx`，在 01 定義；工作包編號使用 `WP-xx`，在 10 定義；驗收用例編號使用 `AC-xx`，在 11 定義。
- 運行參數語義以 04 為準；訓練語義以 03 為準；對象與版本關係以 05 為準；任務狀態以 07 為準。
- 真實產品行為與 Demo 不同時，在 14 記錄差距，並在 10 分配修復工作包，不把演示中的簡化實現直接複製成產品規範。
- 階段劃分統一為 M0—M6，階段定義以 09 為準。估算是資源假設下的計劃，不是已承諾的發佈日期。
- 需要新增頂級入口或改變 AI 操作邊界時，先更新產品需求與交互，再更新實現任務。
- 模型名稱、引擎版本、精度支持和性能結論會變化，必須通過能力記錄和實測報告更新，不依賴文檔中一個固定的“支持”勾選。

## 5. 範圍說明
