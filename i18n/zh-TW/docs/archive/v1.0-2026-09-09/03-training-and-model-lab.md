# 訓練、微調與模型實驗室規格

版本：1.0 · 日期：2026-09-09 · 狀態：原型方法清單與真實實現規範；具體適配組合待驗證。

相關文檔：[數據規格](05-data-model-and-assets.md)、[運行與硬件](04-runtime-and-hardware.md)、[評測驗收](11-testing-and-acceptance.md)。

<a id="1-三个维度必须分开"></a>

## 1. 三個維度必須分開

訓練類別說明處理什麼模型，例如語言、圖像或音頻；訓練類型說明優化目標，例如 SFT、DPO、語音識別微調；參數更新方式說明修改哪些權重，例如 LoRA、QLoRA、全參數或指定模塊。

SFT 和 LoRA 可以組合，不能作為同一個下拉列表中的互斥選項。用戶提及的 STF 按上下文歸一為 SFT（監督微調）；界面和文檔統一使用 SFT。

<a id="2-方法与数据矩阵"></a>

## 2. 方法與數據矩陣

下表保留最終 Demo 的方法範圍，不代表每個模型和每個硬件都已經支持。

| 類別 | 訓練類型 | 優化目標 | 數據結構 | 可能的更新方式 | 首選驗收點 |
| --- | --- | --- | --- | --- | --- |
| 語言 | SFT | 學習指令和對話回答 | 多輪 messages | LoRA、QLoRA、全參數 | 正常任務和格式遵循 |
| 語言 | CPT 繼續預訓練 | 適配連續領域文本 | text、source_id | LoRA、全參數；量化路徑單獨驗證 | 領域能力和通用能力回歸 |
| 語言 | DPO | 偏好選擇 | prompt、chosen、rejected | LoRA、QLoRA、全參數 | 固定偏好集勝率與質量 |
| 語言 | GRPO | 可驗證獎勵優化 | prompt、answer、獎勵配置 | 適配器或全參數 | 獎勵有效性和獨立答案正確率 |
| 語言 | PPO | 獎勵模型驅動優化 | prompt、獎勵模型、參考策略 | 由訓練適配器聲明 | 獎勵、KL 與獨立能力檢查 |
| 多模態 | SFT | 圖文／音視頻理解 | messages、media | LoRA、全參數、指定模塊 | 真實媒體讀取與語義回答 |
| 多模態 | DPO | 媒體相關偏好 | media、prompt、chosen、rejected | 由模型模塊結構決定 | 媒體事實與偏好表現 |
| 圖片 | 擴散模型微調 | 風格或領域適配 | image、caption | LoRA、全參數 | 主體、風格與內容一致性 |
| 圖片 | DreamBooth | 主體適配 | image、caption、trigger | LoRA、全參數 | 主體保持及泛化 |
| 圖片 | 配對圖像訓練 | 融合、修復或編輯映射 | source、reference、target | 全參數、指定模塊 | 對齊、結構和細節回歸 |
| 視頻 | 視頻微調 | 鏡頭、動作與風格 | video、caption、fps、frames | LoRA、全參數 | 時序一致性與運動質量 |
| 音頻 | 語音合成微調 | 音色／發音／韻律 | audio、text、speaker | 全參數、指定模塊 | 發音、可懂度和音質 |
| 音頻 | ASR 微調 | 語音識別 | audio、text、language | LoRA、全參數 | CER／WER、分段和時間戳 |
| 音頻 | 聲音轉換訓練 | 音色轉換 | audio、speaker、音高特徵 | 模型適配器定義 | 內容保持與目標音色 |
| 音頻 | 音樂生成微調 | 音樂風格與條件生成 | audio、description、duration | LoRA、全參數 | 時長、描述符合度和聽感 |

訓練庫候選包括 [TRL](https://huggingface.co/docs/trl/index)、[PEFT](https://huggingface.co/docs/peft/index) 與 [MLX-LM](https://github.com/ml-explore/mlx-lm)。選用這些庫不自動使矩陣全部成立；版本、模型結構、量化和設備仍需適配驗證。PPO 等變化較快的訓練接口必須單獨鎖定版本並保留兼容層。

<a id="3-原型模型模板"></a>

## 3. 原型模型模板

Demo 包含 Qwen3-4B、Qwen2.5-VL-3B、Qwen Omni 多模態示例、SDXL、FLUX、圖像融合自定義網絡、Wan 視頻示例、CosyVoice、Whisper、RVC、MusicGen。

這些名稱是原型配置模板，不應直接成為正式產品中“已通過適配”的模型清單。正式條目必須記錄倉庫標識、固定 revision、權重校驗值、tokenizer／處理器版本、許可證文件引用、支持的輸入和訓練模塊。Qwen Omni 等描述性示例必須替換為一個具體可下載、可加載的版本才能進入實機驗收。

<a id="4-训练配置字段"></a>

## 4. 訓練配置字段

| 參數 | 說明 | 默認與約束策略 | 記錄位置 |
| --- | --- | --- | --- |
| 任務名稱 | 用戶目標和區分用途 | 必填；允許後改顯示名，不能改任務編號 | Task |
| 模型版本 | 固定源權重和 tokenizer | 必填；不得使用浮動 latest 作為完成記錄 | ModelVersion |
| 訓練類型 | SFT、DPO 等 | 從能力聲明生成 | TrainConfig |
| 更新方式 | LoRA、QLoRA、全參數、指定模塊 | 與模型和訓練引擎聯合校驗 | TrainConfig |
| 目標模塊 | 適配層／視覺連接層／輸出層 | 展示解析後的模塊列表 | TrainConfig |
| 數據版本 | 輸入樣本及處理結果 | 提交時固定版本與劃分 | DatasetVersion |
| 訓練步數／輪數 | 停止條件 | 正式產品允許選一種主條件，展示換算邏輯 | TrainConfig |
| 學習率 | 更新幅度 | 必須是有限正數；範圍由適配器限制 | TrainConfig |
| 每設備批量 | 單設備 micro batch | 正整數，與內存檢查關聯 | TrainConfig |
| 梯度累積 | 多個微批次累積後更新 | 正整數；展示有效批量 | TrainConfig |
| 最大序列長度 | 訓練截斷與打包長度 | 受模型和內存限制 | TrainConfig |
| 種子 | 劃分／初始化等可復現輸入 | 明確哪些隨機過程使用該種子 | TrainConfig |
| LoRA rank／alpha／dropout | 適配器結構與縮放 | rank 在 Demo 已有，其他待真實實現補齊 | AdapterConfig |
| 優化器／調度器 | AdamW 等優化器和學習率策略 | 由後端能力列出，禁止任意字符串執行 | OptimizerConfig |
| Warmup／權重衰減／梯度裁剪 | 訓練穩定性配置 | 默認來自版本化模板，可查看實際值 | OptimizerConfig |
| 訓練精度 | FP32、FP16、BF16 等 | 根據硬件、算子和引擎驗證 | EnvironmentConfig |
| 梯度檢查點 | 用重算降低激活內存 | 顯示速度與內存取捨 | TrainConfig |
| 保存／評測間隔 | 中間檢查點和驗證頻率 | 正數；支持結束時額外保存 | CheckpointPolicy |
| 輸出保留策略 | 檢查點數量和空間預算 | 不自動刪除被引用的產物 | ArtifactPolicy |

有效批量按“每設備批量 × 梯度累積 × 數據並行設備數”說明。張量並行設備數不能直接代入這條公式。分布式訓練採用何種並行方式由執行器聲明。

<a id="41-原型数值不是生产上限"></a>

### 4.1 原型數值不是生產上限

Demo 使用訓練步數 10—10,000、驗證集比例 5%—40%、批量 1—64、序列長度 128—131,072 等演示校驗。正式產品必須改為模型、方法和設備聯合約束，並在能力記錄中說明來源，不照搬這些常量作為產品能力承諾。

<a id="5-多媒体训练补充"></a>

## 5. 多媒體訓練補充

<a id="51-图像"></a>

### 5.1 圖像

數據準備包含圖片可解碼檢查、長寬、通道、顏色空間、方向信息、重復與近重復檢查。裁剪、縮放和標注修改必須生成處理配方。配對任務需要明確 source、reference、target 是否像素對齊，不能只校驗文件存在。

參數包括分辨率、裁剪策略、增強、主體觸發詞、文本編碼器是否訓練、先驗保持等模型相關配置。損失函數、網絡模塊和優化器必須屬於適配器白名單，不能通過任意腳本字段注入。

<a id="52-视频"></a>

### 5.2 視頻

記錄容器、編碼、幀率、幀數、時長、分辨率、抽幀策略和字幕／描述。變幀率素材必須定義統一時間基準。切片邊界以時間和幀索引雙重記錄，處理後的數據產生新版本。

驗收必須包含真實視頻解碼和短片訓練；僅顯示關鍵幀、移動一張圖片或完成文件寫入不算視頻訓練／生成通過。

<a id="53-音频"></a>

### 5.3 音頻

記錄採樣率、聲道、時長、響度、切片、轉寫、說話人和語言。結束時間必須大於開始時間且不超過實際音頻長度。重採樣、降噪、靜音切分等處理由用戶選擇並保留參數；不默認進行無法追溯的自動清洗。

語音合成、ASR、聲音轉換、音樂生成使用獨立數據與評測適配器。音頻可播放只證明文件可以解碼，不能代替語音質量或訓練效果驗收。

<a id="6-提交前检查"></a>

## 6. 提交前檢查

分為數據、模型、環境、配置和資源五類檢查。檢查結果可以是通過、阻斷或提示；每條結果包含原因、字段位置、可執行的修復動作和檢查版本。

必需阻斷：模型或數據文件缺失／損壞、數據格式不符、必要組件未準備、設備不可達、參數無效、引擎不支持當前方法、用戶選擇的精度不被實際設備支持、輸出目錄不可寫。

提示項：預計內存接近上限、樣本量較少、驗證集偏小、實驗目標描述不足。用戶未填寫來源聲明時保留“未填寫”，不能由 AI 變成“已授權”，也不把來源聲明缺失偽裝成技術格式錯誤。

<a id="7-模型实验室"></a>

## 7. 模型實驗室

| 專項 | 輸入 | 必要設置 | 輸出 | 獨立驗收 |
| --- | --- | --- | --- | --- |
| 行為調整／破甲對照 | 源權重、目標數據、回歸集 | Heretic／Abliterix 版本、目標、候選預算、允許能力下降 | 每種方法的候選與變更記錄 | 正常任務、目標行為、格式和通用能力 |
| 蒸餾 | 教師、學生、數據 | 教師採樣、損失／目標、訓練預算、教師輸出版本 | 學生候選及教師來源 | 學生質量與體積／速度對照 |
| 合併 | 兼容基座與適配器／模型 | 方法、權重、結構校驗 | 新權重或合併適配器 | 能否加載、能力回歸、配置可重現 |
| 量化 | 源權重、可選校准集 | 格式、位寬、分組、校准策略 | 運行產物 | 正確性、體積、速度、質量變化 |
| 轉換 | 原始模型、處理器與示例輸入 | Core ML／ONNX／TorchScript 等目標、形狀、精度 | 目標格式及元信息 | 數值一致性和目標設備執行 |

<a id="71-行为调整研究边界"></a>

### 7.1 行為調整研究邊界

保留用戶確認的入口和雙引擎獨立候選設計；不把方法名稱等同於產品已具備技術能力。自研研究路徑在沒有執行適配器時保持不可啓動。第一步是覈實具體上游來源、版本、輸入條件和輸出形式，再運行正常任務與目標行為對照。

<a id="72-蒸馏边界"></a>

### 7.2 蒸餾邊界

區分教師生成數據後的離線蒸餾與訓練過程中調用教師的在線蒸餾。教師調用的地址、輸入發送範圍、費用來源、輸出緩存和失敗重試需要明確記錄。遠程教師不可用時不能默默切換其他教師。

<a id="73-合并边界"></a>

### 7.3 合併邊界

先檢查架構、層數、tokenizer、基座版本和適配器目標模塊。維度相同不等於語義兼容。合併不覆蓋任一輸入；產生新版本並記錄參與權重。

<a id="74-量化转换边界"></a>

### 7.4 量化／轉換邊界

轉換不承諾提升速度，量化不承諾保持全部能力。產物登記前至少完成獨立加載、固定樣例對照和目標運行環境檢查。ANE 驗收必須使用實際 Core ML 產物及設備執行記錄。

<a id="8-评测与候选登记"></a>

## 8. 評測與候選登記

評測集在訓練前凍結，避免根據本次輸出反復改變准入條件。報告同時保存基線、候選、評測配置、樣本版本、閾值、逐樣本結果和匯總。

語言任務至少覆蓋業務正確性、格式、正常任務回歸和目標行為；圖像關注主體與結構；視頻增加時序；音頻按任務選擇 CER／WER、可懂度、音質或聽評。無法自動量化的項目標為人工評審，不偽造一個綜合分數。

登記候選的前提是產物存在、哈希一致、能獨立加載、要求的評測已完成且符合預設規則。登記操作冪等；同一候選重復點擊不產生多個模型版本。

<a id="9-完成标准"></a>

## 9. 完成標準

每一個“支持的訓練組合”都必須有一條從真實數據到獨立加載候選的證據鏈：輸入版本、處理配方、最終配置、設備環境、訓練日誌、檢查點、評測報告、產物哈希、運行結果。訓練損失下降、腳本成功退出或頁面顯示完成，均不能單獨作為交付依據。
