# 測試策略與驗收標準

版本：1.0 · 日期：2026-09-09 · 狀態：原型測試已復跑；真實產品測試為待執行計劃。

相關文檔：[需求](01-product-requirements.md)、[工作包](10-work-breakdown.md)、[發佈](12-operations-and-release.md)、[原型證據](14-prototype-traceability.md)。

<a id="1-证据层级"></a>

## 1. 證據層級

| 層級 | 能證明什麼 | 不能證明什麼 |
| --- | --- | --- |
| 文檔與靜態檢查 | 需求、鏈接、示例與字段一致 | 應用實際可運行 |
| 原型狀態測試 | 模擬狀態、部分校驗和交互意圖 | 真實執行、持久化與性能 |
| 單元／合同測試 | 規則、接口、狀態、參數映射 | 實際驅動、模型加載或最終體驗 |
| 集成測試 | 數據庫、進程、文件、服務交互 | 所有硬件與模型通用支持 |
| 實機測試 | 指定組合的真實執行和指標 | 未測試版本和其他設備 |
| 用戶端到端驗收 | 真實入口到最終產物的完整任務 | 對外發佈、升級等未執行流程 |
| 發佈驗收 | 具體安裝包和支持矩陣可交付 | 未來版本自動繼承通過 |

測試報告必須標明層級、輸入、環境、版本、執行時間、結果與限制。原型測試和模擬執行不得進入真實性能統計。

<a id="3-测试环境与数据"></a>

## 3. 測試環境與數據

<a id="31-最小设备池"></a>

### 3.1 最小設備池

- 一台明確型號與統一內存大小的 Apple Silicon Mac。
- 一台明確 GPU、顯存、系統和驅動版本的 NVIDIA Linux 機器。
- M5 擴展時提供明確型號的 AMD GPU 和 Intel GPU／NPU 設備。
- 一台乾淨安裝／升級測試環境；可使用獨立用戶賬戶或虛擬機，但 GPU 功能驗收必須有實際適用設備。

每次報告保存 CPU、GPU／NPU、內存、系統、驅動、引擎、模型、精度、存儲、網絡和電源狀態。設備不可用時標記未測，不以其他廠商機器代替。

<a id="32-数据夹具"></a>

### 3.2 數據夾具

準備小型可公開文本、圖像、短視頻和音頻樣例，並附來源記錄。正常數據與負例分別管理，負例包含缺字段、損壞文件、空內容、重復、過長輸入、越界切片、錯採樣率、變幀率和模型不兼容。

功能性小樣本用於檢查鏈路，質量評測集用於檢查效果，二者分開。不得把訓練中使用的樣本直接當獨立測試集。近重復分組信息與劃分種子固定保存。

<a id="4-核心验收用例"></a>

## 4. 核心驗收用例

<a id="ac-01项目与草稿持久化"></a>

### AC-01：項目與草稿持久化

前置：兩個項目，各有語言和圖片草稿。操作：編輯、切換項目、關閉應用、重啓。預期：任務編號、字段、選中對象和歷史按項目恢復；後台結果歸屬原項目。證據：數據庫記錄、應用操作錄像或截圖、相關事件。覆蓋 PRD-001、PRD-018。

<a id="ac-02四类入口与继续任务"></a>

### AC-02：四類入口與繼續任務

從首頁逐類進入，恢復草稿、新建任務、查看運行和評測，再返回首頁。預期：入口清楚、狀態按鈕指向下一步，無重復訓練入口或錯誤類別。不能只檢查路由存在。覆蓋 PRD-002、PRD-020。

<a id="ac-03模型准备与独立加载"></a>

### AC-03：模型準備與獨立加載

使用固定模型 revision，下載、暫停／恢復（支持時）、取消、重試，並加入一個損壞文件。預期：完整性失敗不能顯示準備成功；完成後獨立進程可加載；適配器需要基座時能指出依賴。覆蓋 PRD-003。

<a id="ac-04数据导入检查与版本"></a>

### AC-04：數據導入、檢查與版本

導入正常 JSONL 與四類負例，檢查行號、媒體、重復和劃分。應用排除／重採樣後驗證原件哈希不變，新版本可追溯；數據改變使舊檢查失效。覆蓋 PRD-004。

<a id="ac-05市场访问与返回原任务"></a>

### AC-05：市場訪問與返回原任務

從已有訓練草稿進入市場，分別完成開放下載、受限申請、拒絕、通過、下載和選擇數據。預期：錯誤 schema 不能使用；返回後原名稱、參數、項目和步驟保留；訪問獲准不出現授權代判標籤。覆蓋 PRD-005。

<a id="ac-06训练方法与更新方式"></a>

### AC-06：訓練方法與更新方式

對每個開放組合運行最小真實訓練，至少包含首期 SFT + LoRA。驗證目標模塊、數據 schema、優化步數與權重變化；不支持的 QLoRA／精度／設備組合由服務端拒絕。新增方法逐項增加用例。覆蓋 PRD-006。

<a id="ac-07任务生命周期"></a>

### AC-07：任務生命週期

覆蓋排隊、準備、運行、取消、失敗、檢查點、可用時暫停／恢復。預期：沒有確認就不顯示終態；失敗重試產生新嘗試；舊日誌保留；恢復不是僅加載權重後偽稱繼續原軌跡。覆蓋 PRD-007。

<a id="ac-08真实运行与结果"></a>

### AC-08：真實運行與結果

文字生成、圖像生成、視頻生成、TTS／ASR 等按已開放能力實際執行。預期：輸入被使用，輸出文件可獨立讀取，最終結果和歷史一致；不能用預置圖或音頻作為真實產物。覆蓋 PRD-008。

<a id="ac-09运行参数真正生效"></a>

### AC-09：運行參數真正生效

測試關閉思考、上下文、輸出限制、採樣、停止詞與流式。比較請求配置、後端實際參數和觀察結果；超預算拒絕／裁剪符合用戶選擇。修改彈窗取消後原值不變；運行中不能修改快照。覆蓋 PRD-009。

<a id="ac-10缓存prefill-与-decode"></a>

### AC-10：緩存、Prefill 與 Decode

固定模型和輸入，驗證緩存隔離、失效、KV dtype、分塊、批處理、併發和 CUDA Graph。引擎不支持字段時拒絕，不能丟參。分離部署缺連接器時阻斷；實現後注入傳輸和模型版本錯配。覆蓋 PRD-010。

<a id="ac-11推测解码配对"></a>

### AC-11：推測解碼配對

分別測試普通草稿、MTP、DFlash 的正常和不匹配輸入。MTP 缺組件拒絕；DFlash 目標、草稿、模板或思考條件錯配拒絕；配套準備後測正確性、接受率和延遲。覆蓋 PRD-011。

<a id="ac-12设备与引擎适配"></a>

### AC-12：設備與引擎適配

逐個登記真實設備，驗證可達、探測、依賴、加載和運行狀態分離。NVIDIA、Apple、AMD、Intel、CPU 分別保存報告；同品牌不同系統不自動繼承支持。覆蓋 PRD-012。

<a id="ac-13媒体参数与-core-mlane"></a>

### AC-13：媒體參數與 Core ML／ANE

圖片檢查調度器、CFG、VAE 與卸載；視頻檢查幀率、幀數、時長與切片；音頻檢查採樣率、切片、流式塊和轉寫。Core ML 原始權重錯配拒絕，轉換產物獨立執行；只有具備分配證據才聲明 ANE 使用。覆蓋 PRD-008、PRD-012、PRD-013。

<a id="ac-14评测与候选准入"></a>

### AC-14：評測與候選准入

基線和候選使用固定數據與規則，注入一個不達標候選和一個損壞產物。預期：不能登記為可用模型；通過候選可獨立加載試用，來源實驗可返回；重復登記冪等。覆蓋 PRD-014。

<a id="ac-15ai-建议模式"></a>

### AC-15：AI 建議模式

檢查建議生成不修改、應用只改白名單、過期 revision 拒絕、撤銷不覆蓋後改、提交後只讀、惡意材料無執行權。核對遠程請求範圍與來源問題回答邊界。覆蓋 PRD-017。

<a id="ac-16作品配方与来源"></a>

### AC-16：作品、配方與來源

保存產物後關閉應用，重新打開並載入配方；切換模型版本／設備後檢查差異提示。預期：輸入、產物、基座／適配器、參數和來源都可找到；收藏與文件保存不混淆。覆蓋 PRD-016。

<a id="ac-17完整媒体工作流"></a>

### AC-17：完整媒體工作流

真實完成圖片 → 視頻 → 配音，並在中間注入失敗。預期：前序結果保留，重做後舊下游有來源版本提示，最終全部產物可獨立打開。若沒有合成能力，不得稱為最終成片。覆蓋 PRD-015。

<a id="ac-18故障与恢复"></a>

### AC-18：故障與恢復

在運行、寫文件、提交事務、事件發送等階段終止進程，模擬磁盤滿和遠端斷開。重啓後無重復執行、不丟已提交記錄、不把部分文件標完整；任務狀態未知時進行重連核對。覆蓋 PRD-018。

<a id="ac-19模型实验室"></a>

### AC-19：模型實驗室

對合併、蒸餾、量化、轉換和行為對照逐項執行。檢查輸入兼容、候選獨立、產物哈希、質量回歸和來源鏈。自研未實現入口不可啓動。覆蓋 PRD-013。

<a id="ac-20幂等与竞争"></a>

### AC-20：冪等與競爭

雙擊提交、相同冪等鍵重發、不同內容復用冪等鍵、取消與完成競爭、AI 與手工編輯競爭、重復終態事件。預期：合法單次執行、明確衝突、數據庫與界面一致。覆蓋 PRD-007、PRD-018。

<a id="ac-21远程执行与输入边界"></a>

### AC-21：遠程執行與輸入邊界

測試遠端身份不符、憑證失效、上傳中斷、相同文件去重、運行斷連、日誌補拉。預期：不靜默發送到其他地址，不在未知狀態重復啓動，診斷數據無明文密鑰。覆蓋 PRD-012、PRD-018。

<a id="ac-22安装升级备份与导出"></a>

### AC-22：安裝、升級、備份與導出

在乾淨環境安裝具體候選包，升級含歷史任務的舊版本，回滾一次失敗遷移，並恢復備份。導出後用獨立進程加載文件。預期：身份和數據一致，不將卸載等同刪除模型數據。覆蓋 PRD-018、PRD-019。

<a id="ac-23界面键盘与外观"></a>

### AC-23：界面、鍵盤與外觀

檢查 1024、736、360 px 深淺色、最小 320 px，表單標籤、焦點、彈窗、錯誤關聯、長名稱、中文路徑、空態和大列表。用鍵盤完成一條任務；不能以靜態截圖代替關鍵交互。覆蓋 PRD-002、PRD-020。

<a id="ac-24性能与质量对照"></a>

### AC-24：性能與質量對照

對每個宣傳的優化執行關閉／開啓對照，固定負載、精度和環境，記錄冷／熱、併發、內存與質量。結果包含無收益或變慢情況，不篩選最好樣本作為普遍結論。覆蓋 PRD-010、PRD-011、PRD-012。

<a id="5-性能测试方法"></a>

## 5. 性能測試方法

<a id="51-基准条件"></a>

### 5.1 基準條件

每個配置至少包含短、中、長輸入和單請求／多請求兩組負載。正式輸入長度由參考模型能力決定，並記錄精確 token 數。冷加載與熱運行分開；穩定性測試至少 30 個固定請求，必要時重復 3 輪；首輪編譯和模型下載單獨計時。

採樣參數、輸出長度限制、停止條件、種子、緩存命中條件和併發必須相同。比較不同量化或不同精度時明確它們改變了計算條件，並同時報告質量。

<a id="52-指标口径"></a>

### 5.2 指標口徑

| 指標 | 口徑 |
| --- | --- |
| 端到端延遲 | 客戶端提交到最終結果完成；包含傳輸和排隊 |
| 首 token 延遲 | 提交到首個輸出 token；單獨注明是否包含模型加載 |
| Prefill 速度 | 輸入 token 數／實際 Prefill 時長；僅引擎能明確歸因時報告 |
| Decode 速度 | 首 token 之後的生成 token 數／對應生成時長；1 token 輸出不計算 |
| 總吞吐 | 測試窗口實際完成 token 或請求數／窗口時長 |
| 峰值內存 | 測量工具記錄的峰值；顯存／統一內存／進程內存分別列出 |
| 緩存命中 | 引擎實際命中統計；沒有觀測接口則標未知 |
| 草稿接受率 | 被接受的草稿 token／提出的草稿 token，口徑與引擎報告對應 |
| 質量變化 | 固定樣本與規則下的候選和基線差異 |

不以字符數直接冒充 token 數，不以第一段響應提前返回證明完整推理更快，不以單次最好結果替代中位數和 p95。

<a id="6-训练质量验收"></a>

## 6. 訓練質量驗收

功能驗收與模型質量驗收分別報告。功能驗收要求參數更新、檢查點完整、可恢復、產物可加載；質量驗收要求固定業務／回歸樣本、合理閾值、樣本量與人工評審。

閾值在測試前確定，按任務分別制定。無法統一自動評分時保留逐樣本結果和評審說明，不用一個無來源分數掩蓋差異。損失下降、獎勵升高不單獨構成通過。

<a id="7-自动化分层"></a>

## 7. 自動化分層

- 單元層：參數 schema、版本、數據劃分、狀態轉移、建議應用和緩存鍵。
- 合同層：請求／響應、錯誤代碼、冪等、事件順序、執行器能力。
- 集成層：真實 SQLite、臨時目錄、進程、文件校驗和受控遠程服務。
- 模型層：小模型／小樣本真實運行，檢查權重和輸出，不使用大模型佔滿常規 CI。
- 設備層：帶標籤的專用機器執行已安排矩陣，產物與報告關聯提交版本。
- 端到端層：瀏覽器／桌面真實操作完成用戶路徑。

<a id="8-缺陷等级与放行"></a>

## 8. 缺陷等級與放行

| 等級 | 示例 | 放行原則 |
| --- | --- | --- |
| 阻斷 | 數據丟失、重復昂貴執行、錯誤項目歸屬、虛假成功、憑證洩露 | 本版本不得發佈 |
| 高 | 主流程無法完成、參數被忽略、候選准入繞過、取消不生效卻顯示成功 | 必須修復並復測 |
| 中 | 明確的非主路徑錯誤、可繞過但影響使用的交互問題 | 評估範圍與公開限制，通常修復 |
| 低 | 非關鍵文案、局部間距、輔助信息不清楚 | 記錄並納入後續修正 |

不支持某硬件不是缺陷，錯誤宣稱支持或允許不可執行組合才是缺陷。未測能力在發佈矩陣中保持未測，不能通過關閉測試消除失敗記錄。

<a id="9-阶段门槛"></a>

## 9. 階段門檻

M1 通過持久化與任務合同；M2 通過真實推理和參數；M3 通過訓練到候選閉環；M4 通過媒體和市場；M5 對每個新增組合獨立驗收；M6 通過安裝、升級、恢復和完整回歸。每階段保留已失敗案例作為後續回歸輸入。

<a id="10-报告模板"></a>

## 10. 報告模板

每份報告必須包含：報告編號、對應需求／工作包、代碼提交、應用包身份、模型和數據版本、環境摘要、操作步驟、預期結果、實際結果、日誌／產物引用、通過／失敗／未測、限制和復測結果。

發佈驗收必須使用將要交付的同一個安裝包與運行依賴。重新打包、更改簽名、驅動或模型版本後，相關驗收失效並按影響範圍復測。
