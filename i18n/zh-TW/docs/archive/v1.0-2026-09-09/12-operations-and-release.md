# 安裝、運行維護與發佈計劃

版本：1.0 · 日期：2026-09-09 · 狀態：待實現產品的運行規範；當前沒有安裝包、後台服務或生產部署。

相關文檔：[開發路線](09-development-roadmap.md)、[任務合同](07-api-and-task-lifecycle.md)、[測試](11-testing-and-acceptance.md)。

<a id="1-交付单元"></a>

## 1. 交付單元

區分桌面客戶端、控制服務、執行器、環境包、模型文件、數據、作品和報告。應用升級不默認重下全部模型，也不自動升級正在使用的訓練環境。

發佈清單包含應用版本、提交哈希、構建平台、包摘要、簽名身份、基礎依賴、可選環境、數據庫 schema、支持矩陣、已知問題和回滾說明。

<a id="2-首次安装与环境准备"></a>

## 2. 首次安裝與環境準備

1. 安裝應用，檢查基本存儲權限和可用空間。
2. 用戶選擇數據根目錄與模型緩存位置。
3. 只讀探測設備，顯示真實型號、內存、驅動和可用後端。
4. 用戶選擇要準備的運行／訓練環境，查看依賴來源、空間和操作範圍。
5. 創建獨立環境並執行最小自檢；成功後登記環境摘要。
6. 準備模型，完成下載完整性和加載檢查。
7. 執行一個真實示例任務，保存結果與配方。

沒有驅動時說明需要的步驟；驅動安裝、系統權限變更和遠程服務部署不作為普通連接檢查的一部分。用戶取消準備後，現有環境和數據保持可用。

<a id="3-运行模式"></a>

## 3. 運行模式

| 模式 | 網絡與執行 | 展示規則 |
| --- | --- | --- |
| 演示模式 | 預置數據和模擬執行，無真實計算承諾 | 全局醒目標記，結果附演示來源 |
| 本地模式 | 本機已準備模型和執行環境 | 顯示實際設備、參數和產物 |
| 遠程模式 | 用戶指定服務器或已配置雲實例 | 提交前展示發送內容與目標 |

演示與真實數據目錄分開，不能在同一任務中混用模擬指標和真實指標。生產發佈包可以保留演示體驗，但必須有清晰模式邊界，模擬成功記錄不得進入正式支持報告。

<a id="4-日常运行与资源管理"></a>

## 4. 日常運行與資源管理

模型實例按模型版本、適配器、引擎、精度和加載參數標識。復用條件一致才共享；否則新建實例或明確卸載重載。用戶可以查看駐留模型、佔用來源和正在使用的任務。

關窗、退出應用和停止執行器分別定義：關窗可以保留後台任務；退出前顯示本地運行任務處理選項；遠程任務即使控制端退出也應可在重開後重新連接。沒有遠端持久執行能力時必須提示其限制。

<a id="5-日志与指标"></a>

## 5. 日誌與指標

日誌分應用、控制服務、執行器、任務四層，統一 task_id／attempt_id／environment_id。用戶界面顯示階段和中文摘要，可展開原始技術錯誤。

默認日誌不保存完整數據集、明文憑證或無關文件內容。任務輸入與輸出作為項目資產保存，訪問與清理遵循項目規則。診斷導出先生成可預覽清單，用戶選擇範圍後再導出。

指標需要聲明來源與採集間隔。無法從系統或引擎讀取的 GPU／ANE 使用率、緩存命中率或推理分段耗時顯示未測，不從進度條反推指標。

<a id="6-常见故障处理"></a>

## 6. 常見故障處理

| 故障 | 自動處理 | 用戶可選操作 | 必須保留 |
| --- | --- | --- | --- |
| 模型下載中斷 | 保存下載游標和已校驗塊 | 續傳、重新下載、取消 | 來源 revision、臨時文件狀態 |
| 文件校驗失敗 | 隔離不完整文件，不登記成功 | 刪除該臨時下載並重試 | 校驗摘要和錯誤 |
| 設備連接中斷 | 限定頻率重連和狀態查詢 | 修改連接、等待、取消本地等待 | 已知 attempt_id 和事件游標 |
| OOM | 記錄錯誤並釋放可釋放資源 | 減小參數，新建嘗試或恢復 | 原參數、日誌、可用檢查點 |
| 磁盤滿 | 停止新寫入，報告可恢復範圍 | 選擇空間、清理緩存、重試收集 | 完整產物和未完成標記 |
| 引擎進程崩潰 | 控制服務保持可用 | 查看日誌、重試、新環境 | 退出信息和快照 |
| 數據庫遷移失敗 | 停止新版本寫入，保留備份 | 回滾應用／恢複數據庫 | 舊庫、遷移版本和日誌 |
| 評測失敗 | 保留候選研究記錄，禁止准入 | 查看樣例、調整後新建實驗 | 固定評測規則和逐樣本結果 |

不得通過自動反復重跑昂貴訓練掩蓋故障，也不得清理用戶原始數據來“自動修復”磁盤問題。

<a id="7-备份与恢复"></a>

## 7. 備份與恢復

備份範圍：元數據庫一致快照、資產 manifest、需要保留的模型／數據／作品、任務快照、環境鎖文件、檢查點和報告。憑證只保留重新連接說明或安全存儲引用，不導出明文。

推薦允許用戶選擇完整備份或元數據／配方備份。後者必須說明大文件缺失時需要重新獲取，不能聲稱可離線恢復所有產物。

恢復先校驗 schema 與文件摘要，創建新恢復目錄，驗證後再切換當前工作區。恢復失敗不覆蓋仍可使用的原工作區。每次正式發佈前至少進行一次從實際備份恢復代表項目的演練。

<a id="8-清理与空间治理"></a>

## 8. 清理與空間治理

按類別展示空間：模型、數據原件、處理版本、檢查點、作品、運行緩存、下載臨時文件和日誌。先列出路徑、大小、引用與原因，再執行用戶選擇的清理。

優先可恢復方式。存在引用的文件不能因為“很久沒打開”就刪除；訓練檢查點若被恢復任務引用必須保留。清理完成後驗證索引、引用和剩餘空間，必要時允許撤銷。

卸載客戶端默認不刪除用戶數據根目錄。刪除模型、移除模型條目、清理引擎緩存是不同動作，文案要說明實際影響。

<a id="9-更新与回滚"></a>

## 9. 更新與回滾

應用更新先檢查是否存在本地任務和數據庫遷移。需要中斷時讓用戶選擇合適時機，不能在訓練過程中自動重啓側進程。下載的新包校驗摘要與簽名，再切換版本。

數據庫遷移採用版本化腳本和備份；不可逆遷移需要保留舊應用能夠讀取的備份副本。環境升級以新環境並存方式進行，舊任務仍可找到原依賴。模型更新產生新 ModelVersion，不能更改已有版本的文件。

回滾後驗證項目列表、任務快照、產物讀取和新任務執行。應用回滾成功不等於所有訓練環境都回滾成功，報告要分開。

<a id="10-导出与对外发布"></a>

## 10. 導出與對外發佈

導出包包括選定產物、配方、來源關係、必要處理器／tokenizer、兼容條件和報告。用戶可選擇模型、適配器、作品或評測報告；適配器導出明確列出基座依賴。

導出完成後使用獨立環境驗證文件可讀／可加載。對外上傳、模型倉庫發佈、服務器部署和創建雲資源均為獨立動作，不由導出按鈕自動觸發。

發佈前記錄分發依賴與模型／數據材料範圍；只列出實際可核查材料，不由 AI 生成授權結論。當前文檔不包含特定法律結論，也不把來源說明替代用戶的實際發佈決定。

<a id="11-发布验收清单"></a>

## 11. 發佈驗收清單

| 類別 | 必需證據 |
| --- | --- |
| 身份 | 安裝包版本、摘要、簽名、構建來源與提交一致 |
| 安裝 | 乾淨機器安裝、首次啓動、基礎環境檢查 |
| 主流程 | 已聲明範圍的真實訓練／推理／評測／保存閉環 |
| 數據 | 歷史項目升級、備份恢復、引用完整 |
| 設備 | 發佈矩陣內每個組合都有對應報告 |
| 參數 | 公開控件都有實際映射和必要測試 |
| 故障 | 取消、斷連、OOM、磁盤滿、進程崩潰可解釋和恢復 |
| AI | 無自主執行、建議衝突處理、發送範圍明確 |
| 外觀 | 中文、鍵盤、深淺色和代表窗口寬度檢查 |
| 文檔 | 用戶指南、支持範圍、已知問題、回滾方法 |

任何數據丟失、錯誤項目歸屬、參數被靜默忽略、虛假成功或憑證洩露問題都阻斷發佈。未驗證硬件不應列為已支持。
