<a id="2-建议技术决策记录"></a>

## 2. 建議技術決策記錄

<a id="adr-001采用模块化控制服务与独立执行器"></a>

### ADR-001：採用模塊化控制服務與獨立執行器

狀態：建議採用，M0 驗證。

原因：現有產品需要可靠的任務、版本與結果關係，多種引擎依賴差異大。控制服務維護統一合同，獨立執行器承擔計算，可避免某個模型環境崩潰拖垮全應用。

替代方案：全部在前端執行不適合真實訓練；一開始拆成大量微服務增加部署成本。先使用單體領域服務，後續有真實規模需求再拆分。

驗證：最小任務從界面提交到產物落盤，終止執行器後控制服務仍可響應並恢復狀態。

<a id="adr-002建议-reacttypescript--tauri--python"></a>

### ADR-002：建議 React／TypeScript + Tauri + Python

狀態：候選技術棧，尚未鎖定版本。

原因：復用 Web 界面能力，並接近 Python 模型生態。風險在多平台打包、側進程與本地依賴體積，需要 M0 驗證。若桌面殼成為阻礙，可先以本地 Web 宿主驗證業務合同；這不改變正式產品的桌面目標。

<a id="adr-003sqlite-元数据与文件资产分离"></a>

### ADR-003：SQLite 元數據與文件資產分離

狀態：建議採用。

原因：本地單用戶任務索引適合事務元數據庫，大模型和媒體適合文件存儲。風險是事務和文件提交之間的一致性，應通過臨時寫入、摘要校驗、原子登記和恢復掃描處理。

<a id="adr-004能力声明驱动配置"></a>

### ADR-004：能力聲明驅動配置

狀態：產品要求，技術結構建議。

原因：運行參數由模型、引擎、硬件和版本聯合決定。前端控件和後端校驗共享 schema，但後端必須重新校驗。風險是能力表變成靜態宣傳表，需記錄來源、探測結果和實機報告。

<a id="adr-005先实现已配置远程资源"></a>

### ADR-005：先實現已配置遠程資源

狀態：建議採用。

原因：首期重點是運行與訓練閉環，不同時建設雲採購與費用結算。雲實例創建、預算和銷毀作為後續獨立能力；當前僅接入用戶已有服務器或實例。

<a id="adr-006ai-无执行权限"></a>

### ADR-006：AI 無執行權限

狀態：已固定的產品邊界。

原因：用戶要求實時建議但不能幹預。建議應用是一種受限配置變更，不接收任意命令；執行和外部動作走獨立用戶入口。風險是自然語言工具調用繞過邊界，須通過服務端白名單與合同測試阻止。

<a id="adr-007实验产物采用不可变版本"></a>

### ADR-007：實驗產物採用不可變版本

狀態：建議採用，與可追溯目標一致。

原因：失敗重試、量化、轉換和合併都會產生新的實驗分支。覆蓋同一路徑會損壞證據鏈。風險是磁盤佔用上升，通過內容去重、引用和明確清理處理，而不是覆蓋舊產物。

<a id="adr-008工作流执行身份与步骤推进原子化"></a>

### ADR-008：工作流執行身份與步驟推進原子化

狀態：納入規範，待實現；回應 AUD-01、AUD-02。

工作流定義可以復用，每次執行和步驟嘗試必須獨立編號並綁定輸入版本。進入下一步前先檢查目標是否可用，再原子保存狀態。舊結果復用是顯式操作。採用同一領域事務完成即可，首期不引入獨立分布式工作流平台。

<a id="adr-009不可变计算尝试与可补收产物分开"></a>

### ADR-009：不可變計算嘗試與可補收產物分開

狀態：納入規範，待實現；回應 AUD-07、AUD-08。

暫停／取消等控制按執行器證據和狀態版本裁決，停止未知不能冒充成功。原執行嘗試終態不改寫，產物補收使用獨立記錄，只傳輸、校驗和登記已有文件，不觸發訓練重算。具體字段與例外以 05、07 為準。

<a id="adr-010阶段验证和最终产品验收分开"></a>

### ADR-010：階段驗證和最終產品驗收分開

狀態：納入計劃；回應 AUD-12。

M0 用 TV-01—TV-03 完成組合、側進程和最小 LoRA 回程試驗；M1—M6 採用明確的階段門檻。工作包的最終 AC 列表示追蹤歸屬，只有階段驗收要求的子集才影響該階段完成，禁止 M0 依賴 M6 安裝包。M0 通過後仍需鎖定模型、設備、人員與版本，不能直接宣佈完整產品可交付。

<a id="adr-011监督配方加载信任和缓存身份显式化"></a>

### ADR-011：監督配方、加載信任和緩存身份顯式化

狀態：納入規範，待適配驗證；回應 AUD-09—AUD-11。

SFT 固定分詞與損失計算策略；媒體參與緩存身份；模型導入計劃記錄具體格式、加載方式與信任類別。這些規則屬於適配器合同，普通用戶可以通過已說明的模板使用，不要求用戶逐個填寫底層字段。

<a id="adr-012常用预设和首次路径采用小范围增强"></a>

### ADR-012：常用預設和首次路徑採用小範圍增強

狀態：納入計劃；回應 E-01—E-05。

保留四類結構，補直接試用與最近運行；常用預設限模型默認、低內存、低延遲，效果需驗證；M0 前移實際 LoRA 回程試驗；結果修訂與生成配方分開。原型和測試歸入團隊固定目錄安排在 WP-04，遷移先核對清單和摘要並保留舊資產。本輪僅歸檔文檔，不遷移或刪除原型。

<a id="3-风险登记"></a>

## 3. 風險登記

| 風險 | 影響 | 早期信號 | 緩解辦法 | 責任／階段 |
| --- | --- | --- | --- | --- |
| 組合數量過大 | 排期失控、界面假支持 | 新增開關多於真實報告 | 按模型×引擎×設備分項，限制每階段目標 | 產品 + ML／全程 |
| 上游接口變化 | 訓練／推理失效 | 同一配置升級後行為變化 | 鎖版本、合同適配、保留舊環境 | ML／M0—M6 |
| 依賴衝突 | 安裝和運行不穩定 | 一個環境升級破壞另一個 | 獨立環境和摘要，不使用全局任意依賴 | 平台／M1—M2 |
| 多媒體流程只剩形式 | 用戶無法得到真實產物 | 只有預置圖／音頻或文件元數據 | 真解碼、真生成、獨立播放與質量驗收 | ML + 測試／M4 |
| 模擬狀態進入生產 | 虛假完成、虛假測速 | 連接即成功、計時器即完成 | 演示隔離，生產路徑禁止模擬成功函數 | 後端 + 測試／M1—M6 |
| 數據或版本覆蓋 | 結果不可追溯 | 舊任務指向變化的文件 | 不可變版本、摘要、事務和引用 | 後端／M1 |
| 檢查點不能真實恢復 | 長任務丟失 | 只保存權重卻顯示繼續訓練 | 聲明恢復範圍，保存優化器和隨機狀態 | ML／M3 |
| 優化有速度無質量保證 | 模型效果退化 | 只報告 tokens/s | 同時比較質量、內存、接受率與總延遲 | ML + 測試／M5 |
| ANE／NPU 使用被誇大 | 誤導兼容聲明 | 選擇後端即顯示硬件已使用 | 區分允許計算單元與真實執行證據 | 平台／M5 |
| 遠程斷連重復執行 | 資源重復消耗 | 超時即再次提交 | 冪等鍵、遠端持久狀態與先查後重試 | 後端／M2 |
| AI 覆蓋用戶設置 | 違背控制邊界 | 未點擊應用字段就變化 | 建議草稿、舊值校驗、原子應用 | AI + 測試／M3 |
| 大文件與磁盤耗盡 | 應用不可用、產物損壞 | 緩存與作品共用無配額空間 | 空間預檢、分區統計、可恢復清理 | 平台／M1—M6 |
| 研究方法來源不明 | 無法適配或發佈 | 只有方法名、沒有固定項目版本 | 分項核查源碼、依賴、輸入和許可材料 | ML／M5 |
| 舊選擇影響新任務 | 可見控件與提交內容不同 | 換策略、模型或格式後舊值仍生效 | 下游失效、差異預覽、服務端雙向校驗；工作流原子推進 | 前端 + 後端／M1—M5 |
| 監督目標不確定 | 數據相同卻訓練不同目標 | 僅檢查 JSON，沒有有效 labels 統計 | 版本化監督配方、超長與空監督負例 | ML／M3 |
| 補收演變成重算 | 重復花費算力 | 文件傳輸失敗只能重新訓練 | 獨立 collection、同源 manifest、計算次數驗收 | 後端 + 平台／M1—M3 |
| 檢查器假一致 | 編號齊全但任務漏做 | 錯配關係和週期仍通過 | 直接需求覆蓋矩陣、實際數字與依賴檢查、語義負例 | 測試 + 產品／本輪起 |

<a id="5-不应继续沿用的原型简化"></a>

## 5. 不應繼續沿用的原型簡化

固定進度條、預置模型輸出、單一圖片素材、模擬訪問批准、連接按鈕直接置 ready、以人工選擇生成評測通過、所有字段放進一個無類型對象、靜態硬件廠商模板、任意模型使用相同採樣器。

這些簡化適合演示界面，不適合正式執行。具體差距和工作包見 [14](14-prototype-traceability.md)。發現差距時優先修正執行語義，不重新擴張信息架構。

## 6. 決策維護

新決策記錄問題、可選方案、推薦依據、試驗結果、結論、負責人和日期。被替代的決策保留歷史和原因。產品需求變化需要更新關聯工作包與驗收；僅上游版本升級則更新環境、能力和受影響測試，不默認修改產品範圍。

本輪問題處理詳見 [16 審計整改與需求追蹤](16-audit-remediation-plan.md)。文檔已補齊不能關閉實現風險；只有對應代碼或流程修改、回歸證據和驗收記錄齊全，才把實現狀態改為已完成。歷史依據保留在 [1.0 歸檔](archive/v1.0-2026-09-09/README.md)與審計報告。
