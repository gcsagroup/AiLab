## 3. 文檔工具的代表性測試

**21 項測試全部通過。** 正常基線和新加一份合法文檔應通過；其餘反例應被拒絕並給出對應錯誤。所有變更只發生在臨時副本，測試前後核對原始文檔摘要不變。

- 保留編號但把 WP-14 改成錯誤需求／驗收關係，必須報錯。
- 修改 M1 週期卻保留舊累計數字，必須報錯；M0 誤用最終 AC 也必須報錯。
- 缺失整改映射、普通導出被診斷包替代、缺少直接需求覆蓋、虛構產品已修狀態，必須報錯。
- 依賴成環、引用不存在子項、早期任務依賴後期任務、復合依賴未指明子交付，必須報錯。
- 斷鏈、越界行號、壞 JSON、表格列數、未閉合代碼塊和歸檔被修改，必須報錯。

這補上原 AUD-14 中“編號齊全但關係錯誤”“週期改變但檢查仍通過”的盲區。工具報告規則一致性；正式變更仍需人工復核語義，不能用多張表同步寫錯來替代產品判斷。

<a id="4-合同与计划交叉复核"></a>

## 4. 合同與計劃交叉復核

本輪復核了以下跨文檔關係，修訂目標均有工作包與驗收承接：

- 工作流執行、步驟與輸入版本綁定；目標佔用與推進原子處理；舊結果只經明確操作復用。
- 模型、任務模式、輸入媒體、產物格式、引擎和推測組件聯動失效；顯示位置與實際提交配置同源。
- 暫停失敗、暫停中取消、取消中崩潰和收集階段取消有明確處理；狀態未知不得偽報已停止。
- 計算結果、嘗試終態和獨立補收記錄分開；補收不得重算，原失敗／取消事實與舊評測保留。
- SFT 的分詞／模板／監督範圍、EOS／PAD、截斷與拼接版本固定；有效 labels 是訓練前檢查對象。
- 模型導入識別實際加載方式與信任類別，不因受限加載失敗自動降級為執行未知代碼。
- 作品人工修訂保留獨立版本；普通產物導出與診斷包分別實施和驗收。
- M0 技術試驗不依賴 M3 訓練產品或 M6 發佈；同份 LoRA 跨端試驗、首次用戶流程和正式導出有獨立驗收。

狀態圖的 7 條關鍵異常轉移及 3 個刪邊反例通過文本檢查；5 個執行控制接口具有版本和冪等約定。兩張 Mermaid 圖僅做文本結構與合同復核，未計為視覺渲染通過；上述檢查均不是真實執行器故障注入。
