# 測試策略與驗收標準

版本：1.1 · 日期：2026-09-09 · 狀態：已按審計補充反例、技術試驗和分階段驗收；真實產品測試仍為待執行計劃。

相關文檔：[需求](01-product-requirements.md)、[工作包](10-work-breakdown.md)、[發佈](12-operations-and-release.md)、[原型證據](14-prototype-traceability.md)、[整改追蹤](16-audit-remediation-plan.md)。

<a id="1-证据层级"></a>

## 1. 證據層級

| 層級 | 能證明什麼 | 不能證明什麼 |
| --- | --- | --- |
| 文檔與靜態檢查 | 鏈接、示例和編號結構；可解析關係、階段依賴及指定負例 | 應用實際可運行、全部自然語言語義正確 |
| 原型狀態測試 | 模擬狀態、部分校驗和交互意圖 | 真實執行、持久化與性能 |
| 單元／合同測試 | 規則、接口、狀態、參數映射 | 實際驅動、模型加載或最終體驗 |
| 集成測試 | 數據庫、進程、文件、服務交互 | 所有硬件與模型通用支持 |
| 實機測試 | 指定組合的真實執行和指標 | 未測試版本和其他設備 |
| 用戶端到端驗收 | 真實入口到最終產物的完整任務 | 對外發佈、升級等未執行流程 |
| 發佈驗收 | 具體安裝包和支持矩陣可交付 | 未來版本自動繼承通過 |

測試報告必須標明層級、輸入、環境、版本、執行時間、結果與限制。原型測試和模擬執行不得進入真實性能統計。

<a id="3-测试环境与数据"></a>

## 3. 測試環境與數據

<a id="31-最小设备池"></a>

### 3.1 最小設備池

- 一台明確型號與統一內存大小的 Apple Silicon Mac。
- 一台明確 GPU、顯存、系統和驅動版本的 NVIDIA Linux 機器。
- M5 擴展時提供明確型號的 AMD GPU 和 Intel GPU／NPU 設備。
- 一台乾淨安裝／升級測試環境；可使用獨立用戶賬戶或虛擬機，但 GPU 功能驗收必須有實際適用設備。

每次報告保存 CPU、GPU／NPU、內存、系統、驅動、引擎、模型、精度、存儲、網絡和電源狀態。設備不可用時標記未測，不以其他廠商機器代替。

<a id="32-数据夹具"></a>

### 3.2 數據夾具

準備小型可公開文本、圖像、短視頻和音頻樣例，並附來源記錄。正常數據與負例分別管理，負例包含缺字段、損壞文件、空內容、重復、過長輸入、越界切片、錯採樣率、變幀率和模型不兼容。

功能性小樣本用於檢查鏈路，質量評測集用於檢查效果，二者分開。不得把訓練中使用的樣本直接當獨立測試集。近重復分組信息與劃分種子固定保存。

<a id="4-核心验收用例"></a>

## 4. 核心驗收用例

<a id="ac-01项目与草稿持久化"></a>

### AC-01：項目與草稿持久化

前置：兩個項目，各有語言和圖片草稿。操作：編輯、切換項目、關閉應用、重啓。預期：任務編號、字段、選中對象和歷史按項目恢復；後台結果歸屬原項目。證據：數據庫記錄、應用操作錄像或截圖、相關事件。覆蓋 PRD-001、PRD-018。

<a id="ac-02四类入口与继续任务"></a>

### AC-02：四類入口與繼續任務

從首頁逐類進入，恢復草稿、新建任務、查看運行和評測，再返回首頁。預期：入口清楚、狀態按鈕指向下一步，無重復訓練入口或錯誤類別。不能只檢查路由存在。覆蓋 PRD-002、PRD-020。

<a id="ac-03模型准备信任与独立加载"></a>

### AC-03：模型準備、信任與獨立加載

使用固定模型 revision，下載、暫停／恢復（支持時）、取消、重試，並加入損壞文件、格式偽裝、受限加載失敗、不受信任 pickle／檢查點、TorchScript 和需要自定義代碼的模型。核對 ModelImportPlan 中聲明的格式、加載方式、信任類別、依賴及隔離邊界。預期：完整性通過不能替代信任判斷；受限加載失敗不得自動降級為任意反序列化；需要執行能力時按明確決定限制文件、網絡、憑證，隔離效果有記錄。完成後在獨立進程按聲明加載方式加載，適配器缺基座時指出具體依賴。使用無害受控夾具測試，不執行來源未知的惡意模型。覆蓋 PRD-003。對應 AUD-11。

<a id="ac-04数据导入检查与监督配方"></a>

### AC-04：數據導入、檢查與監督配方

導入正常 JSONL 與四類負例，檢查行號、媒體、重復和劃分；應用排除／重採樣後原件摘要不變，新版本可追溯。對多輪、超長回答、空回答、僅系統消息、padding、packing 邊界和多模態樣本輸出最終 tokens／labels，核對 tokenizer／processor／模板、assistant-only 或 completion-only、EOS／PAD、截斷和邊界策略。預期：有效監督 token、截斷和丟棄樣本統計可解釋；零監督樣本必須排除，訓練集或必需驗證集過濾後無有效監督則阻斷任務；數據或監督配方版本改變使舊檢查失效。覆蓋 PRD-004。對應 AUD-10。

<a id="ac-05市场访问与返回原任务"></a>

### AC-05：市場訪問與返回原任務

從已有訓練草稿進入市場，分別完成開放下載、受限申請、拒絕、通過、下載和選擇數據。預期：錯誤 schema 不能使用；返回後原名稱、參數、項目和步驟保留；訪問獲准不出現授權代判標籤。覆蓋 PRD-005。

<a id="ac-06训练方法更新方式与监督目标"></a>

### AC-06：訓練方法、更新方式與監督目標

對每個開放組合運行最小真實訓練，至少包含首期 SFT + LoRA。驗證目標模塊、數據 schema、監督配方、最終 tokens／labels、優化步數和權重變化；對支持同一配方的適配器核對監督範圍等價，不依賴各庫默認值。模型／任務模式變化使不兼容訓練輸入或舊檢查失效；服務端拒絕偽造模式、不支持的 QLoRA／精度／設備與零有效監督數據。新增訓練方法逐項增加用例。覆蓋 PRD-006。對應 AUD-04、AUD-10。

<a id="ac-07任务生命周期与异常出口"></a>

### AC-07：任務生命週期與異常出口

逐行執行 [07 狀態表](07-api-and-task-lifecycle.md)，覆蓋排隊、準備、運行、收集、取消、失敗、檢查點及可用時暫停／恢復。注入暫停檢查點失敗、pausing 時取消、cancelling 時執行器崩潰、finalizing 時取消收集、控制超時和強制停止失敗；核對狀態、允許動作、錯誤、恢復入口與事件。停止證據缺失時 `stop_status=unknown`，界面不能宣稱已停止或可安全重開。失敗重試建立新計算嘗試，舊記錄保留；恢復包含已約定的訓練狀態，不能僅加載權重後偽稱原軌跡繼續。覆蓋 PRD-007。對應 AUD-07、AUD-08。

<a id="ac-08真实运行模型模式与结果"></a>

### AC-08：真實運行、模型模式與結果

文字生成、圖像生成、視頻生成、TTS／ASR 按已開放能力實際執行。測試音頻能力模型切到純視覺模型及反向切換，帶圖片／視頻／錄音時分別換模型；界面選擇值、已應用模式、媒體輸入與提交快照一致，不兼容項明確重置並說明，偽造舊模式請求由服務端拒絕。真實輸入必須被使用，輸出文件能獨立讀取，最終結果與歷史一致，不能以預置媒體替代真實產物。覆蓋 PRD-008。對應 AUD-04。

<a id="ac-09运行参数执行位置与预设"></a>

### AC-09：運行參數、執行位置與預設

測試關閉思考、上下文、輸出限制、採樣、停止詞和流式，比較界面、已應用配置、請求快照、後端實際參數及觀察結果；超預算拒絕／裁剪符合用戶選擇。覆蓋默認本機／本次雲端、默認雲端／本次本機與配方重載，按鈕旁位置、參數摘要和發送範圍都來自本次已應用配置。逐一使用“模型默認、低內存、低延遲”預設，應用前可看實際字段差異，取消不變；換模型／設備後失效值與需重載項有說明，未經測量不宣稱加速。運行中不能修改快照。覆蓋 PRD-009。對應 AUD-06、E-02。

<a id="ac-10缓存prefill-与-decode"></a>

### AC-10：緩存、Prefill 與 Decode

固定模型與輸入，驗證緩存隔離、失效、KV dtype、分塊、批處理、併發和 CUDA Graph。相同文字換圖片／視頻／音頻，或相同媒體改變順序、裁剪、抽幀、採樣、processor 版本時不得錯誤命中；保存媒體內容或編碼摘要、處理器與預處理參數的身份條件。委託底層緩存時驗證適配器實際保證這些條件，不增加弱化的應用層緩存；未知組合關閉。引擎不支持字段時拒絕，不能丟參。分離部署缺連接器時阻斷；實現後注入傳輸和模型版本錯配。覆蓋 PRD-010。對應 AUD-09。

<a id="ac-11推测解码配对"></a>

### AC-11：推測解碼配對

分別測試普通草稿、MTP、DFlash 正常和不匹配輸入，覆蓋普通草稿與 DFlash 雙向切換、準備前後換模型／引擎／模板／思考條件、直接提交舊配置。準備狀態屬於目標模型、策略、組件和引擎的確定組合，失配後清除並阻斷準備／應用／提交；不能繼承一個獨立 `draftReady` 布爾值。MTP 缺組件、DFlash 配套錯配均拒絕；正確組合測正確性、接受率和延遲。覆蓋 PRD-011。對應 AUD-03。

<a id="ac-12设备与引擎适配"></a>

### AC-12：設備與引擎適配

逐個登記真實設備，驗證可達、探測、依賴、加載和運行狀態分離。NVIDIA、Apple、AMD、Intel、CPU 分別保存報告；同品牌不同系統不自動繼承支持。覆蓋 PRD-012。

<a id="ac-13媒体参数与-core-mlane"></a>

### AC-13：媒體參數與 Core ML／ANE

圖片檢查調度器、CFG、VAE 和卸載；視頻檢查幀率、幀數、時長與切片；音頻檢查採樣率、切片、流式塊和轉寫。從轉換候選的“運行”入口走完默認配置與加載鏈，格式參與引擎選擇，來源配置失效時不能繼承；原始權重→不支持的 Core ML 引擎、Core ML 產物→不支持該格式的 PyTorch 路徑兩個方向都拒絕。橋接轉換須作為顯式準備步驟並留摘要鏈。只有具備實際分配證據才聲明 ANE 使用。覆蓋 PRD-008、PRD-012、PRD-013。對應 AUD-05。

<a id="ac-14评测与候选准入"></a>

### AC-14：評測與候選准入

基線和候選使用固定數據與規則，注入一個不達標候選和一個損壞產物。預期：不能登記為可用模型；通過候選可獨立加載試用，來源實驗可返回；重復登記冪等。覆蓋 PRD-014。

<a id="ac-15ai-建议模式"></a>

### AC-15：AI 建議模式

檢查建議生成不修改、應用只改白名單、過期 revision 拒絕、撤銷不覆蓋後改、提交後只讀、惡意材料無執行權。核對遠程請求範圍與來源問題回答邊界。覆蓋 PRD-017。

<a id="ac-16作品生成配方与结果修订"></a>

### AC-16：作品、生成配方與結果修訂

保存產物後關閉應用，重新打開並載入配方，換模型版本／設備後檢查差異提示。輸入、產物、基座／適配器、參數和來源均可找到；收藏與文件保存不混淆。編輯轉寫／字幕產生 WorkRevision，可查看原文、修訂、父版本與差異；job.snapshot、原生成配方和原輸出保持不變。重新生成只復用生成參數，不隱含帶入人工修訂；導出能明確選擇原版或修訂版。覆蓋 PRD-016。對應 E-04。

<a id="ac-17完整媒体工作流与原子推进"></a>

### AC-17：完整媒體工作流與原子推進

真實執行兩輪圖片 → 視頻 → 配音，保存 WorkflowRun id／revision、step attempt 和 input revision。第二輪修改輸入後零次生成，默認不得用上一輪結果推進；顯式復用須由用戶選擇並記錄源執行／產物，修改上游使舊下游標記失效。

分別在目標類別運行中、暫停中、恰好完成、恰好取消時推進。目標佔用檢查失敗，步驟、輸出集合與源草稿均不變；查看阻塞任務、等待或退出可用，解除阻塞後一次點擊只推進一次。注入中途失敗並重做，前序產物保留、輸入與來源版本完整，最終媒體獨立可打開。沒有合成能力不得稱最終成片。覆蓋 PRD-015。對應 AUD-01、AUD-02。

<a id="ac-18故障恢复与只补收"></a>

### AC-18：故障恢復與只補收

在運行、寫文件、提交事務和事件發送時終止進程，模擬磁盤滿與遠端斷開。重啓後無重復計算、不丟已提交記錄、不把部分文件標完整；任務狀態未知時重連核對。另在計算完成、遠端產物完整後注入本地磁盤滿、傳輸中斷、資產登記事務失敗，通過 `POST /attempts/{id}/collections` 只補收：復用原 manifest，`run`／`resume` 調用次數不增加，文件摘要相同，資產只登記一次。原 RunAttempt 的失敗終態和計算結果保留，新 collection 記錄恢復經過與狀態，不能偽裝為重新計算成功。覆蓋 PRD-018。對應 AUD-07、AUD-08。

<a id="ac-19模型实验室与转换候选试用"></a>

### AC-19：模型實驗室與轉換候選試用

對已開放合併、蒸餾、量化、轉換和行為對照逐項執行，檢查輸入兼容、候選獨立、產物摘要、質量回歸和來源鏈。轉換候選從實際入口選擇與格式匹配的引擎再獨立運行；原引擎不兼容時必須失效，正反兩類格式錯配與缺橋接步驟均阻斷。導出轉換產物由 WP-29 的通用導出器承接，轉換測試不替代導出驗收。自研未實現入口不可啓動。覆蓋 PRD-013。對應 AUD-05。

<a id="ac-20幂等与竞争"></a>

### AC-20：冪等與競爭

覆蓋雙擊提交、同冪等鍵重發、不同內容復用鍵、過期狀態版本、暫停／取消／恢復／force-stop 重發、取消與完成競爭、AI 與手工編輯競爭、重復終態和斷連事件補拉。工作流推進與目標佔用變化、重復 advance、舊輸入 revision 也必須原子裁決。預期：合法單次執行，舊請求明確衝突，失敗事務不留下半推進，數據庫與界面一致；停止確認未知不能裁決為已停止。補收重復請求只產生約定收集記錄及一次資產登記。覆蓋 PRD-007、PRD-015、PRD-018。對應 AUD-02、AUD-07、AUD-08。

<a id="ac-21远程执行目的地与输入边界"></a>

### AC-21：遠程執行、目的地與輸入邊界

測試遠端身份不符、憑證失效、上傳中斷、相同文件去重、運行斷連和日誌補拉。默認本機／單次雲端、默認雲端／單次本機、配方重載時，摘要、按鈕旁位置、發送範圍和實際目的地一致，不靜默改地址。上傳和模型加載遵守已決定信任範圍；受限加載失敗不擴大執行權限。取消後失聯保留停止結果未知，不重復啓動；計算已完成而收集失敗時只補傳校驗登記，不重新計算。診斷數據無明文密鑰。覆蓋 PRD-012、PRD-018。對應 AUD-06、AUD-08、AUD-11。

<a id="ac-22安装升级备份与导出回归"></a>

### AC-22：安裝、升級、備份與導出回歸

在乾淨環境安裝具體候選包，升級含歷史任務的舊版本，回滾一次失敗遷移並恢復備份；核對安裝身份、依賴版本、舊任務與原產物。升級／恢復後按 AC-27 重新導出並獨立驗證文件，診斷包另行驗證脫敏；卸載不等同刪除模型數據。此前 M3／M4 的導出子項通過不代表候選包升級驗收已通過；本用例不作為 M0 殼側進程試驗前置。覆蓋 PRD-018、PRD-019。對應 AUD-12、AUD-13。

<a id="ac-23界面键盘与外观"></a>

### AC-23：界面、鍵盤與外觀

檢查 1024、736、360 px 深淺色、最小 320 px，表單標籤、焦點、彈窗、錯誤關聯、長名稱、中文路徑、空態和大列表。用鍵盤完成一條任務；不能以靜態截圖代替關鍵交互。另從固定項目位置按清單核驗確認版本的 Demo、測試和檢查器摘要，新成員按復跑說明可打開相同界面、運行指定檢查並理解已知問題；M1 整理資產，M6 使用新成員視角驗證，歷史文件保留。覆蓋 PRD-002、PRD-020。對應 E-05。

<a id="ac-24性能与质量对照"></a>

### AC-24：性能與質量對照

對每個宣傳的優化執行關閉／開啓對照，固定負載、精度和環境，記錄冷／熱、併發、內存與質量。結果包含無收益或變慢情況，不篩選最好樣本作為普遍結論。覆蓋 PRD-010、PRD-011、PRD-012。

<a id="ac-25首次用户零资源到首次结果"></a>

### AC-25：首次用戶零資源到首次結果

由 5 名目標用戶分別使用乾淨安裝、沒有預置模型／項目／數據／歷史的環境，從首頁選擇類別內“直接試用”，完成創建項目、選擇首期支持模型、準備依賴、檢查設備、輸入樣例、生成首次真實結果、保存並在重啓後繼續。允許產品內幫助，不依賴開發文檔或開發者代填步驟。記錄每人的成功／失敗、阻塞、人工幫助、耗時與產物；5 人均能完成且無阻斷問題才通過，小樣本結果不外推為全部用戶可用性結論。斷網或資源不足應有可理解的恢復入口，不能用預置資源偽稱零資源路徑。完整驗收使用 M6 候選包，M2 只做首條已接入語言路徑的階段預演。覆蓋 PRD-002、PRD-020。對應 E-01。

<a id="ac-26同一-lora-产物跨端试用"></a>

### AC-26：同一 LoRA 產物跨端試用

在指定 NVIDIA 訓練組合完成真實 SFT + LoRA，經評測登記後，將同一份適配器送至指定 Apple 目標引擎試用；記錄基座 revision、目標模塊、適配器摘要、tokenizer／模板、精度、引擎和硬件。無轉換時摘要保持相同；必須轉換時保留輸入／輸出摘要及可復跑轉換鏈，不能另訓一個相似模型代替。通過產品候選入口和獨立加載分別驗證指定樣例，對照無適配器／有適配器結果及預先確定的兼容、質量標準；從導出包恢復鏈路也可復現。錯誤基座、缺依賴、錯格式和不匹配模塊必須阻斷。M0 的 TV-03 只證明所選技術路徑，本用例在 M3 完整產品鏈路首次執行，M6 對凍結髮布組合回歸。覆蓋 PRD-006、PRD-008、PRD-012、PRD-014、PRD-019。對應 E-03。

<a id="ac-27模型适配器作品与报告导出"></a>

### AC-27：模型、適配器、作品與報告導出

每類各選真實對象：模型、LoRA 適配器、圖片／視頻／音頻作品、評測報告，從普通用戶入口選擇範圍／版本與目標路徑，檢查依賴解析、manifest、摘要、完整落盤和獨立使用。適配器包記錄精確基座依賴與缺失提示，不默認包含無權分發的基座；媒體獨立打開，修訂版與原生成配方可區分；報告能追蹤模型、數據、評測規則和結果。

注入缺文件、磁盤滿、取消、摘要不符與中斷恢復：臨時／部分包不顯示成功，完整性通過後才發佈最終包；恢復不觸發訓練或推理重算，源資產不變。M3 驗模型／適配器／文本作品／報告，M4 增加媒體，M5 增加本版轉換格式，M6 在升級／恢復後的同一候選包回歸全部適用對象。診斷包不能替代本用例。覆蓋 PRD-019。對應 AUD-13、E-04。

<a id="5-性能测试方法"></a>

## 5. 性能測試方法

<a id="51-基准条件"></a>

### 5.1 基準條件

每個配置至少包含短、中、長輸入和單請求／多請求兩組負載。正式輸入長度由參考模型能力決定，並記錄精確 token 數。冷加載與熱運行分開；穩定性測試至少 30 個固定請求，必要時重復 3 輪；首輪編譯和模型下載單獨計時。

採樣參數、輸出長度限制、停止條件、種子、緩存命中條件和併發必須相同。比較不同量化或不同精度時明確它們改變了計算條件，並同時報告質量。

<a id="52-指标口径"></a>

### 5.2 指標口徑

| 指標 | 口徑 |
| --- | --- |
| 端到端延遲 | 客戶端提交到最終結果完成；包含傳輸和排隊 |
| 首 token 延遲 | 提交到首個輸出 token；單獨注明是否包含模型加載 |
| Prefill 速度 | 輸入 token 數／實際 Prefill 時長；僅引擎能明確歸因時報告 |
| Decode 速度 | 首 token 之後的生成 token 數／對應生成時長；1 token 輸出不計算 |
| 總吞吐 | 測試窗口實際完成 token 或請求數／窗口時長 |
| 峰值內存 | 測量工具記錄的峰值；顯存／統一內存／進程內存分別列出 |
| 緩存命中 | 引擎實際命中統計；沒有觀測接口則標未知 |
| 草稿接受率 | 被接受的草稿 token／提出的草稿 token，口徑與引擎報告對應 |
| 質量變化 | 固定樣本與規則下的候選和基線差異 |

不以字符數直接冒充 token 數，不以第一段響應提前返回證明完整推理更快，不以單次最好結果替代中位數和 p95。

<a id="6-训练质量验收"></a>

## 6. 訓練質量驗收

功能驗收與模型質量驗收分別報告。功能驗收要求參數更新、檢查點完整、可恢復、產物可加載；質量驗收要求固定業務／回歸樣本、合理閾值、樣本量與人工評審。

閾值在測試前確定，按任務分別制定。無法統一自動評分時保留逐樣本結果和評審說明，不用一個無來源分數掩蓋差異。損失下降、獎勵升高不單獨構成通過。

<a id="7-自动化分层"></a>

## 7. 自動化分層

- 文檔層：解析實際 PRD → 工作包 → AC 關係、交付對象、階段與子項依賴、參考週期和審計映射；結構檢查與自然語言內容審查分別報告。
- 單元層：參數 schema、版本、數據劃分、監督 tokens／labels、狀態轉移、WorkflowRun 身份與輸入版本、建議應用和含媒體身份的緩存鍵。
- 合同層：請求／響應、錯誤代碼、冪等、事件順序、執行器能力。
- 集成層：真實 SQLite、臨時目錄、進程、文件校驗和受控遠程服務。
- 模型層：小模型／小樣本真實運行，檢查權重和輸出，不使用大模型佔滿常規 CI。
- 設備層：帶標籤的專用機器執行已安排矩陣，產物與報告關聯提交版本。
- 端到端層：瀏覽器／桌面真實操作完成用戶路徑。
