# GCSA AI Lab 用戶操作手冊

[簡體中文](../../../docs/USER_GUIDE.zh-CN.md) · [繁體中文](USER_GUIDE.zh-CN.md) · [English](../../en/docs/USER_GUIDE.zh-CN.md)

本手冊對應當前公司簽名候選 Ver2.4（031）。可以繼續既有任務、查看和編輯作品修訂、載入更早歷史，並導出明確選擇的版本。正文與配音文案各支援最多 16000 字元，字幕最多 200 條。029 已接受 Media 三入口在兩個既有任務中的四個原生實例、正反向 Tab、Enter／Escape 回焦、正常退出與一次停機讀回的有限子集（E137）；沒有執行真實導入或模型運行。028 工作台四按鈕的既有的有限接受保留。詳見[028進度](implementation/2026-09-15-ver2-4-028-workbench-keyboard-progress.md)、[Media進度](implementation/2026-09-15-media-keyboard-progress.md)和[候選範圍](implementation/2026-09-10-ver2-scope.md)。

031 的原生檔案匯入已用 3 條 JSONL 實際驗證，但 Python 環境選擇存在已知問題：選中 venv 的 Python 後，確認框可能顯示基礎直譯器路徑。若顯示路徑與所選環境不一致，請取消，不要確認儲存。本輪已取消且未變更環境，三環境儲存、同號重新開啟、恢復內建及診斷匯出尚未完成。[031 進度與負例](implementation/2026-09-16-ver2-4-031-native-picker-progress.md)

030 的工作庫連線隔離修復已通過原始碼、簽章包和兩項包內真實控制服務測試。切換或重新啟動時，舊連線的一般 API 請求和媒體讀取會失效，寫入不會自動向新庫重送；請等待目前連線恢復後再操作。原生備份、目標庫啟動失敗復原、成功切庫、分別儲存專案及同號重新開啟的有限子集已獲根接受；檔案、目錄和 Python 環境選擇器的非同步競態未涵蓋。[030 進度](implementation/2026-09-16-ver2-4-030-connection-isolation.md)

可以使用 Tab、Shift-Tab、Return 和 Escape 操作已覆蓋的鍵盤路徑。027 的文字原作品純鍵盤導出與同號重開、028 的工作台四按鈕原生路徑均為有限驗收，不代表所有頁面和任務已經完成鍵盤驗收。011 曾在開啓 macOS“鍵盤導航”後檢查彈窗焦點並恢復原設置，該條件僅屬於[011歷史記錄](implementation/2026-09-13-ver2-2-011-progress.md)。

011 的窄屏、獨立空庫、隱藏重開和初顯計時保留歷史歸屬，不轉記為 028 性能結論。界面出現後，運行前仍須等待相應檢查完成。020 曾出現的長列表空白尚未定位；指定設備、跨主機、乾淨安裝、達標質量和五名首次用戶等完整驗收仍未完成，詳見[交付矩陣](implementation/2026-09-10-current-delivery-matrix.md)。

來源組劃分從 Ver2.2（006）候選開始提供，005 不包含此功能。下文相關步驟已用七行原件及真實 tokenizer 完成[指定原生流程驗收（E72）](implementation/2026-09-10-current-delivery-matrix.md)，包括完整備份恢復後繼續原預覽。此次不加載模型訓練，不代表模型質量或驗證損失通過。

<a id="1-获得第一个结果"></a>

## 1. 獲得第一個結果

1. 打開 App，新建項目。項目分別保存模型、任務、數據和作品。
2. 在首次使用引導中選擇“準備官方語言模型”，查看來源、許可、固定版本和下載清單後開始下載。當前固定語言模型約 953.3 MB，界面建議預留約 2 GiB。
3. 下載中斷後，在“模型庫 → 模型準備記錄”打開同一條記錄並繼續。已下載的有效文件保留；文件完整後仍需點擊“加入當前項目模型庫”。
4. 選擇“用此模型開始試用”，或在引導中建立示例草稿。示例是一段可修改的普通文字輸入。
5. 點擊“檢查配置”，確認模型、設備和配置；檢查通過後點擊“開始運行”。下載、登記、保存草稿都不會自動運行模型。
6. 輸出完成後點擊“保存作品”。任務與原配方自動保留；作品可在“作品與素材”查看和導出。

無需首次下載也可使用“導入模型”，選擇已有的完整模型目錄。只有檢查通過的精確組合可運行；文件完整不代表回答質量通過。

<a id="2-修改任务与运行设置"></a>

## 2. 修改任務與運行設置

1. 在工作台選擇類別，再點擊“繼續上次運行”或“繼續上次訓練”；也可從“任務與結果”或右上角“任務隊列”打開指定任務。要建立另一份任務，使用“新建試用”或“新建訓練”。列表末尾的“加載更多任務”用於繼續查看更早記錄。
2. 修改輸入或展開“運行設置”。草稿會自動保存；若提示保存失敗，點擊“保存草稿”重試，確認顯示“草稿已保存”後繼續。舊結果仍對應原執行時的模型與參數。
3. 使用預設時，先選擇“運行預設”，點擊“預覽預設差異”，確認後選擇“應用到草稿”。應用只修改配置，不運行模型。
4. 點擊“檢查配置”，通過後再明確點擊“開始運行”或“開始訓練”。運行中、暫停中或停止狀態待覈實時，配置保持只讀；先處理原執行，再繼續修改。

語言生成可以設置最大輸出、溫度、Top-p、種子、上下文總預算、停止序列和流式顯示。上下文預算包括模板、輸入及最大輸出預留；超限時拒絕運行並保留輸入。當前只提供單條輸入，不裁剪歷史對話，固定 Qwen2.5 組合沒有思考開關。

停止序列每行一條，最多 8 條，每條最多 128 個字符。空行忽略，首尾空格保留；命中後停止且不顯示該序列。關閉流式只改變顯示時機，最終結果、運行狀態和停止操作仍保留。

默認配置優先用於建立基線；低內存預設可能讓首字更慢，低延遲效果取決於輸入和當前設備。4-bit KV 緩存的既有質量驗證失敗，當前不可選擇；它與模型權重量化是兩項不同功能。

<a id="3-微调与评测"></a>

## 3. 微調與評測

在語言或圖片工作台選擇“訓練 / 微調”，導入基座與數據，檢查樣本和參數後明確開始。語言當前為固定 SFT + LoRA；圖片當前為 Tiny-SD 的 LoRA。視頻和音頻訓練尚未開放。

005 候選已驗證的語言訓練表單從當前執行位置的配方讀取參數範圍，顯示默認來源、固定批量和步數停止條件。讀取配方不會檢查設備、連接遠端或覆蓋已填內容；讀取失敗或已有值超出當前範圍時，先修正或重新讀取，再檢查配置。當前本機與 NVIDIA 組合均最多200步、每設備批量1、梯度累積1、單個數據並行設備；NVIDIA學習率至少0.000001，LoRA Alpha必須是整數。本機保留自己的範圍，切換位置後不會把不兼容值靜默改小。

語言質量驗收應在訓練前創建並凍結評測計劃，再把計劃綁定到訓練草稿。評測集與訓練集分開，保留業務、格式、正常能力和目標行為四類問題。訓練完成只表示產生了獨立適配器；未達標準的產物仍是實驗適配器。

評測會分別加載基線與候選，顯示逐條輸出和判定。訓練後的臨時對照可用於分析，但不能代替預定准入計劃。只有通過預定門檻並明確登記後，才使用“質量通過”的候選；該結論僅覆蓋相應模型、評測集和設備。

支持暫停的訓練需等待界面確認暫停後再繼續。停止後若存在可用檢查點，可創建恢復任務；恢復任務保留來源和固定訓練配置。停止狀態待覈實時，先覈實或補收原運行，避免另起一份重復計算。

<a id="31-按来源组准备语言训练数据006-候选新增"></a>

### 3.1 按來源組準備語言訓練數據（006 候選新增）

原件使用 UTF-8 JSONL，每行只包含 `source_id` 和 `messages`。`source_id` 是非空來源標識；來自同一原始記錄的不同問答必須沿用同一個值，不能為了劃分給每條變體另編來源。同一來源組的有效樣本會完整留在訓練或驗證一側。下面三行展示兩條同源變體和一條獨立來源：

```jsonl
{"source_id":"订单-001","messages":[{"role":"user","content":"订单001什么时候发货？"},{"role":"assistant","content":"订单001将在周五发货。"}]}
{"source_id":"订单-001","messages":[{"role":"user","content":"请确认001号订单的发货日。"},{"role":"assistant","content":"发货日是周五。"}]}
{"source_id":"订单-002","messages":[{"role":"user","content":"订单002可以修改地址吗？"},{"role":"assistant","content":"订单002尚未发货，可以修改地址。"}]}
```

1. 在“數據集市場 → 我的數據”點擊“導入語言數據”，選擇原件；在原件卡片點擊“劃分訓練與驗證”。訓練草稿選擇原件後也有同名入口。
2. 選擇用於分詞檢查的模型、最大序列長度、固定劃分種子和驗證比例。當前支持固定 Qwen2.5-0.5B-Instruct 原權重的分詞資料；長度須與之後的訓練設置一致。
3. 點擊“檢查並預覽劃分”。檢查只在 CPU 上分詞和核對監督範圍，不加載模型權重、不訓練。查看有效及排除樣本、兩側來源組與樣本數、請求和實際驗證比例、排除原因及新增文件範圍；需要時展開最多三條詞元和監督標籤證據。
4. 確認沒有阻斷項後，點擊“應用劃分，生成新版本”。應用登記獨立的訓練子集、驗證子集和來源證明，原件保留；此時訓練草稿還沒有自動改變。
5. 在訓練草稿的劃分窗口點擊“使用訓練子集”，或從數據卡片的訓練子集點擊“用於訓練”。保存草稿，再“檢查配置”，最後明確開始訓練。其他已填參數保留，仍須滿足當前模型與執行位置的範圍。

新語言 SFT 訓練強制使用已應用劃分的訓練子集（`train`）。原件、驗證子集和未應用預覽都不能直接提交新訓練；換模型分詞資料或改變最大序列長度後，須從原件重新檢查與劃分。已有歷史檢查點只按它原來凍結的配置恢復，不因此獲得來源組隔離證明。

零監督、超長及不支持的媒體或工具樣本會先排除；超長樣本整條排除，不截短後混入訓練。至少要有兩個含有效樣本的獨立來源組，兩側均非空。劃分按組進行，實際樣本比例可能偏離請求；發現兩側存在規範化後完全相同的用戶提示詞會阻斷應用。語義近似去重尚未檢查，來源標識仍需由準備數據的人覈實。

驗證子集目前用於留出隔離和檢查，尚未計算驗證損失，也不代替獨立質量評測或證明模型質量。默認 NVIDIA 訓練上傳只包含訓練子集；劃分證明隨訓練配置固定。

<a id="32-找回预览与处理检查中断"></a>

### 3.2 找回預覽與處理檢查中斷

預覽準備好後可以關閉窗口；再次從原件打開“劃分訓練與驗證”，在“已有檢查與預覽”讀取原記錄。重啓或恢復工作庫後也從這裡繼續，讀取記錄不會重新分詞、應用或訓練。

檢查中需要停止時，點擊“取消本次檢查與預覽”，等待界面確認停止。若顯示“上次檢查被中斷”，先取消舊計劃並覈實結果；需要新檢查時再選擇“保留參數，重新預覽”。連接中斷後沿原記錄重新讀取或“重試上次操作”，避免反復新建。已應用結果若提示部分暫存尚未清理，可以“重試清理暫存”；正式子集已經登記，此操作不會生成第二份劃分。

<a id="4-图片视频配音与工作流"></a>

## 4. 圖片、視頻、配音與工作流

圖片使用文字描述生成；視頻使用已導入的 PNG 素材，或把已保存圖片用於視頻任務。當前固定視頻組合輸出約兩秒短片，既有樣例運動很弱。中文配音使用固定小北音色；生成文件可播放和導出，仍需自行檢查內容和發音。

商品工作流按圖片、視頻、配音分步執行。每步先檢查再開始，接受本輪結果後進入下一步；復用舊結果必須明確選擇並確認來源。修改上游後，下游會標記過期，需要重新檢查。整輪保存會分別保存三項作品，當前沒有合成一條帶配音成片的功能。

<a id="5-修订与导出"></a>

## 5. 修訂與導出

1. 在“作品與素材”的作品卡片點擊“文字修訂”“配音文案修訂”或“字幕修訂”。窗口默認查看當前版本，可在“查看作品版本”切換原版或已加載的修訂，查看正文、父版本和與父版本的差異。
2. 首次列出最近最多 100 條修訂。需要更早記錄時點擊“加載更早版本”，當前正在查看的版本保持；重復加載直到找到所需記錄。若提示作品已有新修訂，點擊“重新讀取作品版本”，再重新選擇要查看的版本。
3. 要編輯時，先選擇當前版本，再點擊“編輯當前版本”，焦點會到首個編輯字段；沒有字幕時到“添加字幕”。完成後選擇“保存獨立修訂版本”；不保留本次修改則選擇“取消本次編輯”，焦點回到編輯按鈕，可直接按 Return 重新編輯。保存會新增獨立版本，原版和舊修訂保留。若保存提示已有其他修訂，本次輸入仍保留；確認不再需要這些輸入後，才點擊“放棄本次編輯，讀取當前版本”。
4. 編輯中按 Escape 會顯示退出確認並聚焦“繼續核對”。按 Return 可返回之前仍可用的輸入；只有確認放棄時才選擇“放棄未保存編輯並關閉”。

| 內容 | 上限 |
| --- | --- |
| 文字正文、配音文案 | 各 16000 字符 |
| 單條字幕 | 500 字符 |
| 一份作品的全部字幕 | 最多 200 條，總文字最多 16000 字符 |

按界面顯示的字數核對；擴展漢字“𠮷”計一個字符。超限輸入不會被提前截斷，但保存前必須縮減到上限內。字幕開始與結束時間使用秒，須按時間排序、互不重疊，並位於原視頻時長內。

長字幕可逐頁滾動，也可收起“與父版本的差異”縮短內容。021 已核對展開／折疊差異時的逐頁、大幅和上下邊界滾動，背景作品頁保持原位，關閉後背景仍可滾動。020 曾出現的兩幀空白根因未定；若再次遇到，可先嘗試常規上、下一頁滾動並保留問題記錄，不能據此認定問題已修復。

文字修訂不改變原生成配方；配音文案修訂不改變聲音；字幕保存為獨立 VTT 文件，不燒錄進視頻。窗口內的播放器始終播放原始媒體。

導出修訂時，先在“查看作品版本”選定原版或某個修訂版，再點擊“導出所選原版”或“導出所選修訂版 N”；作品卡片上的“導出原作品”始終導出原版。選擇保存目錄、檢查文件範圍，最後點擊“開始導出”。只有全部文件寫入並校驗後才顯示完成和保存位置；舊修訂導出不會自動改為當前版。修訂版導出保留原媒體、獨立文字／字幕和版本記錄。

模型、適配器和評測報告也有獨立導出入口。適配器包記錄所需的精確基座，不默認包含基座權重；在其他工具使用前，應按清單準備兼容引擎和依賴。臨時或未完成目錄不能當作完整導出包使用。

006 及後續候選的訓練／驗證子集卡片提供“導出劃分”，劃分窗口也可選擇“導出原件、子集與證明”。先核對預覽，再明確導出；數據包包含原件、兩個子集、來源組及檢查證明和對象說明，原文與來源標識會一並導出。導出不會重新劃分或訓練。普通訓練報告和適配器包只攜帶固定劃分身份，並列出完整數據包這一外部依賴，不默認附帶原件或驗證數據，也沒有驗證損失結果。

<a id="6-数据市场与-ai-辅助"></a>

## 6. 數據市場與 AI 輔助

訓練草稿可打開數據集市場，檢查提供方條目、版本和訪問條件。需要申請的條目必須等待提供方批准；批准後下載、檢查，再返回原草稿使用。原任務的其他參數保留，選擇數據不會自動訓練。

本輪只驗過受控測試提供方，不代表已經連接商業數據市場。下載文件、使用聲明和提供方授權分別保留，不能互相替代。

AI 輔助只提出建議。先查看建議與草稿差異，再決定是否應用；應用後仍需手動檢查並開始任務。建議生成失敗或回答格式不合格時，原草稿保留。當前實際驗證的是本機模型建議，未開放的遠程連接不繼承此結論。

<a id="7-备份恢复与故障处理"></a>

## 7. 備份、恢復與故障處理

從“設備與環境 → 備份與恢復”創建完整備份。先完成運行或停止下載；備份包含數據庫、引用資產、原運行記錄及停止後的下載緩存。大型模型複製需要時間。

恢復時選擇備份和目標目錄，查看檢查結果後“恢復到新目錄”。恢復完成不自動替換當前工作庫；確認使用後再點擊“切換到恢復的工作庫”。原庫保留，恢復後的新運行使用本 App 的內置環境。

006 及後續候選使用資料庫 v4。完整備份包含來源組原件、兩份子集、證明及其關聯；尚未應用且已準備好的預覽也隨備份保留。恢復到新目錄後可讀取原預覽並明確應用，不會重新分詞或訓練。正在檢查、取消中或停止狀態未確認時，先處理原記錄再備份或清理；缺少文件或劃分關係不一致會阻止備份／恢復。

存儲清理先列出精確文件範圍和大小，再明確執行。當前只移動本庫無引用資產，並提供恢復入口；原執行證據和庫外下載不在清理範圍內。

環境安裝或恢復後，在“設備與環境”點擊“刷新環境”重新探測。按鈕等待期間會禁用；探測失敗會顯示原因，可再次重試，當前項目和未保存輸入會保留。

遇到服務中斷，先重新連接並查看原任務。狀態待覈實或產物待補收時，沿原任務覈實和補收；補收不會重新訓練或推理。若需要診斷，在“設備與環境 → 導出診斷摘要”預覽包含與排除的範圍，再選擇目錄保存。診斷只包含受限狀態摘要，不包含任務正文、原始日誌、憑據或本機路徑。

從 005 起會記錄本次控制服務會話最近32次環境探測的結果、耗時、退出碼與完成時間，區分超時、無法啓動、異常退出和無效輸出。023 另記錄本次服務環境檢查中的等待、身份檢查與緩存結果，便於分辨時間花在哪裡。預覽診斷只讀取已有記錄，不重新探測；記錄可能包含舊配置，服務重啓後清空。它幫助說明上次檢查為何失敗，不能證明當前設備已經就緒。

<a id="8-执行目标与文件传输"></a>

## 8. 執行目標與文件傳輸

在“設備與環境 → 執行目標”登記已經啓動的獨立執行服務，填入目標名稱、連接地址、執行器編號和訪問憑據。HTTPS 地址只包含主機與可選端口，例如 `https://执行服务主机:端口`；舊的 `http://127.0.0.1:端口` 回環模式繼續保留。地址與編號共同固定目標身份，原生 App 使用系統鑰匙串保存此目標的憑據；開發瀏覽器只在控制服務內臨時保存，服務重啓後需要重新輸入。清除憑據會保留目標記錄，重新連接需要再次配置。

HTTPS 服務需使用獨立執行目錄，並顯式配置綁定 IP、證書鏈和私鑰，見[執行服務準備示例](implementation/2026-09-10-remote-nvidia-evidence.md#执行服务准备示例)。證書須能由運行時隨附的公開 CA 包驗證，與登記主機匹配且在有效期內；驗證失敗會顯示原因，不發送項目文件。

“HTTPS 協議連接已驗證”或“回環協議連接已驗證”表示身份與傳輸協議可用。當前已完成本機 TLS 協議驗證，005 簽名包已納入 HTTPS，原生證書拒絕與目標界面已驗；跨主機受信證書和 NVIDIA 實機仍待驗收。NVIDIA 任務還要通過實際設備與模型檢查，沒有可用設備時會阻止提交。

“新文本任務的默認位置”只影響本項目以後新建的文本生成和訓練草稿。已有草稿保留原位置，可以在任務的“執行位置”中單獨修改；每次修改都需要重新檢查。遠端首期使用固定 Qwen2.5-0.5B-Instruct 原權重、Transformers、CUDA 和 BF16，檢查前可以保留輸入，尚不支持的適配器／檢查點組合會明確拒絕。

先查看檢查結果里的目標、待發送文件、總大小與SHA摘要，再點擊“確認發送並開始運行／訓練”。檢查不會自動上傳模型。只有明確開始後才傳輸已列文件和本次輸入；運行記錄與配方保存實際目標，憑據不進入配方。

若只驗證連接和文件，可在目標下點擊“驗證文件傳輸”，選擇當前項目的已導入數據或素材，先“檢查發送範圍”，再“開始傳輸驗證”。這條路徑保存副本並核對接收內容，沒有模型計算。“查看傳輸記錄”與“加載更早傳輸記錄”可繼續覈實同一目標的歷史。

斷線或證書驗證失敗時顯示的是最後取得的狀態，不能據此判斷遠端已經停止。修復連接後沿原記錄“重連並覈實原執行”；需要取消時也沿原編號請求，只有確認遠端進程退出後才表示已經停止。計算完成但接收失敗時使用“只補收已有產物”，按原封存清單取回和核對文件，不會重新運行模型。

<a id="9-安装与更新状态"></a>

## 9. 安裝與更新狀態

本輪開發、原生測試和運行使用同一 App 路徑。完整候選每次構建遞增括號中的編號；“技術預覽”表示驗收狀態，不是功能版本號。當前 Apple Silicon／macOS 26 及以上是待最終候選復驗的系統範圍。

本地候選更新工具先生成雙方版本、簽名、文件和當前數據庫的計劃，再明確執行替換；舊包及數據庫備份保留。使用方法見[桌面構建與更新說明](../scripts/desktop/README.md)。其中數據庫備份不含模型等資產，不能代替“備份與恢復”中的完整備份。

005 使用資料庫 v3，006 及後續候選會把庫升級到 v4，並在遷移前保存一致的數據庫副本。005 會拒絕打開 v4 庫，不能用替換回舊 App 的方式直接降級該庫；需要回到舊版時，應使用升級前保留的兼容工作庫和完整備份。遷移副本只包含數據庫，不能代替資產備份。更早的 0.1.0 包同樣不能直接讀取 v3 庫。

最終候選的真實安裝、升級與失敗回滾結果將隨對應簽名包交付。當前沒有自動更新發佈通道；本手冊不代表獨立機器安裝或正式分發驗收已經通過。
