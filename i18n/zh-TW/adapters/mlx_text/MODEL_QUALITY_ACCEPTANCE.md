# 原權重與量化模型質量准入

日期：2026-09-10。當前結論：正式質量比較、失敗門禁、報告及模型導出回讀已完成；本次 MLX 4-bit 權重量化候選質量未通過，仍為實驗模型，候選登記數量為 0。

<a id="已接入的流程"></a>

## 已接入的流程

1. 原模型通過正式轉換任務生成 MLX 4-bit／64／affine 模型，保存時綁定轉換嘗試、原權重版本和封存文件清單。
2. 新建評測可選擇適配器或量化模型。量化模型固定回到其轉換來源原權重；首次創建評測時固定准入方案，其他方案允許生成對照報告但不能用於准入。
3. 提交前分別核對兩份完整權重、分詞器、模板、方案和執行代碼。兩個獨立子進程各加載一份模型，使用同一組問題與生成參數。
4. 登記時重新覈算每條真實輸出、類別匯總、回歸門檻和獨立進程身份，並重驗轉換來源及封存報告。只有顯式登記成功才寫入量化候選並將模型標為 `quality_approved`。
5. 模型默認引擎保持 MLX。沒有產品轉換來源、格式／引擎不匹配、方案替換、來源變化、證據不完整、人工項未完成或質量失敗均不能准入。

此處是權重量化質量比較，不是 q4 KV 緩存驗收。原 LoRA 的訓練前方案要求、舊失敗報告和 q4 KV 的 No-Go 結論保持有效。

<a id="固定真实对照"></a>

## 固定真實對照

預註冊方案：[frozen-plan.json](../../../../.artifacts/m5-quantization-quality/plan-20260910-v1/frozen-plan.json)。方案 SHA-256 為 `1c0af19ea167218b5a67926d8987334cf9fa36436c157709d7484bb812ac2ea5`。使用 Qwen2.5-0.5B-Instruct 原權重與本次獨立新庫實際生成的 MLX 4-bit 權重。16 條問題分四類，每類至少通過 75%，回歸允許下降為 0；溫度 0、Top-p 1、種子 0、每題最多 64 token。只運行一輪正式對照，沒有在看答案後修改題目、規則或閾值。

|---|---:|---:|---:|
| 業務 | 2 / 4 | 2 / 4 | 3 / 4，未達到 |
| 格式 | 2 / 4 | 2 / 4 | 3 / 4，未達到 |
| 回歸 | 3 / 4 | 3 / 4 | 3 / 4，達到 |
| 行為 | 4 / 4 | 3 / 4 | 3 / 4，達到 |
| 合計 | 11 / 16 | 10 / 16 | 按類別判定，不能用合計代替 |

質量結果為 `failed / eligible=false`，正式登記接口返回 `409 EVALUATION_FAILED`。兩側獨立加載進程為 99880、99884，實際加載的模型摘要分別為 `a9b08fa2b761cbfc7335b28c6b0997b6e7713893aaca4b215625ffc99a1d36b3` 和 `9c11562b7a0990d0efc12ab596fcda0120a96f26245aeb481d30ccb7c2a35aba`。完整逐題答案、規則、耗時和峰值內存見[評測記錄](../../../../.artifacts/m5-quantization-quality/real-20260910-v1/evaluation-record.json)。這組小樣本不代表普遍業務質量；一次順序加載的時間與峰值僅作觀測，不作為性能收益驗收。

報告導出 11 個文件、模型導出 13 個文件，全部重新計算 SHA-256；導出報告與封存報告完全相同，量化權重導出後的模型摘要相同。兩份已登記資產均做完整文件集合校驗；外部來源按原導入策略重算模型清單，源碼及凍結方案均未變。證據見[只讀收口報告](../../../../.artifacts/m5-quantization-quality/real-20260910-v1/completion.json)。

另一審查者獨立重判了 32 份原始回答，復核類別計分、三個分離 PID、准入拒絕，以及兩次導出的大小和哈希，結論一致；[獨立復核](../../../../.artifacts/m5-quantization-quality/independent-review-v1.json)同時確認原報告字節未變。

首次腳本末尾誤用“已登記資產完整目錄”檢查外部 Hugging Face 下載目錄，其中原有 `.cache` 不屬於導入模型清單，導致[原運行報告](../../../../.artifacts/m5-quantization-quality/real-20260910-v1/report.json)標為失敗。原報告保留，後續只讀核驗按原導入範圍逐文件復核並通過，沒有重跑模型或覆蓋質量失敗。

<a id="验证与剩余边界"></a>

## 驗證與剩餘邊界

- 新量化控制合同 22 項通過，涵蓋首次方案、偽造通過、同進程、錯權重、轉換來源變化、登記併發變化、報告導出及隔離恢復後准入；這些夾具明確標記，不能當作模型質量通過證據。
- 同輪舊 LoRA／轉換加新量化的控制回歸通過；MLX 規則、身份及真實 tokenizer 相關 76 項通過。界面評測與量化入口 9 項通過，TypeScript 檢查通過。
- 普通窗口及最終應用包驗收由整體驗收報告記錄；本文件不以組件測試代替最終包檢查。NVIDIA 訓練、同份 LoRA 回 Apple、真實正向質量候選仍未通過，不據此完成 M0—M6。

復跑代碼為 [run_model_quality_probe.py](../../../../tests/control/run_model_quality_probe.py)；已有實測的只讀核驗為 [verify_model_quality_probe.py](../../../../tests/control/verify_model_quality_probe.py)。復跑必須創建獨立新證據目錄，保留舊結果；不能用重跑或新方案把本候選失敗改寫為通過。
